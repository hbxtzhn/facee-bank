## 一句话
结构化输出是让模型按固定字段和格式输出，常用 JSON，这样程序可以直接解析和校验结果，不用从一大段自由文本里硬抠。

## 要点
- [kp1|3] 结构化输出：让模型按约定的字段和格式返回结果
- [kp2|3] JSON 容易被程序解析，也有现成的校验工具
- [kp3|2] 自由文本格式不稳定，程序很难可靠地提取信息
- [kp4] 即便要求了 JSON，也建议校验，不能默认一定符合

## 详解
### 先搞懂：像让对方填表，而不是写作文
你想知道一个客户的姓名、电话和需求。让他写一段话，每个人写法都不同，你得人工去读。让他填表，姓名一栏、电话一栏，你直接就能录入系统。

结构化输出就是让模型“填表”而不是“写作文”。

后文用到的词：
- **JSON**：一种用键值对表示数据的文本格式，几乎所有语言都能解析。
- **字段**：数据里的一项，如 name、age。
- **解析**：把文本变成程序里的对象。
- **校验**：检查数据是否符合预期的结构。

### 为什么自由文本不好用
模型默认的回答是自然语言，同样的问题每次措辞都可能不同。程序要从里面找“金额”“日期”，就得写一堆脆弱的匹配规则，稍一变化就出错。

### 为什么选 JSON
- 格式固定，键名和值清楚。
- 各种编程语言都有现成的解析库。
- 可以用工具检查字段是否齐全、类型是否正确。

### 一个例子
你要从评论里提取情感和关键词。要求模型返回：

```json
{"sentiment": "positive", "keywords": ["物流快", "包装好"]}
```

程序拿到后直接解析，就能存库或统计。

### 怎么让模型输出 JSON
- 在提示里写清楚字段名和格式要求。
- 使用接口提供的 JSON 模式或按 schema 约束的功能（后者约束更强，见后续题目）。
- 拿到结果后做校验，不通过就重试或报错。

## 易错点
- 以为只要提示里说了“输出 JSON”就一定合法；模型仍可能多输出文字或格式出错
- 输出了合法 JSON，就以为字段一定对；还要校验字段和类型
- 直接信任结果执行敏感操作，不做校验

## 追问
### [f1] 模型输出的 JSON 解析失败怎么办？
先做校验，失败就带上错误信息让模型重试，仍失败则走降级或报错。

### [f2] 为什么要校验，既然已经让模型输出 JSON 了？
因为模型生成存在不确定性，可能缺字段或类型不对，程序侧校验才能保证后续逻辑安全。
