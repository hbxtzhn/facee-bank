## 一句话
浅拷贝只复制对象自己这一层：基本类型复制值，引用类型只复制地址，所以副本和原对象会共用同一个内部对象。

## 要点
- [kp1|3] 浅拷贝只复制第一层：基本类型复制值，引用类型复制地址
- [kp2|3] 副本和原对象的引用成员指向同一个堆对象
- [kp3|2] 通过副本修改共享的内部对象，原对象也会跟着变
- [kp4] Object.clone() 默认就是浅拷贝
- [kp5] String 等不可变对象被共享时不会出问题

## 详解
### 先搞懂：复印一张写着地址的纸条
做项目时常有这样的对象：订单里有一个收货地址对象。现在要“复制一份订单”。

打个比方：订单是一张纸，上面有“金额”这一栏，还有“地址”这一栏。但“地址”栏里写的不是地址内容，只是一个门牌号，告诉你去哪个仓库里找那份地址资料。

- 浅拷贝：把整张纸复印一份。金额是数字，复印后各自独立；“地址”栏的门牌号也被原样复印，两张纸指向同一份地址资料。
- 深拷贝：连仓库里那份资料也复印一份，新纸上写新门牌号。

后文用到的几个词：

- **基本类型**：int、double、boolean 这类，变量里直接放值。
- **引用类型**：对象、数组等，变量里放的是对象在堆里的地址。
- **堆**：对象实际存放的内存区域。

### 浅拷贝：只复制这一层
浅拷贝新建一个对象，然后逐个成员往里填：

1. 基本类型成员：复制值，两边互不影响；
2. 引用类型成员：复制的是地址，两个对象的这个成员指向同一个堆对象。

所以副本里的引用成员不是新对象，而是原对象那个成员的“别名”。

### 为什么会有问题
如果通过副本去修改共享的内部对象，原对象看到的也是改后的结果。比如副本订单把地址对象里的城市改了，原订单的城市也变了。

但如果只是让副本的引用成员指向另一个新对象（重新赋值），那只改了副本自己的“门牌号”，原对象不受影响。区别在于：是改了共享对象的内容，还是换了一个指向。

另外，String、Integer 这类不可变对象就算被共享，也没法被修改，所以浅拷贝时它们通常不会带来麻烦。

## 示例
```java
class Address { String city; }
class Order implements Cloneable {
    int amount;
    Address address;
    @Override
    protected Order clone() throws CloneNotSupportedException {
        return (Order) super.clone(); // 浅拷贝
    }
}
// Order b = a.clone();
// b.amount = 1;        // 不影响 a
// b.address.city = "X"; // a.address.city 也变成 "X"
```

## 易错点
- 以为浅拷贝得到的副本完全独立；其实引用成员仍然共用同一个对象
- 以为 `b = a` 就是浅拷贝；这只是让两个变量指向同一个对象，连新对象都没创建
- 以为浅拷贝一定有问题；成员全是基本类型或不可变对象时，浅拷贝就足够安全

## 追问
### [f1] 浅拷贝和深拷贝怎么选？
成员全是基本类型或不可变对象，浅拷贝就够，省事省内存。含有可变的引用成员，并且副本和原对象要各改各的，就用深拷贝。
