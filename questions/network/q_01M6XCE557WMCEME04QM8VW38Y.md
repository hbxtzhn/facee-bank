## 一句话
SYN 表示请求建立连接，ACK 表示确认号有效、对收到的数据做了确认，FIN 表示本方不再发送数据、请求关闭。

## 要点
- [kp1|3] SYN 置 1：请求建立连接，并同步初始序号
- [kp2|3] ACK 置 1：确认号字段有效，表示已收到对方的数据
- [kp3|2] FIN 置 1：本方数据发完了，请求关闭自己这个方向
- [kp4] 三次握手用 SYN 和 ACK，四次挥手用 FIN 和 ACK

## 详解
### 先搞懂：打电话的开头和结尾
打电话时：

- 开头你说「喂，能听到吗？」，这是请求建立联系（SYN）。
- 对方说「听到了」，这是确认（ACK）。
- 结束时你说「我说完了」，这是不再说话的通知（FIN）。

TCP 报文头里有一组标志位，每一位是 0 或 1，用来表示这个报文的用途。

后文的术语：

- **标志位**：TCP 首部里的几个开关位，值为 1 时表示这个功能被启用。
- **序号**：给发送的每个字节编号，用来保证顺序。
- **确认号**：告诉对方「我已经收到了这个编号之前的所有数据，下一个想要这个编号」。

### SYN：请求建立连接
SYN 是同步的意思。发送方把 SYN 置为 1，表示想建立连接，同时把自己的初始序号告诉对方。只有建立连接的前两个报文会带 SYN。

### ACK：确认
ACK 置为 1 时，说明报文里的确认号字段是有效的，表示已经收到对方的数据。连接建立以后，几乎所有报文都带着 ACK，因为每个数据包都顺便确认对方上一次发来的内容。

### FIN：我不再发了
FIN 表示发送方的数据已经发完，请求关闭自己这个方向的传输。收到 FIN 的一方，先回一个 ACK 表示知道了，自己还可以继续发数据，等发完了再发自己的 FIN。

### 它们怎么组合
| 阶段 | 报文 | 标志位 |
|---|---|---|
| 三次握手 | 第一次 | SYN |
| 三次握手 | 第二次 | SYN + ACK |
| 三次握手 | 第三次 | ACK |
| 四次挥手 | 第一次 | FIN（通常带 ACK） |
| 四次挥手 | 第二次 | ACK |
| 四次挥手 | 第三次 | FIN（通常带 ACK） |
| 四次挥手 | 第四次 | ACK |

## 易错点
- 以为 ACK 只在握手时出现；连接建立后，数据报文也带着 ACK
- 以为 FIN 表示连接立刻断开；它只关闭发送方向，对方还可以继续发送
- 把 ACK 标志位和确认号混为一谈；标志位是开关，确认号是具体数值，标志位为 1 确认号才有效

## 追问
### [f1] 除了这三个，常见的标志位还有哪些？
RST 表示重置连接，遇到异常时强行断开；PSH 表示尽快把数据交给应用层。
