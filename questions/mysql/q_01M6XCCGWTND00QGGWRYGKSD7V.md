## 一句话
配置路由是用一张配置表记录每个分片键值该去哪张表，路由时查表决定。最灵活，但多了一张要维护的表。

## 要点
- [kp1|3] 配置路由靠配置表记录分片键值到目标表的映射
- [kp2|3] 优点是灵活，想把哪类数据放哪张表都能手动配置
- [kp3|2] 缺点是要额外维护配置表，每次路由还多一次查询
- [kp4] 适合分片键没有规律、没法用区间或取模表达的场景

## 详解
### 先搞懂：像小区的门牌对照表
快递员送货，如果门牌号乱七八糟没有规律，他就带一本对照表：张三住几栋、李四住几栋，翻表就知道。配置路由就是这本对照表。

后文用到的术语：

- **配置表**：专门存映射关系的一张表，比如「用户编号对应哪张分表」。
- **映射**：一个值和它的目标位置之间的对应关系。
- **分片键**：决定数据落到哪张表的字段。

### 机制：先查表，再访问数据表
写入或查询一个用户的订单时：

1. 先到配置表里查，这个用户的数据在哪张表；
2. 拿到表名后，再去那张表读写数据。

配置表里的内容可以随时改。比如某个大客户的数据特别多，可以给他单独配一张表。

### 优点：想怎么放就怎么放
- **灵活**：不依赖固定公式，可以按实际情况安排每类数据去哪里。
- **调整方便**：数据迁移后只要改配置，路由就跟着变。
- **适合不规律的分片键**：分片键值既没有顺序、也不好用公式分均匀时，用查表最直接。

### 缺点：多了一份要维护的东西
- **维护成本高**：配置表要有人维护，新增数据时要同步新增配置。
- **多一次查询**：每次路由先查配置，查询慢了、配置表出问题，整个业务都会受影响。
- **配置表本身可能成为瓶颈**：所以通常要把配置缓存到应用内存里，同时处理好缓存和数据库的一致性。

### 什么时候用
分片键是无规律的字符串，或者要把特定客户、特定地区的数据放到指定的位置，配置路由很合适。如果规律明确，用范围或 Hash 路由更省事。

## 示例
```sql
-- 配置表：记录每个租户的数据在哪张表
CREATE TABLE route_config (
  tenant_id  VARCHAR(32) PRIMARY KEY,
  table_name VARCHAR(32) NOT NULL
);

INSERT INTO route_config VALUES ('big_customer', 'order_vip');
INSERT INTO route_config VALUES ('shop_a', 'order_1');

-- 第一步：查路由
SELECT table_name FROM route_config WHERE tenant_id = 'big_customer';
-- 第二步：到 order_vip 里查数据
```

## 易错点
- 以为配置路由没有缺点；配置表要维护，路由多一次查询
- 配置改了但没迁移数据；路由指向新表，数据还在旧表，查不到
- 配置表没做缓存和保护；它一旦变慢或不可用，所有读写都受影响

## 追问
### [f1] 配置路由的配置表怎么避免成为性能瓶颈？
把配置加载到应用内存或缓存里，只在变更时刷新，路由就不用每次查库。同时要保证配置表可靠，比如做好备份和高可用。
