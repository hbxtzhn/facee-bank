一轮执行通常用调用 ID 对应一次工具开始和结束。如果系统允许同一个 ID 的新调用直接覆盖旧记录，较早的写操作就可能被后来的只读操作伪装掉，最终汇总时误以为这一轮只有安全查询。

项目在一次 attempt 内维护调用 ID 到执行记录的映射。宿主开始某次工具时会认领记录；若该 ID 已经被认领，再次开始会标记失败并抛错，而不是替换原有执行。这样即使模型或 SDK 产生重复 ID，原先的写入风险也不会被覆盖。

例如先用 ID `a` 执行写入，再用同一 ID 执行读取。如果第二次覆盖第一次，重放判断可能看到的只有读取；保留第一次并拒绝重复使用，可以避免这种证据丢失。这是一项执行记录保护，不等于对所有外部请求都实现了业务幂等。
