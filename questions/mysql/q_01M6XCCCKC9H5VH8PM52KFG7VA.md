## 一句话
B+ 树只在叶子节点存数据，叶子之间有链表；B 树每个节点都存数据，没有链表。所以 B+ 树更矮、范围查询更快。

## 要点
- [kp1|3] B+ 树数据只在叶子节点，非叶子节点只存键，B 树每个节点都存数据
- [kp2|3] B+ 树非叶子节点能放更多键，分叉更多，树更矮
- [kp3|2] B+ 树叶子节点用链表相连，范围查询顺着读就行
- [kp4] B 树可能在中间节点就命中，B+ 树必须走到叶子

## 详解
### 先搞懂：目录页和内容页
想象一本书。B 树像是目录里每一条后面都附上了正文，目录变得很厚。B+ 树像是目录只写页码，正文全部放在后面的内容页里，内容页之间还按顺序连着。目录很薄，一页就能列很多条，翻几次就能到内容页。

几个术语：

- **非叶子节点**：树里负责指路的节点，告诉你往哪个子节点走。
- **叶子节点**：树最底层的节点，B+ 树的数据都在这里。
- **扇出**：一个节点能分出多少个子节点。

### 区别一：数据放在哪里
B 树的每个节点，不管是不是叶子，都存键和对应的数据。B+ 树只有叶子节点存数据，非叶子节点只存键。

所以同样大小的一页，B+ 树的非叶子节点能放更多键，分叉更多，树的高度更低，读磁盘的次数更少。

### 区别二：叶子节点的链表
B+ 树的叶子节点按键的顺序用指针串起来。范围查询时，定位起点后顺着链表一路读下去就行。B 树没有这个链表，范围查询要在树里来回走，比较麻烦。

### 区别三：查询路径
B 树里，如果目标键正好在某个中间节点，查到那里就能结束。B+ 树不管查什么，都要走到叶子，路径长度一致，查询时间更稳定。

### 方案对比：B 树和 B+ 树
| 对比点 | B 树 | B+ 树 |
|---|---|---|
| 数据存放 | 每个节点都存 | 只在叶子节点 |
| 非叶子节点 | 存键和数据，分叉少 | 只存键，分叉多 |
| 树高 | 相对更高 | 相对更矮 |
| 叶子链表 | 没有 | 有，叶子顺序相连 |
| 范围查询 | 较麻烦 | 顺着链表读 |
| 等值查询 | 可能中途命中 | 必须到叶子，深度一致 |

结论：数据库索引既要少 IO，又要范围查询和排序，所以选 B+ 树。

### 进阶：重复键的处理（基础薄弱可先跳过）
B+ 树的非叶子节点里的键只是路标，不代表数据本身，同一个键可能同时出现在上层和叶子层；B 树里每个键只出现一次。

## 易错点
- 以为 B+ 树的非叶子节点也存数据；它们只存键和指针
- 以为 B 树一定更慢；B 树在命中中间节点时可以更早结束，但整体上对磁盘型索引不如 B+ 树
- 以为叶子链表只是为了遍历；它的价值主要体现在范围查询和排序

## 追问
### [f1] 为什么数据库不选 B 树做索引？
B 树节点里存了数据，每页能放的键更少，树更高，IO 更多；而且没有叶子链表，范围查询和排序不方便。
