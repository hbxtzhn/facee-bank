## 一句话
LIKE 有 `${}`、引号包 `#{}`、`concat`、`bind` 四种写法：`${}` 有注入风险，引号包 `#{}` 会报错，推荐用 `concat`。

## 要点
- [kp1|3] `${}` 直接拼接，用户输入含恶意内容时有 SQL 注入风险
- [kp2|3] 把 `#{}` 放在引号里会变成普通字符 `?`，参数无法设置
- [kp3|2] `concat('%', #{x}, '%')` 简洁安全，是推荐写法
- [kp4|2] `bind` 标签也安全，但要多写一行，较繁琐

## 详解
### 先搞懂：LIKE 的难点在“百分号”
搜索框里输入 `张`，想查所有姓张的人。SQL 要写成 `like '%张%'`。难点在于：`%` 要和用户输入拼在一起，而用户输入应该用占位符 `#{}` 传，防止注入。怎么把两者安全地拼起来，就是这道题的核心。

术语说明：

- **通配符**：`%` 代表任意多个字符；
- **拼接**：把几段文字连成一段；
- **`bind`**：动态 SQL 标签，先在 Java 侧算出一个变量，再用 `#{}` 引用。

### 四种写法
1. **`${}` 写法**：`like '%${name}%'`。直接拼文本，用户输入 `' or '1'='1` 之类的内容就能改写语句，有注入风险，不要用。
2. **引号包 `#{}`**：`like '%#{name}%'`。引号里的 `?` 被数据库当成普通字符，参数无处可设，运行时报错。
3. **`concat` 函数**：`like concat('%', #{name}, '%')`。参数仍是占位符，安全，写法也短，推荐。
4. **`bind` 标签**：先 `bind` 一个变量，值是 `'%' + name + '%'`，再 `like #{pattern}`。安全，但多一个标签，写起来繁琐。

另一个办法：在 Java 里把百分号拼进参数，SQL 里只写 `like #{pattern}`。

### 方案对比：LIKE 的写法
| 写法 | 是否预编译 | 能否运行 | 问题 | 结论 |
|---|---|---|---|---|
| `'%${name}%'` | 否 | 能 | 注入风险 | 避免 |
| `'%#{name}%'` | 是 | 报错 | 占位符被当普通字符 | 错误写法 |
| `concat('%', #{name}, '%')` | 是 | 能 | 依赖数据库有此函数 | 推荐 |
| `bind` 标签 | 是 | 能 | 多写一个标签 | 可用 |

结论：默认用 `concat`；个别数据库拼接函数写法不同，或想让 SQL 更易迁移时，用 `bind` 或在 Java 里拼百分号。

## 示例
```xml
<select id="searchByName" resultType="User">
  select * from user where name like concat('%', #{name}, '%')
</select>
```

## 易错点
- 用 `${}` 写模糊查询，图省事却留下注入口
- 在引号里写 `#{}`，以为会自动替换，结果报参数错误
- 用户输入本身含 `%` 或 `_` 时也会被当通配符，需要时要转义

## 追问
### [f1] 用户输入里有 `%` 怎么办？
`%` 和 `_` 在 LIKE 里是通配符。如果要按字面匹配，需要先转义，再配合 `escape` 子句使用。
