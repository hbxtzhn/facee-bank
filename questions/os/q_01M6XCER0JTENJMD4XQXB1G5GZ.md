## 一句话
临界区就是访问共享资源的那段代码，必须保证同一时刻只有一个线程在里面执行。

## 要点
- [kp1|3] 临界区是访问共享资源（共享变量、文件等）的一段代码
- [kp2|3] 要求互斥：一个线程在里面时，其他线程不能进入
- [kp3|2] 常用互斥锁和信号量来保护临界区
- [kp4] 临界区越短越好，减少别的线程等待

## 详解
### 先搞懂：只有一个人能用的试衣间
商场试衣间一次只能进一个人，里面的人出来之前，别人得在外面等。临界区就是代码里的试衣间，里面放的是共享的东西。

比如扣库存：两个线程同时读到库存 10，各自减 1 再写回，结果是 9 而不是 8。把「读库存、减一、写回」这段放进临界区，一次只让一个线程执行，就不会出错。

后文会用到几个词：

- **共享资源**：多个线程都能读写的数据，如全局变量、文件。
- **互斥**：同一时刻只允许一个线程使用。
- **竞态**：结果取决于线程执行顺序，导致不确定。

### 临界区要满足什么
- **互斥**：同一时刻最多一个线程在里面。
- **有限等待**：想进的线程不会被无限期拦在外面。
- **进入和退出要配对**：进去前加锁，出来后一定要放锁。

### 怎么实现保护
常用方式有两种：

- **互斥锁**：进入前加锁，出来时解锁，任一时刻只有一个线程持锁。
- **信号量**：用一个计数器表示可用资源数，P 操作申请，V 操作释放，计数初始为 1 时可以实现互斥。

### 写临界区的原则
只把真正访问共享数据的代码放进去，其他逻辑（比如网络请求、日志）放在外面。临界区太长，别的线程等待时间就长，系统并发度会下降。

## 示例
```java
private int stock = 10;
private final Object lock = new Object();

public void deduct() {
    synchronized (lock) {   // 进入临界区
        if (stock > 0) {
            stock--;
        }
    }                       // 离开临界区
}
```

## 易错点
- 把整个方法都包进临界区；只需要保护访问共享数据的那几行
- 加锁后忘了在异常路径解锁；要用 finally 或 synchronized 等能自动释放的写法
- 以为只读不需要保护；有线程在写时，读也可能读到中间状态

## 追问
### [f1] 临界区和临界资源是一回事吗？
不是。临界资源是被共享的数据，临界区是访问这些数据的代码。
