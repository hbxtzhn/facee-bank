## 一句话
Redisson 先用 Lua 脚本原子地加锁并设好过期时间，加锁成功后启动看门狗定期续期；失败的线程等待并重试，释放锁时看门狗随之停止。

## 要点
- [kp1|3] 加锁用 Lua 脚本，一次完成“判断、写入、设过期时间”
- [kp2|3] 加锁成功且没指定 leaseTime，会启动看门狗定期续期
- [kp3|2] 加锁失败的线程在等待时间内重试，超时才返回失败
- [kp4|2] 解锁时递减重入次数，减到 0 才删 key 并取消续期
- [kp5] 锁的 value 是 hash，记录线程标识和重入次数

## 详解
### 先搞懂：像去门口登记的会议室
会议室门口有一本登记簿。你来了先看有没有人登记，没有就写上你的名字并写明时间；有人就在旁边等，等对方走了再试。

Redisson 的锁就是这个流程。后文用到的词：

- **加锁脚本**：一段 Lua 脚本，在 Redis 里一次执行完。
- **看门狗**：加锁后定期给锁续期的后台任务。
- **waitTime**：最多愿意等多久，超过就放弃。

### 第一步：用 Lua 脚本加锁
脚本做的事情大致是：

1. 锁的 key 不存在：创建一个 hash，记下“线程标识 → 1”，并设置过期时间，返回成功。
2. key 已存在且线程标识就是自己：重入次数加一，刷新过期时间，返回成功。
3. 否则：说明锁被别人持有，返回锁剩余的存活时间。

判断、写入、设置过期时间三步放在脚本里。Redis 保证中间不被其他命令打断，所以不会出现两个线程同时认为自己加锁成功。

### 第二步：成功就启动看门狗
如果调用时没有指定 leaseTime，Redisson 会把过期时间设为默认的 30 秒。

同时它会启动一个定时任务，大约每隔三分之一的时间把锁延长一次。业务还没做完，锁就不会因为到期而失效。

### 第三步：失败就等待重试
拿不到锁的线程不会一直死循环狂刷 Redis。它订阅锁释放的通知，再根据返回的剩余存活时间等待，被唤醒后重新尝试加锁。`tryLock(waitTime, ...)` 在等待时间用完后返回 false；`lock()` 则会一直等下去。

### 第四步：解锁
解锁同样用 Lua 脚本：先确认锁是自己的，把重入次数减一；减到 0 才真正删除 key，发出释放通知唤醒等待者，并取消看门狗的续期。

### 进阶：版本差异（基础薄弱可先跳过）
- 具体脚本、续期间隔和等待的实现，不同 Redisson 版本略有不同，以所用版本的源码为准。
- 如果指定了 leaseTime，不启动看门狗，锁到点就过期。

## 示例
```java
RLock lock = redisson.getLock("lock:order:1001");
// 最多等 3 秒；没指定 leaseTime，成功后启用看门狗
if (lock.tryLock(3, TimeUnit.SECONDS)) {
    try {
        doBusiness();
    } finally {
        lock.unlock();
    }
}
```

## 易错点
- 以为失败的线程在死循环狂刷 Redis；实际是等待释放通知后再重试
- 以为 unlock 一次就一定释放；重入多次需要对应次数的 unlock
- 在别的线程里 unlock 这把锁；锁只能由持有它的线程释放

## 追问
### [f1] 为什么锁的数据结构用 hash，不用普通字符串？
hash 的 field 可以记线程标识，value 记重入次数。同一个线程再次加锁，次数加一即可，普通字符串很难同时存这两样信息。
