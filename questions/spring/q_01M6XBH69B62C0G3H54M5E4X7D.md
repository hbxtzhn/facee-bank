## 一句话
依赖注入（DI）就是容器创建好对象之后，把它需要的其他对象主动传给它，而不是让它自己去 new 或去查找；它是实现 IoC 最常见的方式。

## 要点
- [kp1|3] DI：对象需要的依赖由容器传入，而不是对象自己创建或查找
- [kp2|3] DI 是 IoC 最常见、最合适的实现方式
- [kp3|2] 常见的注入方式有构造器注入、setter 注入、工厂方法注入
- [kp4] 依赖写成接口类型，替换实现时不用改使用方的代码

## 详解
### 先搞懂：员工要用电脑，由公司配发
一个员工上班要用电脑，有两种方式：

- 自己去买一台（自己 `new`）；
- 公司行政配好了送到工位（依赖注入）。

后一种方式里，员工不用关心电脑从哪买、什么型号，行政换了新电脑他也不用改自己的工作方式。

后文用到的词：
- **依赖**：一个对象工作时需要用到的另一个对象，如 Service 依赖 Dao。
- **注入**：由外部（容器）把依赖传给对象。
- **容器**：Spring 里创建对象并负责注入的那部分。

### DI 是怎么发生的
1. 容器根据配置创建好 A 对象和 B 对象；
2. 发现 A 依赖 B；
3. 容器把 B 传给 A（通过构造器参数、setter 方法或其他方式）；
4. A 拿到 B，可以直接使用，A 自己没有写任何创建 B 的代码。

### 和 IoC 的关系
IoC 说的是「对象的创建和管理权交给容器」这个设计思想；DI 是容器具体怎么把依赖交给对象的做法，是最常用的一种实现。

### 常见的注入方式
| 方式 | 依赖怎么传入 | 特点 |
|---|---|---|
| 构造器注入 | 作为构造方法的参数 | 对象创建完依赖就绪，依赖可以声明为 final |
| setter 注入 | 通过 setter 方法设置 | 先创建对象再设置，适合可选依赖 |
| 工厂方法注入 | 通过静态或实例工厂方法获得 | 适合创建过程复杂的对象 |

结论：新代码优先用构造器注入；可选依赖用 setter 注入；创建过程特殊的对象用工厂方法。

## 示例
```java
@Service
public class OrderService {
    private final UserDao userDao;

    public OrderService(UserDao userDao) { // 容器把 UserDao 传进来
        this.userDao = userDao;
    }
}
```

## 易错点
- 以为依赖注入就是 @Autowired；这是常见写法之一，注入的本质是容器把依赖传给对象
- 对象自己通过 `new` 或静态方法查找依赖，再声称使用了依赖注入
- 以为只能注入 Bean；也可以注入配置值，如用 @Value 注入属性

## 追问
### [f1] 依赖注入和 IoC 是同一个东西吗？
不是。IoC 是设计思想，DI 是实现思想的主要手段，另外还有依赖查找等做法，但不如 DI 常用。

### [f2] 依赖注入的好处是什么？
降低类之间的耦合，替换实现不用改使用方；也方便测试时注入假对象。
