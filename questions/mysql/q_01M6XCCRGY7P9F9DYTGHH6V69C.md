## 一句话
插入意向锁是 INSERT 在插入前，在目标间隙上加的一种特殊间隙锁。插入位置不同的事务互不等待，但会被已有的间隙锁挡住。

## 要点
- [kp1|3] 插入意向锁是 INSERT 在插入前，在目标间隙上加的间隙锁
- [kp2|3] 同一间隙里，插入位置不同的事务互不阻塞
- [kp3|2] 如果间隙上已有别人的间隙锁或临键锁，插入就要等待
- [kp4] 它表达的是「我打算在这里插入」，不是真正的排他
- [kp5] 和表级的意向锁是两回事

## 详解
### 先搞懂：排队进场，先打个招呼
假设表里 id 有 5 和 10，两条记录之间的空隙是 (5,10)。事务 A 想插入 6，事务 B 想插入 8。

这两次插入不冲突，没必要让它们排队。所以 InnoDB 让每个插入先在这个间隙上「挂个牌子」：我打算在这儿插入某个位置。位置不同，牌子互相兼容，两个事务可以同时插入。

类比：电影院一排空座位，两个人各坐一个不同的座位，不需要互相等；但如果有人已经把这一排包场了（间隙锁），别人就得等包场结束。

后文会用到这几个词：

- **间隙锁**：锁住记录之间的空隙，阻止别人插入。
- **插入意向锁**：插入动作先加的、表示意图的间隙锁。

### 它在什么时候出现
执行 `INSERT` 时，在把行真正写进去之前，InnoDB 会在要插入的位置所在的间隙上加插入意向锁，然后才加记录上的排他锁并写入。

### 兼容规则
- 插入意向锁和插入意向锁：位置不同时兼容，不用互相等待。
- 插入意向锁和别人已持有的间隙锁、临键锁：冲突，插入会被阻塞。
- 别人想加间隙锁时，如果有事务在同一间隙已持有插入意向锁，间隙锁请求也要等待。

### 为什么重要：解释一类阻塞和死锁
前面几题讲过，可重复读下范围查询会加间隙锁或临键锁。这时别的事务想往这个范围里插入，就会因为插入意向锁和间隙锁冲突而被阻塞。

两个事务都先持有间隙锁（互相兼容），再都去插入（都要等对方的间隙锁释放），就会形成死锁。这是一个常见的死锁来源。

## 示例
```sql
-- 假设 id 有 5、10，可重复读
-- 事务 A：锁住间隙 (5,10)
START TRANSACTION;
SELECT * FROM orders WHERE id = 7 FOR UPDATE;

-- 事务 B：插入前需要在 (5,10) 上加插入意向锁，被 A 的间隙锁挡住
INSERT INTO orders(id) VALUES (8);
```

## 易错点
- 把它和表级的意向锁（IS、IX）混为一谈；插入意向锁是间隙上的锁
- 以为多个插入一定互相阻塞；位置不同时不会阻塞
- 以为只要有间隙锁就不能插入；只是在冲突范围内插入会等

## 追问
### [f1] 插入意向锁和间隙锁是什么关系？
插入意向锁是间隙锁的一种特殊形式。普通间隙锁的目的是阻止别人插入；插入意向锁的目的是声明「我要在这个间隙里插入」，并且和同一间隙里的其他插入意向锁不冲突。

### [f2] 它为什么容易引发死锁？
两个事务先各自持有同一间隙的间隙锁（间隙锁互相兼容），再都去插入，就会各自等对方释放间隙锁，形成死锁。
