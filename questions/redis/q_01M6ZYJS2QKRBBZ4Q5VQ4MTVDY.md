## 一句话
布隆过滤器用位数组和多个哈希函数判断元素是否存在：它说不存在就一定不存在，说存在则可能误判，常用来拦截不存在的数据请求。

## 要点
- [kp1|3] 布隆过滤器说“不存在”，就一定不存在
- [kp2|3] 它说“存在”，不保证真的存在，会有误判
- [kp3|2] 用来在缓存前拦截不存在的请求，防止缓存穿透
- [kp4] 占用空间很小
- [kp5] 标准版本不支持删除元素

## 详解
### 先搞懂：门卫手里的名单摘要
小区门卫不想背所有住户名单，于是他有个办法：按姓名算出几个“特征”，在黑板上打钩。来访者报名字，门卫算出特征，只要有一个特征没钩，就肯定不是住户；如果特征全钩了，可能是住户，也可能是巧合，得进一步确认。布隆过滤器就是这个门卫。

后文用到的词：
- **位数组**：一长串只有 0 和 1 的格子。
- **哈希函数**：把任意内容算成一个固定范围内的数字。
- **误判**：不存在的元素被判断为存在。

### 它解决什么问题
缓存穿透时，大量请求查询不存在的数据，直接冲击数据库。把所有存在的数据 ID 提前放进布隆过滤器，请求来了先问它：

- 回答“不存在”：直接返回，不再查缓存和数据库；
- 回答“可能存在”：继续走缓存和数据库的正常流程。

少量误判只是让几个无效请求漏过去，不会影响正确性。

### 它的特点
- **没有漏判**：真实存在的元素，一定会被判断为存在；
- **有误判**：不存在的元素，有一定概率被判断为存在；
- **省空间**：不保存元素本身，只用位数组，占用很小；
- **不好删除**：多个元素共用格子，删除会影响其他元素，所以标准版本不支持删除。

### 在 Redis 里怎么用
可以使用 RedisBloom 模块提供的布隆过滤器，或者用 Redisson 等客户端提供的封装。也可以在应用内存里用 Guava 之类的库实现。

## 示例
```java
// 使用 Guava 的布隆过滤器：预计 100 万个元素，可接受 1% 误判率
BloomFilter<Long> filter = BloomFilter.create(Funnels.longFunnel(), 1_000_000, 0.01);
filter.put(1001L);

filter.mightContain(1001L);  // true：可能存在
filter.mightContain(9999L);  // 多半为 false：一定不存在
```

## 易错点
- 以为它回答“存在”就一定存在；只是可能存在
- 以为它能删除元素；标准版本不能，删除要用别的变种
- 数据新增后忘记把新 ID 加进过滤器，导致新数据被误拦

## 追问
### [f1] 布隆过滤器能完全解决缓存穿透吗？
不能完全解决。它能挡掉绝大多数不存在的请求，但有误判，少量请求仍会到达数据库，通常配合缓存空值、限流一起用。
