## 一句话
覆盖索引是指查询要的所有列都已经在用到的索引里，不需要再回表，直接从索引拿结果。

## 要点
- [kp1|3] 查询用到的列全部包含在某个索引中，这个索引就覆盖了该查询
- [kp2|3] 覆盖索引不需要回表，少一次聚簇索引查找
- [kp3|2] 二级索引里本来就带主键值，所以查主键列也算在覆盖范围内
- [kp4] `EXPLAIN` 的 `Extra` 出现 `Using index`，表示用了覆盖索引

## 详解
### 先搞懂：目录上已经写了你要的信息
你在图书馆找「张三写的书的书名」。作者目录上每条记录不仅有作者，还写了书名。你看一眼目录就够了，不用再去书架拿书。这就是覆盖索引：目录本身已经覆盖了你想要的信息。

几个术语：

- **回表**：查完二级索引后，再去聚簇索引取整行。
- **联合索引**：包含多列的索引，更容易做成覆盖索引。
- **覆盖**：查询的 `SELECT`、`WHERE` 等用到的所有列，都在这个索引里。

### 为什么能省回表
二级索引的叶子节点存索引列加主键值。只要查询要的列都在这些里面，MySQL 查到叶子节点就可以直接返回结果，不用再拿主键回聚簇索引。少一次树查找，也少了很多随机读。

### 怎么做到覆盖
1. 把查询里用到的列都放进联合索引；
2. 不要 `SELECT *`，只查需要的列；
3. 注意主键列不用单独加，二级索引里已经带了。

### 方案对比：同一个查询的不同索引
| 索引 | 查询 `SELECT id, name, age WHERE name = 'Tom'` | 是否回表 |
|---|---|---|
| `(name)` | 能定位，但 age 不在索引里 | 要回表 |
| `(name, age)` | name、age、id 都在索引里 | 不回表 |
| 主键 | 没法按 name 定位 | 不适用 |

结论：高频查询的列不多时，可以考虑建覆盖索引；但列越多索引越大，要权衡。

### 进阶：覆盖索引的代价（基础薄弱可先跳过）
索引里放的列越多，索引占空间越大，写入时维护的代价也越高。所以不要为了覆盖而把很多列都塞进索引，只针对最频繁、最重要的查询这样做。

## 示例
```sql
CREATE INDEX idx_name_age ON user(name, age);

-- 覆盖索引：只查索引里有的列
EXPLAIN SELECT id, name, age FROM user WHERE name = 'Tom';
-- Extra 中会出现 Using index
```

## 易错点
- 以为覆盖索引是一种特殊的索引类型；它是描述一个索引对某条查询是否足够的说法
- 以为用了联合索引就一定是覆盖索引；要查的列有一个不在索引里，就得回表
- 以为 `Using index` 和 `Using index condition` 是一回事；后者是索引下推，不同

## 追问
### [f1] 覆盖索引一定比普通索引查询快吗？
通常更快，因为省了回表。但命中行很少时差别不大，而且索引变大后写入和空间的代价也会增加。
