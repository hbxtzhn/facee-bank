## 一句话
加载读入字节码并生成 Class 对象，验证检查字节码是否安全，准备给静态变量分配内存并赋默认值，解析把符号引用换成直接引用，初始化才真正执行静态赋值和静态代码块。

## 要点
- [kp1|3] 加载：按类名读取字节流，在内存中生成 Class 对象
- [kp2|3] 准备：给静态变量分配内存并赋默认值（如 int 为 0），不是代码里写的值
- [kp3|2] 初始化：执行静态变量赋值和静态代码块，此时才得到代码里写的值
- [kp4|2] 验证保证字节码合法安全，解析把符号引用转成直接引用
- [kp5] 验证、准备、解析三步合称"链接"

## 详解
### 先搞懂：搬进新家的五步
把类加载想成搬进新家：
- 先把家具搬进门（加载）；
- 检查家具是否合格、安全（验证）；
- 先把每件家具的位置占好，暂时空着（准备）；
- 把"那个沙发"这样的名字，换成具体放哪的位置（解析）；
- 最后真正把东西摆好，通电开用（初始化）。

后文用到的术语：
- **符号引用**：用名字描述的引用，如"某个类的某个方法"，还不知道在内存哪里。
- **直接引用**：指向内存里具体位置的引用。
- **静态变量**：用 `static` 修饰、属于类的变量。

### 加载：读入字节码，生成 Class 对象
做三件事：根据类的全限定名找到字节流；把字节流转成 JVM 内部的类数据结构；在内存中生成一个 `Class` 对象，作为访问这个类的入口。

### 验证：确保字节码安全
检查字节码是否符合规范，避免恶意或错误的字节码破坏 JVM。包括文件格式是否正确、数据是否合法、方法体的指令是否安全、引用是否能解析等。

### 准备：为静态变量分配内存，赋默认值
这一步只给静态变量分配内存，并赋**默认值**：int 是 0，boolean 是 false，引用是 null。代码里写的值（如 `static int a = 5`）在这一步还没赋，要到初始化阶段才赋。

有一个例外：被 `static final` 修饰、值是编译期常量的变量，在准备阶段就直接是代码里写的值。

### 解析：符号引用变直接引用
字节码里引用别的类、方法时，用的是名字。解析阶段把这些名字换成内存里的具体位置，之后调用才知道去哪找。

### 初始化：真正执行静态代码
初始化阶段才会执行静态变量的赋值和 `static {}` 代码块，按代码里出现的顺序执行。如果父类还没初始化，会先初始化父类。

## 示例
```java
public class Demo {
    static int a = 5;         // 准备阶段 a = 0；初始化阶段才变成 5
    static {
        System.out.println("初始化时执行：a = " + a);
    }
    public static void main(String[] args) {
        System.out.println(a);
    }
}
```

## 易错点
- 以为准备阶段就把静态变量赋成了代码里的值；那时只是默认值，初始化阶段才赋值
- 以为类加载后就会马上初始化；初始化要等到类被主动使用
- 把"加载"和"类加载整个过程"混为一谈；加载只是五个阶段中的第一个

## 追问
### [f1] 静态变量在哪个阶段赋值？
分两次：准备阶段先赋默认值（如 int 为 0），初始化阶段再执行代码里的赋值。

### [f2] 验证阶段为什么不能省？
.class 文件可能被篡改或由其他工具生成，不一定合法。验证可以防止错误或恶意字节码破坏 JVM 的安全。
