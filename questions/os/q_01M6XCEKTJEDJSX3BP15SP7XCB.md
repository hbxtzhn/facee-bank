## 一句话
进程有创建、就绪、运行、阻塞、结束五种状态；就绪是在等 CPU，阻塞是在等某个事件。

## 要点
- [kp1|3] 五种状态：创建、就绪、运行、阻塞、结束
- [kp2|3] 就绪：具备运行条件，只差 CPU；阻塞：在等某个事件，给 CPU 也没法运行
- [kp3|2] 运行状态：进程正在占用 CPU 执行
- [kp4] 就绪到运行由调度选中，运行到阻塞是请求了 IO 等事件

## 详解
### 先搞懂：医院的挂号和看病
去医院看病：

- 你在挂号台办卡，是**创建**；
- 办好卡，在诊室外排队等医生，这是**就绪**：你什么都准备好了，只等医生；
- 轮到你，医生看病，是**运行**；
- 医生让你先去验血，你要等化验结果，这是**阻塞**：这时就算医生有空，你也没法接着看，得等结果出来；
- 看完病离开，是**结束**。

后文要用的术语：

- **CPU 控制权**：被调度选中后，进程才能在 CPU 上执行。
- **事件**：进程在等的东西，如输入输出完成。

### 五种状态
- **创建**：进程刚被建立，操作系统正在给它准备资源。
- **就绪**：能运行，但 CPU 正被别的进程用着，只能排队。
- **运行**：正占用 CPU 执行指令。
- **阻塞**：在等某个事件，如读硬盘、等网络数据。事件没发生之前，即使给它 CPU 也运行不了。
- **结束**：进程执行完毕，正在从系统中消失。

### 状态之间怎么转换
- 创建完成，进入就绪；
- 就绪的进程被调度程序选中，变为运行；
- 运行中时间片用完，回到就绪；
- 运行中发起读文件等操作，等结果时变为阻塞；
- 阻塞的事件发生后，先回到就绪，再排队等 CPU，不会直接变为运行；
- 运行结束后，进入结束。

最容易混淆的是就绪和阻塞：就绪是缺 CPU，阻塞是缺事件。

## 易错点
- 把就绪和阻塞当成一回事；就绪随时能跑，阻塞即使有 CPU 也不能跑
- 以为阻塞结束后直接运行；它要先回到就绪，等调度程序选中

## 追问
### [f1] 进程什么时候会从运行变成阻塞？
当它发起一个需要等待的操作，比如读磁盘、等网络数据、等锁时，操作系统会让出 CPU，把进程标为阻塞。
