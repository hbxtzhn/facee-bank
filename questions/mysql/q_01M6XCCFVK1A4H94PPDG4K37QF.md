## 一句话
分片键是用来算出数据该存哪张表的字段。系统拿它做一次计算（比如对表数取模），结果就是目标表。

## 要点
- [kp1|3] 分片键是决定一行数据落到哪张分表的字段，比如 user_id
- [kp2|3] 路由就是用分片键算出目标表，常见写法是对表数取模
- [kp3|2] 好的分片键值分布均匀，才不会出现某张表特别大
- [kp4] 分片键最好是查询条件里常用的字段，查询才能直达一张表

## 详解
### 先搞懂：数据太多，要分到几张表里
订单表涨到几亿行，查询和写入都变慢了，常见做法是把它拆成多张结构一样的小表，比如 `order_0` 到 `order_3`。这叫水平分表。

可以把它想成快递分拣：包裹来了，看收件人邮编，决定扔进哪个格口。这里的「邮编」就是分片键，「按邮编找格口的规则」就是路由。

后文会用到的术语：

- **分片键**：用来决定数据落到哪张表的那个字段。
- **路由**：根据分片键算出目标表的过程。
- **数据倾斜**：有的表数据特别多，有的几乎没有，分得不均匀。

### 路由：拿分片键算出目标表
假设订单按 `user_id` 分成 4 张表，规则是 `user_id % 4`：

- `user_id = 10`，算出 2，写入 `order_2`；
- `user_id = 11`，算出 3，写入 `order_3`。

查询时也走同样的计算。带着 `user_id` 来查，先算出表名，只查那一张表，不用把 4 张表都翻一遍。

### 分片键怎么选
选分片键主要看三点：

1. **值要分散**：如果选「性别」这种只有两三个取值的字段，数据只会挤进两三张表，其他表是空的。
2. **查询常用**：如果查询条件里根本不带分片键，系统不知道去哪张表找，只能每张表都查一遍。
3. **写入也要均匀**：写入量不能集中在某一张表上。

### 常见的路由方式
常见有三种：按范围划分、对分片键做哈希后取模、用一张配置表记录映射。它们各有取舍，题库里有专门的题讲怎么选。

## 示例
```sql
-- 4 张分表，按 user_id 取模路由
-- user_id = 10  ->  10 % 4 = 2  ->  order_2
INSERT INTO order_2 (order_id, user_id, amount)
VALUES (1001, 10, 99.00);

-- 查询时带上分片键，只需要查一张表
SELECT * FROM order_2 WHERE user_id = 10;
```

## 易错点
- 以为分片键随便选一个字段就行；选了取值很少的字段，会造成严重的数据倾斜
- 以为分片键只在写入时用；查询不带分片键，就只能扫描所有分表
- 以为分表后原来的自增主键还能直接用；多张表各自自增会重复，需要另外生成唯一 ID

## 追问
### [f1] 查询条件里没有分片键怎么办？
只能向所有分表各发一次查询，再把结果合并，开销大。常见做法是建一张「其他字段到分片键」的映射表，先查映射再定位分表。
