## 一句话
事实记忆存用户偏好和明确事实，经验记忆存过去的决策过程和成败教训；两者用法不同，所以检索和更新的策略也要分开。

## 要点
- [kp1|3] 事实记忆存明确、可核对的信息，如用户偏好、姓名、所在城市
- [kp2|3] 经验记忆存过去怎么做的、结果如何，以及从中总结的教训
- [kp3|2] 事实记忆按内容检索，新旧冲突时用新值覆盖
- [kp4|2] 经验记忆按相似任务检索，用于参考做法，不是覆盖
- [kp5] 区分之后，存什么、取什么、何时淘汰都能分别设计

## 详解
### 先搞懂：通讯录和工作日志
手机里的通讯录记着朋友的电话、生日，这是事实，对就是对、错就是错，换号码了就改掉。工作日志记着上次做某个项目怎么推进的、哪个方案踩了坑，这是经验，没有对错，只供下次做类似的事时参考。

Agent 的记忆也可以分成这两种。

后文用到的术语：
- **事实记忆**：明确的、可以核对的信息。
- **经验记忆**：历史决策轨迹，以及成功和失败的教训。
- **检索**：根据当前任务，从记忆里找出相关内容。

### 事实记忆：存是什么
典型内容有：用户喜欢简洁回答、用户在某个城市、用户使用某种编程语言。

特点是结构简单、一条一条的，新信息可能和旧信息冲突，比如用户搬家了。所以更新策略是发现冲突时用新值覆盖旧值，并保留时间信息。

### 经验记忆：存怎么做
典型内容有：上次排查某类故障时，先查了什么、哪一步有效、哪个做法走不通。

它通常是一段过程加结论，比较长，也很难判断对错。检索时要按任务的相似性去找，找到后当作参考，让 Agent 少走弯路。

### 为什么要区分
| 对比点 | 事实记忆 | 经验记忆 |
|---|---|---|
| 内容 | 偏好、明确事实 | 决策轨迹、成败教训 |
| 形式 | 简短条目 | 过程加总结 |
| 检索方式 | 按主题或键查找 | 按任务相似度检索 |
| 更新方式 | 冲突时覆盖 | 追加，并定期整理 |

结论：混在一起存，检索会混乱，更新也会互相干扰；分开存，各用合适的策略，效果更稳。

### 进阶：记忆写入要谨慎（基础薄弱可先跳过）
- 不是所有对话内容都值得写入，先判断是否有长期价值。
- 失败的经验和成功的一样有价值，但要标明是失败。
- 过期或被证伪的记忆要能删除，否则会误导后续决策。

## 示例
```json
{
  "fact": {"user_id": "u1", "key": "answer_style", "value": "简洁"},
  "experience": {
    "task": "排查接口超时",
    "steps": ["查网关日志", "查数据库慢查询"],
    "lesson": "先查慢查询比查网关更快定位"
  }
}
```

## 易错点
- 以为记忆就是把对话原文全存下来；应提炼后再写入
- 以为事实永远不变；用户的偏好和情况会变，需要更新机制
- 以为经验记忆只记成功；失败教训同样有价值

## 追问
### [f1] 事实冲突了怎么处理？
通常以较新的信息为准覆盖旧值，同时记录更新时间。如果无法判断哪个对，可以向用户确认。

### [f2] 经验记忆怎么避免越存越乱？
写入时做总结而不是存全部过程，并定期去重、合并相似内容，删除过时的条目。
