### 先理解问题

普通的文字生成失败，重新请求通常只是多做一次计算。但 Agent 在生成期间可能调用工具。工具执行后，外部世界可能已经改变：例如已写入一条数据，或者已向群里发送消息。模型随后报错，并不能把之前的写入撤销。若备用模型从原来的问题重新开始推理，它可能再次决定做同一件事。

### 代码里的处理过程

在群 Agent 路径中，每轮会维护一份工具执行证据。工具被包装执行时，系统记录它的副作用类型、是否开始、是否结束以及是否失败。`ToolEffects.snapshot()` 将整轮记录汇总：没有工具操作，或所有记录都是已结束且成功的只读操作时，副作用检查才允许重放；存在未知类型、写入、未结束或失败记录时不允许。已开始发送和剩余时间不足也会阻止后续备用尝试。调用模型失败并不自动意味着可以重试。

项目把经过审查的本地只读和外部只读都视作只读类型；外部只读也必须是不会改变本地或远端状态的查询。尚未声明的工具按未知类型处理。副作用声明绑定工具对象，不由模型给出的名称、参数或结果自行决定。这里描述的是已阅读的群 Agent 路径，不能推断所有入口实现完全相同。

### 用例子记住它

假设一轮中先查到资料，再尝试发送群消息，随后模型连接中断。尽管查询本身安全，发送可能已经发生，因此这轮不能让备用模型重新运行。反过来，如果只查了一次资料、查询成功结束，且没有其他阻断条件，则副作用方面允许尝试备用模型；这仍不是保证一定切换，剩余预算等条件还要满足。
