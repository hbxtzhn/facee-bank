## 一句话
MyBatis-Plus 是 MyBatis 的增强工具，只增强不改变：提供通用 CRUD、条件构造器和分页插件，常见的单表操作不用再手写 SQL。

## 要点
- [kp1|3] 在 MyBatis 基础上增强，不改变 MyBatis 原有用法
- [kp2|3] Mapper 继承 `BaseMapper`，就拥有单表的增删改查方法
- [kp3|2] 提供条件构造器，用 Java 代码拼查询条件
- [kp4|2] 提供分页插件，使用前需要注册
- [kp5] 复杂 SQL 仍然可以照常写 XML

## 详解
### 先搞懂：它解决什么痛点
纯 MyBatis 里，一张表要写增删改查四五条 SQL。十张表就是几十条，大多都是重复的模板代码，比如 `select * from user where id = ?`。

MyBatis-Plus 的想法是：这种大家都一样的单表操作，框架替你生成，你只写真正复杂的业务 SQL。

- **CRUD**：增加、查询、修改、删除这四种基本操作。
- **增强**：保留原有功能，额外加功能。

### 通用 CRUD：继承就有
让你的 Mapper 接口继承 `BaseMapper<实体类>`，就自动拥有 `selectById`、`insert`、`updateById`、`deleteById` 等方法，不需要写 XML。

实体类通过 `@TableName`、`@TableId` 等注解，说明它对应哪张表、哪个是主键。

### 条件构造器与分页
单表查询条件不固定时，可以用条件构造器写，比如“年龄大于 18 并且姓名包含某字”，不用拼 SQL 字符串。

分页方面提供了分页插件，注册后传入分页对象，就能完成分页查询并拿到总数。

### 它不能做什么
多表关联的复杂查询，MyBatis-Plus 不会替你生成。这时仍然写 XML 或注解 SQL，和普通 MyBatis 并存。

## 示例
```java
@TableName("user")
public class User {
    @TableId(type = IdType.AUTO)
    private Long id;
    private String name;
}

public interface UserMapper extends BaseMapper<User> { }

// 使用：不用写任何 SQL
User u = userMapper.selectById(1L);
userMapper.insert(new User());
```

## 易错点
- 以为引入后分页自动生效；分页插件需要先注册
- 实体类名和表名对不上，又没写 `@TableName`，运行时报表不存在
- 想用它解决多表关联查询，最后还是得手写 SQL

## 追问
### [f1] 引入 MyBatis-Plus 会影响原有的 MyBatis 代码吗？
基本不会。它在原有基础上增强，原来的 XML 和接口照常使用，可以逐步迁移。
