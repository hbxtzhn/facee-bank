## 一句话
inode 保存文件的元数据，比如大小、权限和数据块位置；文件名只是目录里指向 inode 编号的一条记录。

## 要点
- [kp1|3] inode 存放文件的元数据：大小、权限、时间、数据块位置等
- [kp2|3] 文件名不存在 inode 里，只是目录项里指向 inode 编号的记录
- [kp3|2] 打开文件时，先通过文件名在目录里找到 inode，再读数据
- [kp4|2] 一个 inode 可以对应多个文件名，这就是硬链接
- [kp5] inode 数量用完时，即使磁盘有空间也建不了新文件

## 详解
### 先搞懂：图书馆的索引卡
图书馆里，书名写在目录卡片上，卡片上记着书的编号；编号对应的登记表里才写着书的位置、页数、借阅规则。书名是名字，登记表是真正的内容描述。

文件系统同理：目录里记着「文件名对应哪个编号」，编号指向 inode，inode 里记着这个文件的各种信息。

后文会用到几个词：

- **inode**：存放文件元数据的结构，用编号标识。
- **目录项**：目录里的一条记录，包含文件名和 inode 编号。
- **元数据**：描述文件的信息，不是文件内容本身。

### inode 里有什么
- 文件大小、类型；
- 权限、所有者；
- 创建、修改、访问时间；
- 数据块在磁盘上的位置；
- 引用计数，即有多少个目录项指向它。

它不保存文件名。

### 文件名和 inode 的关系
目录本身也是一种特殊文件，内容就是一张「文件名到 inode 编号」的表。访问一个路径时，系统逐级查目录，最后拿到 inode 编号，再用 inode 找到数据块。

所以重命名文件只是改目录里的名字，inode 和数据不动。多个名字指向同一个 inode，就是硬链接。

### inode 的数量
创建文件系统时，inode 的总数通常就确定了。小文件特别多时，inode 可能先用完，这时磁盘上还有空间，也无法再创建文件。

## 示例
```bash
ls -i file.txt      # 查看文件的 inode 编号
stat file.txt       # 查看大小、权限、inode 等元数据
df -i               # 查看各文件系统 inode 使用情况
```

## 易错点
- 以为文件名保存在 inode 里；文件名在目录项里
- 以为 inode 用完前不会出问题；它可以先于磁盘空间耗尽
- 以为重命名会搬动数据；同一个文件系统内重命名通常只改目录项

## 追问
### [f1] 删除文件时 inode 会怎样？
先删掉目录项，引用计数减一。当计数变成 0 且没有进程打开它时，系统才释放 inode 和数据块。
