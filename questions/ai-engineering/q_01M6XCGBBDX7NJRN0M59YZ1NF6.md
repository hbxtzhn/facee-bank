## 一句话
AI 工作流是一张有向图：节点负责执行具体步骤，边决定下一步走向哪里，共享状态在各节点之间传递上下文。

## 要点
- [kp1|3] 工作流由节点、边和状态三部分组成
- [kp2|3] 节点执行一个具体步骤，如调用模型、查数据库、跑代码
- [kp3|2] 边决定流转方向，可以是固定的，也可以按条件分支
- [kp4|2] 状态是各节点共享的数据，前一个节点的输出供后面使用
- [kp5] 有向图允许分支和循环，不只是一条直线

## 详解
### 先搞懂：像一张流水线图
想象一家工厂的流水线：每个工位做一件事，传送带决定半成品去哪个工位，托盘上放着当前的半成品和说明单，每个工位都能看、能改。

工作流就是这样：工位是节点，传送带是边，托盘上的东西是状态。

后文用到的术语：
- **节点**：一个执行步骤。
- **边**：连接两个节点，规定执行顺序。
- **状态**：在整个流程中共享、会被不断更新的数据。
- **有向图**：边有方向，从哪个节点指向哪个节点。

### 三个组成部分
- **节点**：做具体的事，可以是一次模型调用、一次工具调用，也可以是一段普通代码。
- **边**：规定节点之间的走向。固定边是做完 A 一定去 B；条件边是看状态决定去 B 还是去 C。
- **状态**：保存用户输入、中间结果等。节点读状态，处理后写回状态，下一个节点就能用到。

### 为什么用图
图可以表达三种常见结构：

1. 顺序：先抽取，再总结；
2. 分支：判断是否需要查资料，需要则走检索节点；
3. 循环：检查结果不合格，就回到生成节点重做。

结构由人事先设计，所以流程可预测、可调试，每一步都能看到状态。

### 对比：工作流和 Agent
| 对比点 | 工作流 | Agent |
|---|---|---|
| 步骤谁定 | 开发者提前设计 | 模型运行时决定 |
| 可预测性 | 高 | 较低 |
| 灵活性 | 较低 | 较高 |

结论：流程固定、要求稳定时用工作流；步骤无法预先确定时用 Agent。

## 示例
```python
state = {"question": "什么是 RAG", "docs": None, "answer": None}

def retrieve(s): s["docs"] = search(s["question"]); return s    # 节点 1
def generate(s): s["answer"] = llm(s["question"], s["docs"]); return s  # 节点 2

for node in [retrieve, generate]:     # 边：先检索再生成
    state = node(state)
```

## 易错点
- 以为工作流就是一条直线；它可以有分支和循环
- 以为节点一定要调用大模型；节点也可以是普通代码或工具
- 以为状态是每个节点私有的；它是整个流程共享的

## 追问
### [f1] 条件边是怎么决定走向的？
通常是一个判断函数，读取当前状态，返回下一个节点的名字。比如状态里置信度低就走人工审核节点。

### [f2] 工作流为什么便于调试？
每个节点的输入输出都保存在状态里，出问题时可以逐节点查看，定位是哪一步出错。
