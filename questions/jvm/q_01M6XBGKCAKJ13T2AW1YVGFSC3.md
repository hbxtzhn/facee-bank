## 一句话
Java 堆是所有线程共享的内存区域，用来存放 new 出来的对象实例和数组，也是垃圾回收的主要区域；堆装不下时抛 OutOfMemoryError。

## 要点
- [kp1|3] 堆存放对象实例和数组，是线程共享的
- [kp2|3] 堆是垃圾回收的主要区域，不再使用的对象由 GC 回收
- [kp3|2] 堆通常分为新生代和老年代，新生代又分 Eden 和两个 Survivor
- [kp4|2] 堆空间不足时抛 OutOfMemoryError: Java heap space
- [kp5] 用 -Xms 和 -Xmx 设置堆的初始值和最大值

## 详解
### 先搞懂：堆就是程序的“公共仓库”
你在代码里写 `new User()`，创建出来的对象就放在堆里。所有线程都能访问这个仓库，所以对象可以在线程之间传递和共享。

术语：
- **对象实例**：`new` 出来的东西，每个对象占一块内存；
- **GC（垃圾回收）**：自动清理不再使用的对象。

### 堆里怎么分区
| 区域 | 放什么 |
|---|---|
| 新生代 Eden | 新创建的对象先放这里 |
| 新生代 Survivor（两个） | Eden 回收后存活的对象，在两个区之间来回复制 |
| 老年代 | 在新生代里活得久的对象 |

新生代中的对象大多“朝生夕灭”，所以回收频繁；老年代存放长期存活的对象。

### 堆的大小和溢出
用 `-Xms` 设置初始大小，`-Xmx` 设置最大大小。GC 之后仍然放不下新对象，就会抛出 `OutOfMemoryError: Java heap space`。

### 堆和别的区域的区别
堆管“对象和数组”，栈管“方法调用和局部变量”，元空间管“类信息”。对象的引用变量放在栈里，指向堆中的对象本体。

## 示例
```java
User user = new User();   // user 引用在栈上，User 对象本体在堆上
int[] arr = new int[10];  // 数组对象也在堆上
```

## 易错点
- 以为所有变量都在堆上；局部变量在栈上，堆上存的是对象本体
- 以为所有对象都一定分配在堆；HotSpot 的优化可能让不逃逸的对象不真正在堆上创建，但从语言层面可按“对象在堆上”理解

## 追问
### [f1] 堆为什么要分新生代和老年代？
大多数对象生命周期很短，把它们集中放在新生代，可以频繁、快速地回收；少数长期存活的对象移到老年代，减少无谓的扫描。
