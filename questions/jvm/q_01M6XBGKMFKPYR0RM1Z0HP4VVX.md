## 一句话
虚拟机栈是线程私有的，每调用一个方法就压入一个栈帧，里面放该方法的局部变量等信息，方法返回时栈帧出栈。

## 要点
- [kp1|3] 虚拟机栈是线程私有的，每个线程有自己的一个栈
- [kp2|3] 每次方法调用压入一个栈帧，方法返回时弹出
- [kp3|2] 栈帧里存放局部变量、操作数栈等该方法运行所需的信息
- [kp4|2] 调用层数过深时抛 StackOverflowError，常见于无限递归
- [kp5] 用 -Xss 设置每个线程栈的大小

## 详解
### 先搞懂：像一摞盘子，只能从最上面拿放
你在做菜（A 方法）时，需要先去切菜（B 方法），就把“做菜”暂停，放一个新盘子“切菜”在最上面；切完拿走，回到“做菜”。虚拟机栈就是这摞盘子，每个盘子是一个**栈帧**。

术语：
- **栈帧**：一次方法调用占用的内存，存局部变量等；
- **局部变量**：方法内部定义的变量，如参数、方法里声明的 `int a`。

### 栈帧里有什么
| 内容 | 作用 |
|---|---|
| 局部变量表 | 存放方法的参数和局部变量 |
| 操作数栈 | 执行字节码指令时临时存放计算数据 |
| 方法出口等信息 | 方法返回后回到哪里继续执行 |

### 调用和返回的过程
1. 线程执行 `main`，先把 `main` 的栈帧压入栈；
2. `main` 调用 `foo`，再压入 `foo` 的栈帧，当前执行的就是栈顶的 `foo`；
3. `foo` 执行完返回，栈帧出栈，回到 `main` 继续执行。

每个线程同一时刻只有一个活动栈帧，也就是正在执行的那个方法。

### 栈溢出
栈的大小有限，递归没有终止条件时，栈帧一层层压入，最后放不下，抛出 `StackOverflowError`。可用 `-Xss` 调整栈大小，但根本办法是修正递归逻辑。

## 示例
```java
void a() { b(); }   // 调用 a：压入 a 的栈帧
void b() { c(); }   // a 调 b：压入 b 的栈帧
void c() { }        // c 返回后依次出栈
```

## 易错点
- 以为栈里存对象；栈里只存局部变量，对象引用存栈中，对象本体在堆
- 以为栈需要 GC；栈帧随方法返回自动出栈，不由 GC 回收

## 追问
### [f1] 栈和线程是什么关系？
每个线程创建时会有自己的栈，线程之间的栈互相独立，所以局部变量天然线程安全。
