## 一句话
互斥锁是一把锁：线程进临界区前先加锁，出来后解锁，这样同一时刻只有一个线程能在临界区里。

## 要点
- [kp1|3] 想进临界区必须先加锁，加锁成功才能进入
- [kp2|3] 锁已被别人持有时，加锁的线程要等待，直到对方解锁
- [kp3|2] 用完必须解锁，否则其他线程会一直等
- [kp4] 锁可以只是一个变量，比如 0 表示没上锁，1 表示已上锁

## 详解
### 先搞懂：公共厕所的门锁
公共厕所里有人时门是锁着的，别人只能在外面等。里面的人出来后开锁，下一个人才能进去。互斥锁就是这个门锁。

后文会用到几个词：

- **互斥锁**：同一时刻只允许一个线程持有的锁。
- **加锁 / 解锁**：申请和释放这把锁。
- **持有**：成功加锁、还没解锁的状态。

### 使用流程
1. 线程准备进入临界区，先尝试加锁。
2. 如果没人持有，加锁成功，线程进入临界区访问共享数据。
3. 如果别人持有，线程要等，等到持有者解锁。
4. 访问完成后线程解锁，放行等待的线程。

### 加锁加的是什么
可以是某个对象，也可以只是一个简单的变量。比如用整数表示：0 无锁，1 已上锁。要注意，检查变量和修改变量这两步必须是原子的，否则两个线程可能同时认为没上锁。实际中这由操作系统或硬件的原子指令保证。

### 等不到锁时怎么办
大体分两类：一类是线程原地不停检查（忙等待），另一类是线程让出 CPU、进入阻塞，等锁释放再被唤醒（无忙等待）。具体区别在另一道题里展开。

## 示例
```java
import java.util.concurrent.locks.ReentrantLock;

ReentrantLock lock = new ReentrantLock();

lock.lock();          // 加锁
try {
    // 访问共享数据
} finally {
    lock.unlock();    // 一定要在 finally 里解锁
}
```

## 易错点
- 加锁后没有解锁，或异常时跳过了解锁，其他线程会永远等下去
- 不同线程用了不同的锁对象，起不到互斥作用；保护同一份数据要用同一把锁
- 以为互斥锁能保证先来的先拿到；是否公平取决于具体实现

## 追问
### [f1] 互斥锁和信号量有什么区别？
互斥锁只有锁住和没锁住两种状态，且一般由加锁的线程来解锁。信号量是一个计数器，可以允许多个线程同时进入，用来表示多个可用资源。
