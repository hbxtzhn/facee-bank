## 一句话
思维链是让模型把推理过程一步步写出来再给结论，这样复杂问题更不容易算错，Agent 的规划和决策也建立在这种逐步推理上。

## 要点
- [kp1|3] 思维链就是让模型先写推理步骤，再给最终答案
- [kp2|3] 把大问题拆成小步，通常能提高多步推理类任务的正确率
- [kp3|2] 可以靠提示词触发，比如要求模型一步一步思考
- [kp4] Agent 用它分析状态、拆解目标、决定下一步行动

## 详解
### 先搞懂：算数要写过程
小学做应用题，老师总说要写步骤。直接心算一个复杂题容易错，一步一步写出来，每步都简单，整体就对了。

模型也一样。它是一个 token 一个 token 往外生成的，如果直接给结论，相当于在脑子里一步算完；先写推理过程，等于有了草稿纸，每一步都建立在前面写下的内容上。

后文用到的术语：
- **推理步骤**：从问题到结论中间的分析过程。
- **提示词**：你发给模型的指令和问题。

### 怎么触发思维链
有两种常见方式：

1. **给示例**：在提示词里放一两个带推理过程的例子，模型会模仿格式；
2. **直接要求**：在问题后面加上「请一步一步思考」之类的话。

现在也有专门训练过的推理模型，会在回答前自动生成较长的思考过程，不再需要用户额外提示。

### 它为什么有效，又有什么代价
有效的原因是中间步骤变成了模型后续生成的上下文，复杂问题被拆成一连串更简单的预测。

代价是输出变长，消耗更多 token，响应也更慢。简单问题没必要用。另外，写出来的推理过程看起来合理，不代表一定正确，仍然需要验证。

### 和 Agent 的关系
Agent 每一轮都要判断现在是什么情况、下一步做什么。这个判断就是靠思维链完成的：先写出对任务状态的分析，再决定调用哪个工具。

## 示例
```text
问题：小明有 5 个苹果，吃掉 2 个，又买来 3 袋，每袋 4 个，现在有几个？
请一步一步思考：
1. 吃掉后剩 5 - 2 = 3 个
2. 买来 3 x 4 = 12 个
3. 共 3 + 12 = 15 个
答案：15
```

## 易错点
- 以为思维链对所有问题都有用；简单问题只会白白增加输出长度
- 以为推理过程写得通顺就一定对；中间步骤也可能出错
- 以为只有提示词能触发；推理模型会自带思考过程

## 追问
### [f1] 思维链和 ReAct 是什么关系？
思维链只负责推理；ReAct 在推理之外加入工具调用，让推理和行动交替进行。可以说 ReAct 是把思维链用到了需要与环境交互的场景。

### [f2] 思维链会带来什么成本？
输出更长，消耗更多 token，延迟也更高。需要权衡的是答案正确率和成本。
