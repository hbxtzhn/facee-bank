## 一句话
消息队列是存放消息的容器，生产者把消息放进去，消费者再按先进先出的顺序取出来处理，双方不用同时在线。

## 要点
- [kp1|3] 消息队列是暂存消息的容器，一般按先进先出传递
- [kp2|3] 生产者负责发消息，消费者负责处理消息
- [kp3|2] 双方不直接通信，而是通过队列异步配合
- [kp4] 它属于中间件，为上层应用提供通信支撑

## 详解
### 先搞懂：小区门口的快递柜
快递员送货时，不用等你在家，把包裹放进快递柜就走。你下班后再去柜子里取，先放进去的包裹一般先被取走。

消息队列就是这个快递柜。先说几个词：

- **消息**：一段要传递的数据，比如“用户 123 下单了”。
- **生产者**：发消息的一方，相当于快递员。
- **消费者**：收消息并处理的一方，相当于取件人。
- **Broker（服务端）**：保管队列的那台服务，相当于快递柜本身。

### 它是怎么工作的
1. 生产者把消息发给 Broker，放进队列；
2. 消息在队列里排队，先到的排在前面；
3. 消费者从队列里取走消息，按顺序处理；
4. 处理完成后告诉 Broker，这条消息就算被消费了。

整个过程中，生产者发完就可以去干别的，不用等消费者处理完。这就是**异步**通信。

### 它解决什么问题
没有消息队列时，A 服务要直接调用 B 服务，B 慢了或挂了，A 也会受影响。有了消息队列，A 只管把消息放进去，B 什么时候处理、处理多快，A 都不用关心。

### 它在系统里的角色
消息队列不直接面向用户，而是夹在各个服务之间做传话员，所以归类为**中间件**。常见的有 Kafka、RocketMQ、RabbitMQ。

## 示例
```java
// 伪代码：生产者发送，消费者处理
producer.send("order-topic", "order-123 created");

consumer.subscribe("order-topic", message -> {
    System.out.println("处理消息：" + message);
});
```

## 易错点
- 以为消息队列保证消息立刻被处理；它只保证消息被暂存，处理时机由消费者决定
- 以为所有消息队列都严格全局先进先出；有些产品只保证同一分区内有序

## 追问
### [f1] 消息队列和直接调用接口有什么区别？
直接调用是同步的，调用方要等对方返回，对方挂了会连累调用方。消息队列是异步的，调用方把消息交给队列就可以继续往下走。
