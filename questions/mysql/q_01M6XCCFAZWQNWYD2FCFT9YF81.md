## 一句话
垂直分表是把字段拆开，大字段、冷字段单独放一张表；水平分表是把行拆开，按分片键分散到多张结构相同的表。

## 要点
- [kp1|3] 垂直分表按字段拆，把大字段或不常用字段拆到扩展表
- [kp2|3] 水平分表按行拆，表结构相同，数据按分片键分散
- [kp3|2] 垂直分表让常用查询每行更小，一页能放更多行，IO 更少
- [kp4] 水平分表需要路由策略，常见有范围、哈希和配置表

## 详解
### 先搞懂：一张宽表，是拆列还是拆行
想象一张学生登记表，每行有姓名、学号这些基本信息，还有一大段个人简介和照片。查名单时只需要姓名学号，但每次都要把简介和照片一起读，很浪费。办法一：把简介和照片单独放另一张表（拆列）。办法二：学生太多，一张纸放不下，按学号分到几张表里（拆行）。

几个术语：

- **垂直分表**：按字段拆，一张表拆成多张表。
- **水平分表**：按行拆，一张表的数据分到多张结构相同的表。
- **扩展表**：存放拆出来的大字段或冷字段的表。
- **路由**：决定一行数据存到哪张表、去哪张表查。

### 垂直分表：拆字段
把常用的基本字段留在主表，大文本、很少用的字段拆到扩展表，两张表用同一个主键关联：

- 主表每行更短，一个数据页能放更多行，查基础数据时读的页更少；
- 需要大字段时，再用主键去扩展表查。

### 水平分表：拆行
表的行数太多，字段拆分也不够了，就把数据分散到多张表，比如 `order_0`、`order_1`、`order_2`。要定一个分片键，再用路由策略决定每行去哪。

### 方案对比：常见的路由策略
| 策略 | 怎么分 | 优点 | 缺点 |
|---|---|---|---|
| 范围路由 | 按值的区间分，如按时间或 ID 段 | 实现简单，扩容只需新增表 | 数据可能不均匀，热点集中在最新一段 |
| 哈希路由 | 对分片键哈希后取模 | 数据分布比较均匀 | 范围查询要查多张表，扩容要迁移数据 |
| 配置路由 | 用配置表记录对应关系 | 灵活，可以随时调整 | 要维护配置表，多一次查询 |

结论：想要数据分布均匀，默认选哈希路由；数据按时间增长、常按范围查，选范围路由；分布不规律时用配置路由。

### 进阶：拆完以后（基础薄弱可先跳过）
分表后，主键不能再靠单表自增，需要分布式 ID；不带分片键的查询需要访问所有分表；表结构变更要同步到每张分表。

## 示例
```sql
-- 垂直分表：主表放基本信息，扩展表放大字段
CREATE TABLE article (
  id BIGINT PRIMARY KEY,
  title VARCHAR(200),
  author_id BIGINT
);
CREATE TABLE article_content (
  article_id BIGINT PRIMARY KEY,
  content LONGTEXT
);
```

## 易错点
- 把垂直和水平搞反；垂直是拆字段，水平是拆行
- 以为分表后原来的自增主键还能用；各表自增会重复，要换成全局唯一 ID
- 以为水平分表一定要分库；分表可以在同一个库里进行

## 追问
### [f1] 水平分表后怎么做分页或排序查询？
没有分片键的话，要分别从各表查再合并排序，深翻页代价很高；常见做法是限制翻页深度，或把数据同步到搜索引擎专门查询。
