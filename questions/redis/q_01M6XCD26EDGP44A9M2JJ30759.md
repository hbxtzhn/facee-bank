## 一句话
RDB 是定时快照，文件小、恢复快，但可能丢最后一次快照之后的数据；AOF 记录写命令，更实时但文件大、恢复慢。要求高时两个都开。

## 要点
- [kp1|3] RDB 是某一时刻的快照，文件紧凑、恢复快，宕机会丢快照之后的数据
- [kp2|3] AOF 记录每条写命令，数据更完整，文件更大、恢复更慢
- [kp3|2] 数据安全要求高，两者同时开启，重启时优先加载 AOF
- [kp4] 能接受丢几分钟数据，只用 RDB；只用 AOF 则缺少方便的备份文件

## 详解
### 先搞懂：照片和流水账
RDB 像定期拍的账户照片：一张照片就是完整状态，翻出来就能用，所以恢复快；但两次拍照之间的变化不在照片里。AOF 像逐笔记的流水账：几乎每笔都有，所以丢得少；但账本又长又厚，从头算一遍才知道余额，所以恢复慢。

后文用到的词：
- **RDB**：某一时刻的数据快照，二进制文件。
- **AOF**：追加记录每条写命令的日志文件。
- **持久化**：把内存数据保存到磁盘。

### 两者的区别
| 维度 | RDB | AOF |
|---|---|---|
| 保存内容 | 某一时刻的完整数据 | 每条写命令 |
| 丢数据 | 可能丢最后一次快照后的数据 | 取决于同步策略，默认最多约丢 1 秒 |
| 文件大小 | 紧凑，较小 | 较大，需要重写压缩 |
| 恢复速度 | 快，直接加载数据 | 慢，要重放命令 |
| 对运行的影响 | 快照时 fork，有写时复制开销 | 持续写日志，受同步策略影响 |
| 适合 | 备份、容灾、快速恢复 | 追求更少丢数据 |

### 怎么选
- **数据重要，想尽量不丢**：RDB 和 AOF 同时开启。重启时 Redis 优先用 AOF 恢复，因为它的数据通常更完整；RDB 留作备份。
- **可以接受丢几分钟数据**：只用 RDB 就够了，简单、恢复快。
- **只用 AOF**：能用，但 RDB 更适合做定期备份和快速重建，两者配合更稳妥。
- **只当缓存，数据丢了能重建**：可以两个都不开。

### 进阶：混合持久化（基础薄弱可先跳过）
Redis 4.0 起提供混合持久化：AOF 重写时，文件前半部分用 RDB 格式，后面接增量命令，兼顾恢复速度和数据完整。新版本默认开启，由 `aof-use-rdb-preamble` 控制。

## 易错点
- 以为开了 AOF 就不用 RDB；RDB 更适合做备份和跨机迁移
- 以为 AOF 一定比 RDB 更好；它的文件更大、恢复更慢
- 以为两个都开重启时会合并；实际优先加载 AOF，不会去合并 RDB

## 追问
### [f1] 两个都开时，重启用哪个恢复？
开启了 AOF 且存在 AOF 文件，就加载 AOF；否则加载 RDB。
