## 一句话
Lua 脚本是把多条 Redis 命令打包成一个脚本，用 EVAL 一次交给服务端执行；脚本执行期间不会被别的命令插入，所以多步操作像一步。

## 要点
- [kp1|3] EVAL 把一段 Lua 脚本发给 Redis，在服务端一次执行完
- [kp2|3] 脚本运行期间，Redis 不会处理其他客户端的命令
- [kp3|2] 适合“判断再修改”的多步操作，如释放锁、扣库存
- [kp4|2] 脚本不要写得太长或死循环，否则会阻塞整个 Redis
- [kp5] 脚本中途出错不会回滚，已执行的命令保留

## 详解
### 先搞懂：先问再改，中间会被插队
举一个扣库存的例子：先查库存是否大于 0，大于 0 再减 1。这是两条命令。

两个客户端同时来：都查到库存是 1，都认为够，都去减，库存就变成 -1，超卖了。

类比银行柜台：你把“查余额、判断、取钱”三件事写成一张单子交给柜员，柜员当场办完，中间不接待别人，就不会被插队。

后文用到的词：

- **EVAL**：执行一段 Lua 脚本的命令。
- **KEYS 和 ARGV**：传给脚本的 key 列表和参数列表。

### Lua 脚本怎么用
Lua 是一种轻量的脚本语言，Redis 内置了它的解释器。用法是：

```bash
EVAL "脚本内容" key个数 key1 key2 ... 参数1 参数2 ...
```

脚本里用 `redis.call('命令', 参数...)` 调用 Redis 命令，用 `KEYS[1]`、`ARGV[1]` 取传进来的值。

### 为什么能保证原子
Redis 执行命令是单线程的：一条命令执行时，其他命令排队等着。脚本被当作一条整体的命令来执行，所以脚本里所有的步骤连续跑完，期间没有别的命令能插进来。

这样“查库存、判断、扣减”写进一个脚本，就不会再有超卖。

### 使用时的注意点
- **阻塞**：脚本执行期间别的命令都在等，脚本越慢，整个 Redis 越卡。脚本要短，不要写长循环。
- **没有回滚**：脚本中间出错，前面已经执行的命令不会撤销。
- **集群**：在集群模式下，脚本访问的 key 要在同一个槽里。

## 示例
```bash
# 库存大于 0 才扣减，整个过程原子完成
EVAL "local n = tonumber(redis.call('get', KEYS[1])); if n and n > 0 then return redis.call('decr', KEYS[1]) else return -1 end" 1 stock:1001
```

## 易错点
- 以为脚本出错会整体回滚；已执行的命令不会撤销
- 以为脚本越长越划算；长脚本会长时间阻塞其他请求
- 以为“原子”指能抵抗宕机；它只表示执行过程不被其他命令打断

## 追问
### [f1] Lua 脚本和 MULTI/EXEC 事务有什么区别？
事务里的命令入队时不能依赖前一条的结果，脚本可以边执行边判断。需要“读了再判断再写”时，脚本更合适。
