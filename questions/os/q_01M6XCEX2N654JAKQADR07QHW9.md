## 一句话
系统调用是应用程序向操作系统内核请求服务的统一入口，比如读写文件、创建进程、申请内存，调用时 CPU 会从用户态切到内核态。

## 要点
- [kp1|3] 系统调用是用户程序请求内核服务的唯一正规入口
- [kp2|3] 调用时 CPU 从用户态切到内核态，内核做完再切回
- [kp3|2] 常见例子：open/read/write 操作文件，fork/exec 管理进程，mmap 管理内存
- [kp4] 应用一般通过库函数间接调用，不直接写系统调用指令

## 详解
### 先搞懂：为什么程序不能自己读磁盘
你写 Java 代码读一个文件，只写了 `new FileInputStream(...)`。真正去磁盘上取数据的不是你的程序，而是操作系统。

可以把操作系统想成银行柜台后面的金库。你是顾客，不能自己进金库拿钱，只能走到柜台，填一张单子，让柜员帮你办。系统调用就是这张单子和这个柜台窗口。

后文用到的几个词：
- **用户态**：普通程序运行的状态，权限受限，不能直接操作硬件。
- **内核态**：操作系统内核运行的状态，权限最高，能操作硬件和所有内存。
- **内核**：操作系统最核心的部分，管进程、内存、文件、设备。

### 系统调用：程序向内核递单子
操作系统要保护自己和别的程序，所以不让普通程序随便碰硬件和别人的内存。程序想做这些事，就得请内核代办。

常见的请求分几类：
- 文件和设备：`open`、`read`、`write`、`close`。
- 进程控制：`fork` 创建子进程，`exec` 加载新程序。
- 内存管理：`mmap` 把文件或一段空间映射到进程的地址空间。
- 网络：`socket`、`send`、`recv` 一类。

### 一次调用大致怎么走
1. 程序把要办的事（调用号）和参数准备好。
2. 执行一条特殊的指令，CPU 从用户态切到内核态，跳到内核预先设好的入口。
3. 内核检查参数是否合法，然后真正去做事。
4. 做完把结果放回，CPU 切回用户态，程序接着往下跑。

### 你平时是怎么用到它的
一般不会直接写这条特殊指令。你调用的是语言或 C 库提供的函数，比如 Java 的文件流，最终在底层会走到系统调用。库函数只是帮你包了一层。

## 易错点
- 以为所有库函数调用都是系统调用；很多函数只在用户态计算，用不到内核
- 以为系统调用和普通函数调用一样便宜；它要切换状态，比普通函数调用贵

## 追问
### [f1] 系统调用为什么比普通函数调用慢？
因为它要从用户态切到内核态，保存和恢复现场，还要检查参数。普通函数调用只是在同一状态下跳转。

### [f2] 举几个常见的系统调用？
文件类有 `open`、`read`、`write`，进程类有 `fork`、`exec`，内存类有 `mmap`。
