## 一句话
IP 层只负责尽力把包送出去，不保证送到：路由器拥塞会丢包，重传和多条路径会造成重复和乱序，所以 TCP 才要做确认和重传。

## 要点
- [kp1|3] IP 是尽力而为的服务，不保证包一定送达、不重复、不乱序
- [kp2|3] 路由器队列满了或链路出错，数据包就会被丢弃
- [kp3|2] 同一批包可能走不同路径，先发的后到，就是乱序
- [kp4] 发送方因超时误重传，接收方就可能收到重复的包

## 详解
### 先搞懂：寄快递会遇到的事
你一次寄出三个包裹，分别走不同的路线。有的被中转站压住丢了，有的绕路晚到，有的因为你催单，快递公司补发了一份，结果收到两份。

网络里的数据包就是这些包裹，IP 层就是只管运、不管结果的快递网络。

后文用到的术语：

- **数据包**：网络层传输的一小块数据，每个包独立转发。
- **路由器**：负责给数据包选路、转发的设备。
- **丢包**：数据包在途中被丢掉，没到目的地。
- **乱序**：包到达的先后顺序和发出的顺序不一样。

### 丢包：路上被扔掉了
丢包常见有两种原因：

- **拥塞**：路由器的缓冲队列是有限的。同时涌来的包太多，队列满了，后面的包只能被丢弃。
- **出错**：链路受到干扰，包的内容出错，校验失败后被丢弃。

IP 本身发现丢包也不会通知发送方，更不会补发。

### 重复：同一个包到了两次
发送方等确认等得太久，就会以为包丢了，再发一份。其实第一份只是慢了，最后两份都到了，接收方就收到了重复的数据。

### 乱序：先发的后到
网络里到一个目的地往往有多条路径，每个包独立选路。走短路径的后发先至，走长路径的先发后至，接收方看到的顺序就乱了。

### 这对 TCP 意味着什么
IP 既然不保证这三件事，想要可靠传输，就必须由上层 TCP 自己来补：

| 问题 | TCP 的对策 |
|---|---|
| 丢包 | 序列号加确认，没收到确认就超时重传 |
| 重复 | 靠序列号识别，重复的直接丢弃 |
| 乱序 | 靠序列号重新排好再交给应用 |

结论：TCP 用「编号、确认、重传」三件套，在不可靠的 IP 之上提供可靠的字节流。

## 易错点
- 以为 IP 层会重传丢掉的包；实际 IP 不管，重传是 TCP 的工作
- 以为乱序一定是出了故障；多路径转发下它是正常现象
- 以为收到重复包会让应用拿到重复数据；TCP 会按序列号去重

## 追问
### [f1] 那 UDP 遇到丢包乱序怎么办？
UDP 不做任何补救，丢了就是丢了，乱了就是乱了。要可靠只能由应用自己实现，比如加编号和重发逻辑。
