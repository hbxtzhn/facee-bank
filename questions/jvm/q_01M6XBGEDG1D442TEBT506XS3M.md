## 一句话
对象逃逸是指一个对象在创建它的方法之外还能被访问到，比如被当作返回值、赋给全局变量，或者被其他线程拿到。

## 要点
- [kp1|3] 对象在方法外还能被引用，就叫逃逸；只在方法内用，就是没逃逸
- [kp2|3] 常见逃逸方式：作为返回值、赋值给字段或静态变量、传给其他方法
- [kp3|2] 分为方法逃逸（被别的方法访问）和线程逃逸（被别的线程访问）
- [kp4] 逃逸分析由 JIT 编译器完成，是后续优化的前提

## 详解
### 先搞懂：东西有没有"带出门"
你在办公室里造了一个小工具，只在这间办公室里用，用完就丢。这个工具没出过这间办公室，别人也不知道它。对象也是这样：如果它在方法里创建、只在方法里用，外面谁也拿不到，这就是**没逃逸**。

如果你把它交给别的同事（返回给调用者），或者放在公共的柜子里（静态变量），这个工具就**逃出了**这间办公室。

后文用到的术语：
- **逃逸**：对象的引用被传到创建它的方法之外。
- **方法逃逸**：对象被其他方法访问到。
- **线程逃逸**：对象被其他线程访问到。

### 三种常见情况
- **没逃逸**：对象只在方法里用。
- **方法逃逸**：对象作为返回值，或者作为参数传给别的方法。
- **线程逃逸**：对象赋值给静态变量或其他线程可访问的字段，别的线程也能看到。

### 为什么要关心逃逸
没有逃逸的对象，只有当前线程会用，别人不会碰它。JIT 编译器据此可以做优化，比如不真的创建这个对象，或者省掉加锁。逃逸分析本身不改变程序结果，只是帮编译器判断"能不能这样优化"。

## 示例
```java
class Demo {
    static Point global;

    int noEscape() {
        Point p = new Point(1, 2);
        return p.x() + p.y();     // p 只在方法内使用：没逃逸
    }

    Point methodEscape() {
        return new Point(1, 2);   // 作为返回值：方法逃逸
    }

    void threadEscape() {
        global = new Point(1, 2); // 赋给静态变量：其他线程也能访问
    }
}
record Point(int x, int y) {}
```

## 易错点
- 以为对象一创建就能判断是否逃逸；这是 JIT 编译热点代码时做的分析
- 以为"传给别的方法"一定逃逸；如果被调用的方法被内联，可能仍判断为没逃逸
- 以为逃逸分析会改变程序行为；它只用来判断能否优化

## 追问
### [f1] 逃逸分析有什么用？
没逃逸的对象可以被 JIT 优化，比如标量替换、锁消除，减少堆上对象的创建和不必要的同步。
