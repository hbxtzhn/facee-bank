## 一句话
上下文切换就是保存当前进程的状态、选出下一个进程、恢复它的状态再让它运行；代价是保存恢复本身的开销和 CPU 缓存变冷。

## 要点
- [kp1|3] 步骤：保存当前进程上下文，调度选出下一个，恢复其上下文并运行
- [kp2|3] 上下文主要包括 CPU 寄存器和程序状态
- [kp3|2] 直接代价：保存恢复状态，加上调度程序本身的运行
- [kp4|2] 间接代价：CPU 缓存里的数据对新进程没用，要重新加载
- [kp5] 切换太频繁，CPU 花在切换上的时间会变多

## 详解
### 先搞懂：翻书看到一半被叫走
你在读一本书，读到第 80 页，同事叫你去帮忙。你得先夹个书签记住位置，再去做事。回来时翻到书签处接着读。

CPU 在多个进程之间切换也是这样：进程 A 暂时被打断时，要把「读到哪了」记下来，之后才能无缝接着运行。

后文要用的术语：

- **上下文**：进程运行到某一刻的状态，主要是寄存器里的内容。
- **调度程序**：操作系统里负责挑选下一个运行进程的部分。
- **CPU 缓存**：CPU 里放热点数据的高速存储，比内存快。

### 切换的完整步骤
假设 CPU 要从进程 A 切到进程 B：

1. **保存**：操作系统把 A 的寄存器和程序状态保存起来；
2. **选择**：调度程序从就绪的进程里选出下一个，比如 B；
3. **恢复**：把 B 上次保存的上下文装回 CPU；
4. **运行**：CPU 开始执行 B，从 B 上次停下的位置接着往下走。

触发切换的情况常见有：时间片用完、进程在等输入输出而被阻塞、有更高优先级的进程到来。

### 代价在哪里
**直接代价**：保存和恢复上下文要花时间，调度程序挑选进程也要运行。这些时间里没有一个用户进程在做有用的事。

**间接代价**：

- CPU 缓存里存的是 A 刚用过的数据，B 运行时要用的数据不在里面，要重新从内存加载，一开始会比较慢；
- 不同进程有不同的地址空间，切换进程还要切换内存映射，相关的地址转换缓存也要重新建立。

所以切换不是越多越好。线程太多、时间片太短，CPU 花在切换上的时间占比就会变大，整体吞吐反而下降。

### 进阶：进程切换和线程切换（基础薄弱可先跳过）
同一进程内的线程共享地址空间，切换线程时不需要换内存映射，所以通常比切换进程代价小。切换动作发生在内核态，需要 CPU 先从用户态切到内核态。

## 易错点
- 以为切换只有保存寄存器这一点代价；缓存变冷这类间接代价也很重要
- 以为切换越频繁越好；过于频繁会让 CPU 把时间耗在切换上
- 以为上下文只有寄存器；还包括程序状态等信息

## 追问
### [f1] 哪些情况会触发进程上下文切换？
常见有时间片用完、进程等待输入输出而阻塞、更高优先级的进程变为就绪，以及进程主动让出 CPU。
