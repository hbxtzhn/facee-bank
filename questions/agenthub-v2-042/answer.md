用户的问题属于输入数据，其中可能包含引号或类似查询运算符的字符。如果直接把输入拼进 SQL 或搜索表达式，输入可能改变原本的查询结构，造成语法错误或超出预期的匹配。项目会从问题中选择查询词，再为 FTS MATCH 构造带引号的短语，并用绑定参数传给 SQL。

这里有两层不同的边界：SQL 参数绑定避免把输入当 SQL 结构；FTS 短语构造则约束搜索引擎如何解释查询内容。两者不能互相代替。代码还对生成链接的 ID、站内路径等做格式限制，但这些检查各有用途，不能把“做了参数绑定”说成所有链接和权限问题都已解决。

例如用户输入中带有 FTS 运算符时，系统希望把候选词按受控短语处理，而不是让用户通过问题文本任意重组 MATCH 查询。之后仍要根据发布状态和访问范围过滤数据，防止合法搜索语法返回不该看的资料。
