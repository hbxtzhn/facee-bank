## 一句话
新建和销毁线程要消耗系统资源，线程数量失控还会拖垮服务；线程池复用已有线程、任务来了直接执行，并且能限制并发数。

## 要点
- [kp1|3] 新建和销毁线程都要消耗系统资源，任务短时尤其不划算
- [kp2|3] 线程池复用线程，任务到达时不用等线程创建，响应更快
- [kp3|2] 线程池能限制线程数量，避免请求突增时线程暴涨
- [kp4] 线程池还支持定时、周期、单线程等执行方式

## 详解
### 先搞懂：打车和养专职司机
你每次出门都临时找一辆车，用完就还回去：每次都要叫车、等车，成本很高。如果公司养几个专职司机，随叫随到，用完回休息室等下一单，省时间也好管理。

线程池就是这些专职司机。后文术语：

- **线程**：程序里一条独立执行的路线，Java 的线程对应操作系统的线程。
- **上下文切换**：CPU 从一个线程换去运行另一个线程时，保存和恢复现场的过程，是有成本的。

### 每个任务新建线程的问题
- **创建销毁成本高**：每新建一个线程，都要向操作系统申请资源，用完再销毁。任务很短时，建线程的时间可能比干活还长。
- **响应慢**：任务到了才开始创建线程，用户要多等一会儿。
- **数量失控**：流量突增时每个请求一个线程，内存被占满，CPU 又要在大量线程之间来回切换，整体反而更慢，严重时服务崩溃。

### 线程池怎么解决
- **复用**：线程执行完任务不销毁，回到池里等下一个任务，省去反复创建销毁的成本。
- **响应快**：池里有空闲线程时，任务一到就能马上开始执行。
- **控制并发**：线程数、排队任务数都有上限，资源占用可控。
- **功能丰富**：支持定时执行、周期执行等，用 `ScheduledThreadPoolExecutor` 就能做到。

### 两个典型场景
- 处理用户请求：Web 服务收到请求就交给池里的线程，避免每次请求都建线程。
- 处理批量任务：大量文件或数据要处理，丢进线程池，用有限的线程慢慢消化，不会把机器撑爆。

## 示例
```java
ExecutorService pool = Executors.newFixedThreadPool(4);
for (int i = 0; i < 100; i++) {
    pool.execute(() -> System.out.println(Thread.currentThread().getName()));
}
pool.shutdown(); // 100 个任务由 4 个线程轮流完成
```

## 易错点
- 以为线程越多越快；线程数超过 CPU 能并行的数量后，切换成本会拖慢整体
- 以为用了线程池就一定安全；队列无界或线程数无上限时同样会耗尽内存

## 追问
### [f1] 线程池里的线程做完任务后会销毁吗？
不会。线程回到池里，从队列取下一个任务继续执行。只有超过核心线程数的线程，空闲时间超过存活时间后才会被回收。
