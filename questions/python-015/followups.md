## 追问 1：为什么说循环引用在现代 Python 中并不一定会导致内存泄漏？

现代 Python 的分代垃圾回收器（gc 模块）能够自动追踪并打破容器间的循环引用。只有当发生循环引用的对象被全局作用域持续引用、或者由于复杂的 C 扩展底层引用计数没有对称归零时，才会导致 GC 无法回收的真实内存泄漏。

## 追问 2：在生产 Linux 服务器上观察到 Python 进程 RSS（物理常驻内存）持续不下降，一定是内存泄漏吗？

不一定。这很可能是 glibc 内存分配器的内存空洞碎片导致的。Python 释放对象后将内存还给 PyMalloc 内存池，PyMalloc 释放后还给 glibc 的 malloc 堆；但受限于 OS 分页对齐机制，如果一个内存页上还有一个未释放的小对象，整页内存就无法归还给操作系统内核。
