## 一句话
主从断线重连后，从节点带上主节点 ID 和自己的偏移量，主节点从复制积压缓冲区里把偏移量之后的命令补发给它，不用重做全量同步。

## 要点
- [kp1|3] 增量同步用在断线重连：只补发断线期间缺失的命令
- [kp2|3] 从节点重连时用 psync 带上主节点 ID 和复制偏移量
- [kp3|2] 主节点把近期写命令保存在复制积压缓冲区
- [kp4|2] 偏移量之后的命令还在缓冲区里，才能增量；否则退回全量
- [kp5] 缓冲区默认大小是 1MB，写入量大时可调大

## 详解
### 先搞懂：只补缺的那几页
新同学中途请了一会儿假，回来时只缺了这段时间的笔记。老师不用把整本笔记再复印一遍，只要告诉他「你上次抄到第几页，我从那页之后给你补」。前提是老师还留着这几页的草稿，如果草稿早就扔了，就只好重新复印整本。

增量同步就是这样：从节点记着自己复制到哪了，主节点留着最近的命令草稿。

后文用到的术语：

- **offset（复制偏移量）**：从节点已经复制到的数据位置。
- **replid（运行 ID）**：标识主节点身份的 ID。
- **复制积压缓冲区**：主节点保存最近写命令的一块固定大小的环形缓冲区。
- **repl-timeout**：主从之间多久没有通信，就认为连接已断。

### 流程
1. **断线**：主从之间网络出问题，超过 `repl-timeout` 时间，主节点认为从节点故障，中断复制连接。
2. **主节点继续工作**：断线期间主节点照常处理写命令，只是没法发给从节点，这些最近的写命令会保存在复制积压缓冲区里。
3. **重新连接**：网络恢复后，从节点重新连上主节点。
4. **发送 psync**：从节点把之前保存的主节点 ID 和自己的偏移量发送出去。
5. **主节点判断**：确认 ID 匹配，并检查从节点的偏移量之后的数据还在缓冲区里。
6. **补发命令**：主节点回复表示可以增量，并把偏移量之后的命令从缓冲区发给从节点，从节点执行后追平。

### 什么情况下增量失败
- 断线太久，缓冲区已经被新命令覆盖，偏移量之后的命令不全了，只能退回全量同步。
- 主节点 ID 和从节点记录的不一致，比如主节点换了，也不能增量。

### 怎么减少退回全量
缓冲区默认只有 1MB 左右，写入很频繁的实例，几秒就可能被覆盖。可以通过 `repl-backlog-size` 调大缓冲区，让更长时间的断线也能走增量。

## 易错点
- 以为增量同步是持续同步的命令传播；它指的是断线重连后补发缺失命令
- 以为缓冲区无限大；它是固定大小的环形缓冲区，旧命令会被覆盖
- 以为断线就一定全量；缓冲区足够时可以只补增量

## 追问
### [f1] 复制积压缓冲区是每个从节点一份吗？
不是。它由主节点维护一份，所有从节点共用，每个从节点靠自己的偏移量来判断要从哪里开始补发。
