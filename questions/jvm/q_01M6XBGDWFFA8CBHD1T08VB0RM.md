## 一句话
Java 有强、软、弱、虚四种引用：强引用只要还在就不回收，软引用在内存不足时回收，弱引用下一次 GC 就回收，虚引用拿不到对象、只用来在对象被回收后收到通知。

## 要点
- [kp1|3] 强引用：普通的 `new` 对象赋值，只要可达就不会被回收
- [kp2|3] 软引用 SoftReference：内存不足、快要 OOM 前才回收，适合做缓存
- [kp3|2] 弱引用 WeakReference：只被弱引用指向时，下一次 GC 就回收
- [kp4|2] 虚引用 PhantomReference：`get()` 总是返回 null，必须配合 ReferenceQueue
- [kp5] 软、弱、虚引用都在 `java.lang.ref` 包里

## 详解
### 先搞懂：对象和"抓住它的手"
对象就像气球，引用就像抓气球的手。强引用是死死攥着，不松手气球就不会飞走。软、弱引用是轻轻捏着一根线，需要的时候气球可以被收走。

后文用到的术语：
- **可达**：从 GC Roots 出发，沿着引用能找到这个对象。
- **GC 回收**：JVM 回收不再被强引用持有的对象所占的内存。
- **引用队列（ReferenceQueue）**：对象被回收后，JVM 把对应的引用对象放进这个队列，程序可以从中取出来做收尾。

### 强引用：最常见的引用
`Object o = new Object();` 里的 `o` 就是强引用。只要还有强引用能到达这个对象，GC 绝不会回收它，宁可抛出 OOM。

### 软引用：内存不够才回收
只被软引用指向的对象，在内存充足时保留，JVM 内存不足、快要抛 OOM 之前会回收它们。适合做对内存敏感的缓存：有空间就留着，没空间就让出来。

### 弱引用：下一次 GC 就回收
只被弱引用指向的对象，GC 一发现就会回收，不管内存是否充足。典型的使用有 `WeakHashMap`，以及 `ThreadLocal` 里的 key 是弱引用。

### 虚引用：只为收到通知
虚引用的 `get()` 永远返回 `null`，不能通过它拿到对象。它必须配合引用队列使用，对象被回收后，虚引用会进入队列，程序据此做清理工作，比如释放堆外内存。

### 方案对比：四种引用
| 引用类型 | 什么时候被回收 | 能否通过它拿到对象 | 典型用途 |
|---|---|---|---|
| 强引用 | 不可达时才回收 | 能 | 日常代码 |
| 软引用 | 内存不足时 | 能（未回收前） | 内存敏感缓存 |
| 弱引用 | 下一次 GC | 能（未回收前） | WeakHashMap、避免泄漏 |
| 虚引用 | 对象回收时通知 | 不能 | 回收后的收尾清理 |

结论：普通代码都用强引用；需要缓存才考虑软引用，需要"随用随丢"考虑弱引用，虚引用一般只在框架底层使用。

## 示例
```java
WeakReference<byte[]> ref = new WeakReference<>(new byte[1024]);
byte[] data = ref.get();   // 回收前能取到，回收后返回 null
if (data != null) {
    System.out.println("还在");
}
```

## 易错点
- 以为弱引用对象马上消失；它只在 GC 发生时才会被回收
- 对象同时还被强引用指向时，软引用和弱引用都不会让它被回收
- 以为通过虚引用能拿到对象；它的 `get()` 永远是 `null`

## 追问
### [f1] ThreadLocal 为什么用弱引用做 key？
key 是弱引用，ThreadLocal 对象在没有别的强引用时可以被回收，减少泄漏。但 value 仍是强引用，所以用完还要调用 `remove()`。

### [f2] 软引用和弱引用做缓存有什么区别？
软引用在内存不足时才回收，缓存保留得更久；弱引用在下一次 GC 就回收，缓存很快失效，所以缓存场景更常用软引用。
