## 一句话
Redis 集群里每个主节点都有从节点，主节点挂了会自动选从节点顶上，缓存不会整体失效，请求也就不会全部压到数据库。

## 要点
- [kp1|3] 单机 Redis 宕机，缓存全部失效，是雪崩的一大来源
- [kp2|3] 主从复制让从节点保存主节点数据的副本
- [kp3|2] 主节点故障时，从节点被提升为新主，服务继续可用
- [kp4|2] Cluster 把数据分片到多个主节点，一个节点故障只影响部分数据
- [kp5] 只提高可用性，不能防止大量 key 同时过期

## 详解
### 先搞懂：一个收银台坏了，整家超市就停吗
小超市只有一个收银台，收银员请假，超市就没法营业。大超市有很多收银台，还有备用收银员，一个人请假，其他人顶上就行。

单机 Redis 就像只有一个收银台：它一旦宕机，缓存数据全部不可用，所有请求都回源到数据库，雪崩就发生了。用集群，就是多配几个收银台和备用人手。

后文用到的术语：

- **主节点**：负责写入数据的 Redis 节点。
- **从节点**：从主节点复制数据的副本，主节点故障时可以顶替。
- **故障转移**：主节点挂了，自动把从节点提升为新的主节点。
- **分片**：把数据分散存放到多个节点。

### 主从加故障转移：挂一个，换一个
主节点会把数据复制给从节点，从节点手里有一份副本。有两种常见方式在主节点挂掉时自动换主：

- **哨兵**：独立的哨兵进程监控主节点，发现下线后投票，选一个从节点升为主节点。
- **Redis Cluster**：节点之间互相检测，主节点被多数节点认为故障后，它的从节点自动接替。

换主期间，写入可能有短暂中断，但数据没有整体丢失，缓存继续对外服务。

### 分片：把风险摊小
Redis Cluster 还会把数据按哈希槽分到多个主节点。即使某个主节点和它的从节点都出了问题，也只是它负责的那部分 key 受影响，其余数据照常命中缓存，数据库只需要应对一小部分回源请求。

### 要明白它能做什么、不能做什么
- 能做：避免因为单个节点宕机导致缓存整体不可用。
- 不能做：集群不会改变 TTL，如果一批 key 同一时间过期，它们照样一起失效。所以集群要和随机 TTL、限流降级配合使用。
- 主从复制是异步的，主节点挂掉时，少量还没复制出去的写入可能丢失。

## 易错点
- 以为上了集群就不会雪崩；大批 key 同时过期集群也防不住
- 以为主从切换是零中断；切换期间会有短暂不可用
- 以为从节点数据和主节点永远完全一致；复制是异步的

## 追问
### [f1] 哨兵和 Cluster 怎么选？
数据量不大、单机放得下，用主从加哨兵，结构简单。数据量大或需要横向扩展，用 Cluster，它自带分片和故障转移。
