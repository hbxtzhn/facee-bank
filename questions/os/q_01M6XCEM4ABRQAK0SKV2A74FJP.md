## 一句话
僵尸进程是已经退出、但父进程还没用 wait 回收它的子进程，它在进程表里还留着一条记录。

## 要点
- [kp1|3] 子进程已退出，父进程没有调用 wait 或 waitpid 回收
- [kp2|3] 它不再运行，只在进程表里留一条退出信息
- [kp3|2] 父进程调用 wait 后，这条记录才被释放
- [kp4|2] 大量僵尸进程会占满进程表，导致无法创建新进程
- [kp5] 父进程退出后，僵尸会交给 init 进程回收

## 详解
### 先搞懂：员工离职后的交接
员工离职，人已经走了，但他的档案还留在人事部，要等直属领导来签字确认才能销毁。如果领导一直不来签字，这份档案就一直留着。

进程也是这样：子进程退出后，操作系统要保留它的退出状态，等父进程来取。父进程一直不取，这条记录就一直留在系统里。

后文要用的术语：

- **进程表**：操作系统记录所有进程信息的表，容量有限。
- **`wait` / `waitpid`**：父进程用来获取子进程退出信息的系统调用。
- **进程描述符**：进程在系统中的记录，包含 PID、退出状态等。

### 僵尸进程是怎么产生的
1. 父进程创建了子进程；
2. 子进程执行完毕，退出；
3. 操作系统保留子进程的退出信息，等父进程来取；
4. 父进程没有调用 `wait` 或 `waitpid`，信息没人取，这条记录就留下来。

这时子进程已经不再运行，也不占 CPU 和大部分内存，它只是还占着进程表里的一个位置。

### 危害和处理
**危害**：进程表容量有限。僵尸进程积累太多，把表占满，系统就不能再创建新进程。

**处理方式**：

- 父进程在子进程退出后调用 `wait` 或 `waitpid`；
- 杀掉僵尸进程本身没有用，因为它已经死了；可以结束它的父进程，它就会被 init 进程接管并回收。

## 示例
```bash
# 在 ps 输出里，状态为 Z 的就是僵尸进程
ps aux | grep Z
```

## 易错点
- 把僵尸进程当成还在运行的进程；它已经结束，只剩一条记录
- 以为对僵尸进程执行 `kill` 就能清掉；要让父进程回收它，或结束父进程

## 追问
### [f1] 僵尸进程和孤儿进程有什么区别？
僵尸进程是子进程已死、父进程没回收；孤儿进程是父进程先退出、子进程还在运行，会被 init 进程收养。
