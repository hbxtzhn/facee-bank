## 一句话
每一层在数据前面加上自己的控制信息（首部），对方收到后再逐层拆掉，这样每一层都只看自己那一份信息就能完成工作。

## 要点
- [kp1|3] 首部里放的是这一层工作需要的控制信息，比如端口、地址
- [kp2|3] 发送方自上而下逐层加首部，接收方自下而上逐层拆首部
- [kp3|2] 典型顺序：TCP 首部、IP 首部、帧头（链路层）依次包在数据外面
- [kp4] 每层只认自己的首部，把后面的内容当作一整块数据

## 详解
### 先搞懂：寄快递一层层套包装
你寄一份文件：先装进文件袋，写上收件部门；再装进快递盒，贴上收件人地址；最后整个交给物流公司，物流公司又加上转运的运单。收件方到了以后，反过来一层层拆。每个环节只看自己那张单子，不用拆开里面的东西。

网络也是这样。后文的术语：

- **首部**：加在数据前面的控制信息，说明这份数据要怎么处理。
- **封装**：每一层给上层交下来的数据加上自己的首部。
- **解封装**：接收方逐层去掉对应的首部，把剩下的数据交给上层。

### 发送时怎么一层层包：以浏览器发请求为例
1. **应用层**：浏览器生成 HTTP 请求内容。
2. **传输层**：加上 TCP 首部，里面有源端口和目的端口，用来找到对方的哪个程序。
3. **网络层**：再加上 IP 首部，里面有源 IP 和目的 IP，用来在网络里选路。
4. **链路层**：最后加上帧头（有的还有帧尾），里面有源 MAC 和目的 MAC，用来在同一个局域网内传到下一跳。

最外面一层是帧头，变成电信号发出去。

### 为什么要这样做
- 每一层要完成自己的工作，都需要一些信息，而这些信息只有本层才懂：传输层要端口，网络层要 IP，链路层要 MAC。
- 把信息放进各自的首部，每一层只读写自己的首部，不碰其他层的内容，层与层才能互不干扰。
- 数据途中经过路由器时，路由器通常只拆到网络层，看 IP 首部决定往哪转发，不会去看里面的 TCP 和应用数据。

### 接收时怎么一层层拆
接收方从下往上：链路层检查帧头里的目的 MAC 是不是自己，去掉帧头；网络层看 IP 首部，确认是发给自己的，去掉 IP 首部；传输层根据 TCP 首部里的端口，把数据交给对应的程序；应用层得到完整的 HTTP 内容。

### 封装的代价
每多一层首部，就多占一些字节，所以真正传输的内容里有一部分是首部。这是分层要付出的代价，换来的是各层独立工作。

## 易错点
- 以为路由器会把每一层都拆开；路由器转发时通常只处理到网络层
- 以为首部只在发送端加一次；实际上每一层各自加一个，到接收端再各自拆掉
- 以为端口是 IP 首部里的信息；端口在传输层首部，IP 首部里放的是 IP 地址

## 追问
### [f1] 数据途中经过路由器，帧头会变吗？
会变。每经过一跳，链路层的帧头会重新生成，MAC 地址换成下一跳的。IP 首部里的源 IP 和目的 IP 一般保持不变。
