## 一句话
阻塞队列是一种线程安全的队列：队列空时取元素的线程会等，队列满时放元素的线程会等；线程池用它缓存还没来得及执行的任务，也让空闲线程不用空转。

## 要点
- [kp1|3] 阻塞队列在队列空时让取的线程等待，满时让放的线程等待
- [kp2|3] 线程池用它存放核心线程都忙时到来的任务
- [kp3|2] 空闲的工作线程在队列上等待，有任务就被唤醒，不会空转占 CPU
- [kp4] 阻塞队列本身是线程安全的，多线程存取无需自己加锁

## 详解
### 先搞懂：排队窗口和取餐口
想象一家小餐馆的出餐口：厨师做好的菜放在窗口，服务员来端。如果窗口没菜，服务员只能站着等；如果窗口摆满了，厨师就得停下来等位置。这个窗口，就是一个阻塞队列。

后文术语：

- **队列**：先进先出的存取结构，先放进去的先拿出来。
- **阻塞**：线程暂停执行，在原地等待某个条件满足，等待时不占 CPU。
- **线程安全**：多个线程同时存取不会出错。

### 阻塞队列的特点
Java 里的 `BlockingQueue` 接口提供了「等待」的存取方式：

- `take()`：队列空时一直等，直到有元素；
- `put()`：队列满时一直等，直到有空位；
- `poll(时间)`、`offer(元素, 时间)`：带超时的等待；
- `offer(元素)`：不等待，满了就直接返回 false。

而且这些操作都是线程安全的，生产者和消费者线程可以放心地并发使用。

### 线程池为什么要用它
线程池里，提交任务的线程是生产者，工作线程是消费者，中间需要一个缓冲区：

- **缓存任务**：核心线程都忙时，新任务先放进队列，不用马上扩容。
- **空闲线程不空转**：没有任务时，工作线程在队列上阻塞等待，不会一直循环检查浪费 CPU；一有任务，它们就被唤醒。
- **控制积压**：用有界队列，能限制排队的任务数量，满了就走拒绝策略。

提交任务时，线程池用的是不会等待的 `offer`，队列满了就返回失败，进而扩线程或拒绝，而不是卡住提交的线程。

## 示例
```java
BlockingQueue<String> queue = new ArrayBlockingQueue<>(2);
queue.put("a");
queue.put("b");
// 再 put 会阻塞，直到有线程 take
System.out.println(queue.take()); // a，先进先出
```

## 易错点
- 以为线程池提交任务时会因队列满而阻塞；提交走的是不等待的 `offer`
- 以为阻塞时线程在空转；阻塞线程会让出 CPU，不消耗 CPU
- 以为阻塞队列是无限的；`ArrayBlockingQueue` 有固定容量，其他有些实现才无界

## 追问
### [f1] 线程池的工作线程怎么从队列取任务？
工作线程循环调用队列的 `take()`（需要常驻时）或 `poll(keepAliveTime)`（允许超时回收时）取任务，取不到就阻塞等待，取到就执行。

### [f2] 为什么线程池推荐用有界队列？
无界队列可能让任务无限堆积，最终耗尽内存。有界队列满了就走拒绝策略，问题更早、更可控地暴露。
