## 一句话
按数据特点选：按时间增长、要平滑加表选范围路由，要数据均匀选 Hash 路由，分片键没规律或要灵活调整选配置路由。

## 要点
- [kp1|3] 范围路由实现简单、扩容平滑，但新数据会集中到最新的表
- [kp2|3] Hash 路由数据均匀，但范围查询要跨多张表
- [kp3|2] 配置路由最灵活，代价是多一张要维护的映射表
- [kp4] 选型先看分片键特点，再看最常见的查询方式

## 详解
### 先搞懂：三种路由其实是三种分拣方法
还是用快递分拣打比方。包裹要分到若干格口，有三种办法：

- 按邮编区间分：1 到 100 万放一号口，100 万到 200 万放二号口；
- 把邮编算一个数再除以格口数取余，余数是几就放几号口；
- 门口贴一张对照表，每个收件人该去几号口，查表为准。

这三种就对应范围路由、Hash 路由、配置路由。后文用到的术语：

- **分片键**：决定数据落到哪张表的字段。
- **数据倾斜**：有的表数据特别多，有的很少。
- **扩容**：增加分表数量来承载更多数据。

### 三种路由各自的特点
**范围路由：按区间划分。** 比如按订单创建时间，一个月一张表。新增表很容易，到了新的月份建一张新表就行，旧表不用动。缺点是最新的表被集中写入，旧表很少有人访问，容易出现倾斜。

**Hash 路由：算出来再取模。** 对分片键算哈希，再对表数取模。数据通常分得均匀，写入压力也分散。缺点是想查某个区间的数据时，满足条件的行散落在各张表里，只能每张表都查。另外表数改变后取模结果变了，要迁移数据。

**配置路由：查表决定。** 用一张配置表记录「哪个分片键值去哪张表」。想把某个大客户单独放一张表、想手动调整位置，都很方便。缺点是每次路由都要先读配置表，这张表本身要保证可靠，还要有人维护。

### 方案对比：三种路由怎么取舍
| 方案 | 数据分布 | 范围查询 | 扩容 | 额外成本 |
|---|---|---|---|---|
| 范围路由 | 容易倾斜到新表 | 方便，落在连续几张表 | 平滑，直接加新表 | 几乎没有 |
| Hash 路由 | 通常均匀 | 要跨多张表 | 改表数要迁移数据 | 几乎没有 |
| 配置路由 | 由配置决定 | 取决于怎么配 | 灵活，可手动调整 | 配置表要维护 |

结论：数据按时间增长、主要查区间时选范围路由；追求均匀、主要按分片键精确查时默认选 Hash 路由；分片键没规律或需要灵活调度时才用配置路由。

### 选型时可以问自己三个问题
1. 最常见的查询是按分片键精确查，还是查一个区间？精确查偏向 Hash，区间查偏向范围。
2. 数据是不是随时间不断增加、旧数据很少访问？是的话范围路由很自然。
3. 将来要不要频繁扩容或调整分布？要的话考虑配置路由，或提前多分一些表。

## 示例
```sql
-- 范围路由：按月份建表
CREATE TABLE order_202611 LIKE order_template;

-- Hash 路由：4 张表，user_id 取模
-- user_id % 4 = 2 -> order_2

-- 配置路由：路由表记录 user_id 去哪张表
CREATE TABLE route_config (
  user_id BIGINT PRIMARY KEY,
  table_name VARCHAR(32) NOT NULL
);
```

## 易错点
- 以为 Hash 路由一定最好；经常查区间时，它每次都要访问多张表
- 以为范围路由不会倾斜；写入集中在最新的区间，最新那张表压力最大
- 以为 Hash 路由随便加表；表数一变，原有数据的落点就变了，要做迁移
- 忽略配置表本身的可靠性；它一旦出问题，所有路由都会受影响

## 追问
### [f1] Hash 路由扩容时数据怎么迁移？
表数变了，取模结果就变了，大部分数据要搬家。常见做法是一开始就多分一些表，扩容时只是把整张表搬到新的库上，不改取模的底数。
