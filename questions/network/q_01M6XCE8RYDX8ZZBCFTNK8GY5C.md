## 一句话
接收窗口就是接收方缓冲区里还剩多少空位，随确认一起告诉发送方；窗口为 0 时发送方先暂停，并定时询问。

## 要点
- [kp1|3] 接收窗口等于接收方缓冲区剩余的可用字节数
- [kp2|3] 接收方在每个确认报文里带上当前的窗口值
- [kp3|2] 发送方发出但未被确认的数据量，不能超过这个窗口
- [kp4] 窗口为 0 时发送方暂停发送，定时发小报文探测

## 详解
### 先搞懂：餐厅门口的空位牌
饭店门口挂一块牌子，写着「还剩 5 个位子」。客人看到牌子，就知道现在能进多少人。店里有人吃完走了，牌子的数字就变大。

接收窗口就是这块牌子。发送方是客人，接收方是店里的座位。

后文用到的术语：

- **缓冲区**：接收方暂存收到数据的内存。
- **接收窗口**：缓冲区剩余的可用空间，单位是字节。
- **探测**：窗口为 0 时，发送方发出的询问小报文。

### 窗口怎么变
1. 数据到达接收方，先放进缓冲区，空位变少，窗口变小。
2. 应用把数据读走后，空位变多，窗口变大。
3. 接收方每次回 ACK，都把最新的窗口值写进首部。

发送方看到这个值，就知道自己最多还能发多少字节。

### 举个例子
接收窗口是 4000 字节。发送方发出 3000 字节后，在收到确认前，只能再发 1000 字节。接收方确认后，如果应用已经读走一部分，窗口又会增大，发送方才能接着发。

### 窗口为 0 的情况
缓冲区被塞满、应用又没来得及读，窗口就是 0。这时发送方暂停发送，并启动定时器，每隔一段时间发一个小报文询问。接收方回应的确认里带着最新窗口值，一旦大于 0，发送方就恢复发送。

### 进阶：窗口值的位置（基础薄弱可先跳过）
窗口值写在 TCP 首部的窗口字段里，随每个报文发送。窗口字段的长度有限，窗口很大时要靠窗口缩放选项来扩大表示范围。

## 易错点
- 以为接收窗口是缓冲区总大小；实际是当前还剩的空位
- 以为窗口是固定值；它随应用读取数据的快慢不断变化
- 以为窗口为 0 就是连接断了；只是暂停，连接仍然有效

## 追问
### [f1] 接收窗口和拥塞窗口是一回事吗？
不是。接收窗口由接收方给出，反映它的处理能力。拥塞窗口由发送方自己维护，反映网络状况。发送方实际能发的量取两者中较小的。
