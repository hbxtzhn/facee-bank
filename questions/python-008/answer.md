## 1. 三种复制方式的内存对比

```text
原始对象 A = [1, [2, 3]]

直接赋值:  B = A
  A ───┐
       ▼
     [ 1,  [2, 3] ]
       ▲
  B ───┘  (A 与 B 指向完全相同的内存地址，操作互相影响)

浅拷贝:    C = copy.copy(A)
  C ───> [ 1,  * ]  (顶层新建列表对象)
                │
                └───> [2, 3] <─── A 的子列表 (嵌套的子对象依然共享引用)

深拷贝:    D = copy.deepcopy(A)
  D ───> [ 1,  * ]  (顶层新建)
                │
                └───> [2, 3] (本例中的可变子列表被递归复制)
```

| 方式 | 语法/方法 | 顶层容器 | 嵌套的子对象 | 是否相互影响 |
|---|---|---|---|---|
| **直接赋值** | `b = a` | 共享相同引用 | 共享相同引用 | 修改任何元素均影响另一方 |
| **浅拷贝** | `copy.copy(a)`、`a[:]`、`a.copy()` | **新建对象** | 共享内部对象引用 | 修改第一层不影响，修改内部子列表相互影响 |
| **深拷贝** | `copy.deepcopy(a)` | 本例新建列表 | 通常递归复制可变对象；不可变对象、共享引用与自定义行为另论 | 本例修改列表互不影响；不保证所有资源都能复制 |

## 2. 深拷贝如何防止“自引用死循环”？

如果一个对象内部引用了自身：
```python
a = [1]
a.append(a)  # a 变成了自引用列表：[1, [...]]
```
如果不加防护直接递归调用 `deepcopy(a)`，会产生 `deepcopy -> deepcopy(a[1]) -> deepcopy(a[1][1])` 导致无限递归，最终抛出 `RecursionError: maximum recursion depth exceeded`。

### 底层机制：memo 字典
`copy.deepcopy(x, memo=None)` 内部维护了一个 **`memo` 哈希表**：
1. 每次准备拷贝一个对象前，先检查该对象的唯一标识 `id(x)` 是否在 `memo` 字典中；
2. 如果存在，说明该对象此前已经在当前拷贝链路中被访问过，**直接从 memo 中返回已经创建好的副本**，终止本次递归；
3. 如果不存在，先在内存中预分配一个新副本对象，将 `memo[id(x)] = copy_obj` 记录在案，然后再继续递归深拷贝它的子属性。

这套机制不仅完美杜绝了死循环，而且如果同一对象在深层被多次引用，深拷贝后也能保持相同的引用指向拓扑结构。
