一次用户请求可能先调用主模型，再调用备用模型。如果把整个请求消耗的 token 都算在最后回答的模型名下，就会低估主模型成本、夸大备用模型成本，也无法判断哪一层带来了额外开销。

群 Agent 的用量统计按每次尝试自己的提供方和模型汇总输入、输出及缓存相关用量。只有对应轮次摘要确实作为新记录插入后才累计，以降低同一轮重复写日志造成的重复计数。这里记录的是代码路径里可获得的使用数据，并非用户侧准确账单；其他功能或入口可能使用不同统计范围。

例如主模型先消耗了一部分输入并失败，备用模型再次读取上下文后成功回答。两次调用都可能产生用量；只记录成功的那次会低估整轮成本。相反，把两次都放到备用模型上，会让模型选型分析失真。
