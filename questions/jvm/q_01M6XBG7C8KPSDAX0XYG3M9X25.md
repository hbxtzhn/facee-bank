## 一句话
JIT 是 JVM 里的即时编译器：程序跑起来之后，它把经常执行的字节码编译成机器码缓存起来，以后直接运行机器码，速度更快。

## 要点
- [kp1|3] JIT 在程序运行时工作，不是在 javac 编译阶段
- [kp2|3] 它只编译被频繁执行的热点代码，其他代码仍然解释执行
- [kp3|2] 编译出的机器码会缓存起来，下次直接用，不用重复翻译
- [kp4] HotSpot 里有 C1 和 C2 两个 JIT 编译器，分别偏重编译速度和优化程度

## 详解
### 先搞懂：为什么字节码还需要再编译一次
Java 源码先被 `javac` 编译成**字节码**（`.class` 文件里的指令），字节码不是 CPU 能直接执行的指令。JVM 要运行它，最简单的办法是读一条、翻译一条、执行一条，这叫解释执行。

可以把它想成现场口译：每句话都要现翻，随时能开讲，但慢。如果同一段话要讲一万遍，更划算的做法是提前翻译好、写成稿子，之后直接照稿子念。JIT 就是那份「翻译好的稿子」。

后文用到的术语：

- **字节码**：javac 生成的、与具体 CPU 无关的指令。
- **机器码**：CPU 能直接执行的指令，和具体 CPU 类型有关。
- **热点代码**：被反复执行的方法或循环。

### JIT：边运行边找热点，编译后直接跑机器码
JIT 的工作过程是这样的：

1. 程序刚启动，字节码先由解释器执行，启动很快。
2. 虚拟机在运行中统计每个方法被调用了多少次、循环跑了多少圈。
3. 某段代码被执行得足够频繁，就被认定为热点，交给 JIT 编译成机器码。
4. 机器码放进内存里的代码缓存，之后再执行这段代码，直接跑机器码。

只编译热点，是因为编译本身要花时间和内存。只执行一两次的代码，编译的成本比省下的时间还多，不值得。

### HotSpot 里的两个编译器
HotSpot 虚拟机有两个 JIT 编译器：

- **C1**：编译得快，做的优化相对少，适合尽快让代码提速。
- **C2**：编译得慢，做的优化更深入，生成的机器码更快，用于最热的代码。

现在默认采用分层编译：代码先解释执行，变热后先交给 C1，继续变热再交给 C2。所以 Java 程序刚启动时偏慢，跑一阵子之后才会变快，这个阶段常被叫作「预热」。

## 易错点
- 以为 Java 是纯解释执行；HotSpot 是解释器加 JIT 配合工作
- 以为 JIT 会编译所有代码；它只编译热点代码
- 以为 javac 就是 JIT；javac 在运行前把源码编译成字节码，JIT 在运行中把字节码编译成机器码

## 追问
### [f1] 为什么 Java 程序刚启动时比较慢？
刚启动时代码都还没被编译，只能解释执行，同时虚拟机还在统计哪些是热点。等热点代码被编译成机器码后，速度才逐渐上来。
