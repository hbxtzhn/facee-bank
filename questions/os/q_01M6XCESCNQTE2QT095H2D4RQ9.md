## 一句话
死锁要同时满足四个条件：互斥、请求并持有、不可剥夺、循环等待；只要破坏其中任何一个，就不会死锁。

## 要点
- [kp1|3] 互斥：资源同一时刻只能被一个线程占用
- [kp2|3] 请求并持有：线程拿着已有资源，又去申请新的，等待时不放手
- [kp3|2] 不可剥夺：线程已拿到的资源，在用完前别人不能抢走
- [kp4|2] 循环等待：若干线程首尾相连，各自等着下一个手里的资源
- [kp5] 破坏任意一个条件就能避免死锁，常用方法是统一加锁顺序

## 详解
### 先搞懂：两个人互相等对方的筷子
甲拿着筷子等勺子，乙拿着勺子等筷子，两人都不肯放下手里的东西，于是都吃不上饭。这就是死锁。

代码里常见的是：线程 A 持有锁 1 再去拿锁 2，线程 B 持有锁 2 再去拿锁 1。

后文会用到几个词：

- **死锁**：一组线程互相等待对方手里的资源，谁也没法继续。
- **资源**：锁、文件、数据库连接等线程需要独占的东西。

### 四个条件逐个看
- **互斥**：资源一次只能一个线程用。别的线程来申请，只能等。
- **请求并持有**：线程已经拿着资源，又去申请别的，申请不到就停在那里，但手里的不放。
- **不可剥夺**：线程拿到的资源，只能自己用完释放，别人不能强行拿走。
- **循环等待**：线程 A 等 B，B 等 C，C 又等 A，形成一个圈。

### 为什么必须同时成立
前三个是死锁的基础环境：资源独占、占着不放、抢不走。第四个让等待连成了圈。少了任意一条，等待链就会断：要么有人能抢到资源，要么有人会放手，要么等待链不成环。

### 怎么破坏条件
| 破坏的条件 | 做法 |
|---|---|
| 请求并持有 | 一次性申请所有资源，或拿不到就先释放已有的 |
| 不可剥夺 | 申请不到时主动放弃手里的资源，或使用带超时的加锁 |
| 循环等待 | 给资源编号，所有线程按同一顺序加锁 |
| 互斥 | 通常难以破坏，因为资源本身需要独占 |

结论：实践中最常用的是统一加锁顺序，其次是用带超时的加锁。

## 示例
```java
// 两个线程都先拿 lockA 再拿 lockB，就不会形成环
synchronized (lockA) {
    synchronized (lockB) {
        // 访问共享数据
    }
}
```

## 易错点
- 以为满足部分条件就会死锁；四个条件必须全部同时成立
- 以为互斥可以随便去掉；去掉互斥意味着共享资源失去保护
- 以为锁嵌套一定死锁；只要加锁顺序一致，就不会成环

## 追问
### [f1] 怎么发现代码里发生了死锁？
Java 里可以用 `jstack` 导出线程栈，它会报告检测到的死锁和涉及的线程、锁。
