## 一句话
范围路由是按分片键的值区间分表，比如一个月一张表。实现简单、扩容平滑，缺点是新数据都往最新的表里写，容易倾斜。

## 要点
- [kp1|3] 范围路由按分片键值落在哪个区间决定存哪张表
- [kp2|3] 优点是实现简单，数据增长时直接加一张新表就行
- [kp3|2] 缺点是数据倾斜，写入集中在最新区间的那张表
- [kp4] 适合时间戳、订单号这类顺序增长的分片键
- [kp5] 区间查询方便，通常只落在连续的几张表

## 详解
### 先搞懂：像档案柜按年份分抽屉
公司的合同档案按年份放：2024 年的放一号抽屉，2025 年的放二号抽屉。找合同时，知道年份就知道开哪个抽屉；明年来了新合同，再添一个抽屉就好。

范围路由就是这个思路：分片键落在哪个区间，就存进对应的表。后文用到的术语：

- **分片键**：决定数据落到哪张表的字段。
- **区间**：给每张表划定的取值范围，比如某个月份。
- **数据倾斜**：有的表数据特别多，有的很少。

### 它怎么工作
以订单按创建时间分表为例：

- 11 月的订单存 `order_202611`；
- 12 月的订单存 `order_202612`。

写入时看创建时间属于哪个月，就写进哪张表。查询时如果带着时间范围，比如「最近三天」，只需要查对应的一两张表。

### 优点：简单，扩容平滑
- **实现简单**：路由就是一个区间判断，不用做复杂计算。
- **扩容平滑**：数据增长了，建一张新表接着用，已有的表和数据完全不用搬动。
- **区间查询方便**：同一个区间的数据挨在一起，查连续范围时不用扫描全部分表。

### 缺点：新表压力大，旧表很清闲
- **数据倾斜**：写入集中在当前区间的那张表，最新的表又热又大，旧表几乎没有访问。
- **热点问题**：如果某个区间的业务量特别大，比如大促当天，那张表会格外繁忙。
- **区间要预先规划**：如果区间划得太大，单表仍然会过大；划得太小，表又会很多。

### 适合什么场景
分片键是时间戳、自增订单号这类顺序增长的字段，并且查询经常带范围条件，这时用范围路由比较合适。如果最关心的是数据和写入都均匀，通常考虑 Hash 路由。

## 示例
```sql
-- 按月份分表，路由规则是订单的 create_time 落在哪个月
CREATE TABLE order_202611 LIKE order_template;
CREATE TABLE order_202612 LIKE order_template;

-- 11 月的订单写入 11 月的表
INSERT INTO order_202611 (order_id, create_time, amount)
VALUES (1001, '2026-11-08 10:00:00', 99.00);
```

## 易错点
- 以为范围路由数据一定均匀；实际写入集中在最新区间，容易倾斜
- 以为区间划好就不用再管；业务增长后要及时建新表，否则写入会失败
- 把热点和数据量混为一谈；旧表数据多但很少访问，新表数据少但压力最大

## 追问
### [f1] 范围路由怎么缓解最新表的写入压力？
可以把区间划得更细，或者在范围路由的基础上再按 Hash 分一层，把同一时间段的数据打散到几张表里。
