## 一句话
节点流是直接连着数据源或目的地的流，比如直接读写文件的 FileInputStream，它负责真正的数据读写。

## 要点
- [kp1|3] 节点流直接与数据源或目的地相连
- [kp2|3] 数据真正的读写由节点流完成
- [kp3|2] 常见的有 FileInputStream、FileOutputStream、FileReader、FileWriter
- [kp4|2] 内存数组对应的 ByteArrayInputStream 也是节点流
- [kp5] 处理流要包装在节点流外面，功能由处理流增强

## 详解
### 先搞懂：水管直接接水源
做项目时读一个文件，需要有个“东西”真的连到那个文件上，才能把数据读出来。这个直接连着文件、网络或内存的流，就是节点流。

打个比方：节点流就像直接插进水井的那根水管，它是水的真正入口。如果想要过滤、加压，就要在这根水管外面再接别的设备，那些设备就是处理流。

后文用到的词：

- **数据源**：数据的来源，如文件。
- **目的地**：数据最终写到的地方，如文件。
- **处理流**：包装在已有流外面的流，另一道题讲。

### 节点流连接什么
常见的数据源和目的地：

- 文件：`FileInputStream`、`FileOutputStream`、`FileReader`、`FileWriter`；
- 内存中的字节数组：`ByteArrayInputStream`、`ByteArrayOutputStream`；
- 内存中的字符数组或字符串：`CharArrayReader`、`StringReader`；
- 网络连接的流，通常从套接字中取得。

### 节点流能做什么、不能做什么
节点流负责最基础的事：打开连接，读或写字节、字符。它的功能比较单一，比如 `FileInputStream` 一次只能读字节，不能读一整行，也没有缓冲。

要想读得更方便、更快，就要在节点流外面包上处理流，比如 `BufferedReader`、`BufferedInputStream`。

### 怎么区分节点流和处理流
一个简单的办法：看构造器的参数。创建时传的是文件名或文件路径的，是节点流；传的是另一个流的，是处理流。

## 示例
```java
// FileInputStream 直接对接文件，是节点流
try (var in = new java.io.FileInputStream("a.txt")) {
    System.out.println(in.read());
}
// ByteArrayInputStream 直接对接内存里的字节数组，也是节点流
var mem = new java.io.ByteArrayInputStream(new byte[]{1, 2, 3});
```

## 易错点
- 以为所有流都能直接创建；处理流需要传入另一个流
- 以为节点流只能连接文件；它也可以连接内存数组、网络
- 以为节点流功能很强；它只做基础读写，缓冲等功能靠处理流
- 以为按“字节还是字符”划分的就是节点和处理；它们是两个不同的划分角度

## 追问
### [f1] 节点流和处理流是什么关系？
处理流包装在节点流外面，读写时数据先经过处理流，再到节点流。处理流提供缓冲、转换等增强功能，真正的 IO 仍由节点流完成。
