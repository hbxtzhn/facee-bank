## 一句话
Cookie 是服务器下发、保存在浏览器里的一小段文本，之后每次访问同一网站，浏览器都会自动带上它。

## 要点
- [kp1|3] Cookie 由服务器通过响应头设置，保存在浏览器端
- [kp2|3] 浏览器之后访问同一网站时，会在请求头里自动带上它
- [kp3|2] 服务器靠它识别用户身份和状态，如登录、偏好设置
- [kp4] Cookie 存在客户端，容量小，用户可以查看和修改

## 详解
### 先搞懂：会员卡
你去一家店办了张会员卡，店员把你的会员号记在卡上。之后你每次进店，出示会员卡，店员就知道你是谁，不用重新问。卡由你保管，随身带着。

Cookie 就是网站发给浏览器的会员卡。几个词：

- **Cookie**：服务器让浏览器保存的一小段文本数据。
- **响应头 Set-Cookie**：服务器用它告诉浏览器“请保存这个 Cookie”。
- **请求头 Cookie**：浏览器用它把保存的 Cookie 回传给服务器。

### Cookie 是怎么工作的
1. 你第一次访问网站，服务器在响应里加上 `Set-Cookie`，内容形如 `name=value`；
2. 浏览器收到后，把它保存起来；
3. 你下次访问同一个网站，浏览器自动在请求里带上这个 Cookie；
4. 服务器读到它，就能认出你，或者读取你的偏好设置。

### 为什么需要它
HTTP 是无状态的，服务器不会记得你是谁。有了 Cookie，服务器就能借浏览器的存储，在多次请求之间保持联系，例如保持登录、记住语言选择、记录购物车。

### 常见属性
- **过期时间**：可以设置保存多久，不设置时通常随浏览器关闭而消失；
- **作用域**：限定哪些域名、路径下会带上它；
- **安全相关属性**：例如只允许通过 HTTPS 传输，或者不允许脚本读取，用来降低泄漏的风险。

### 要注意什么
Cookie 保存在用户的浏览器里，用户能看到，也能修改，所以不要把密码、敏感信息直接放在里面。它的容量也有限，不适合存大量数据。

## 示例
```bash
# 服务器的响应头：让浏览器保存 Cookie
Set-Cookie: sid=abc123; Max-Age=3600; HttpOnly; Secure

# 之后浏览器的请求头：自动带上
Cookie: sid=abc123
```

## 易错点
- 以为 Cookie 保存在服务器上；它保存在浏览器端
- 以为 Cookie 里可以放密码；用户能看到和修改，不应放敏感信息
- 以为所有网站共享 Cookie；浏览器按域名分别保存和发送

## 追问
### [f1] Cookie 和 Session 是什么关系？
Cookie 保存在浏览器，Session 保存在服务器。常见做法是 Session 的编号放在 Cookie 里，浏览器带着编号，服务器据此找回 Session。
