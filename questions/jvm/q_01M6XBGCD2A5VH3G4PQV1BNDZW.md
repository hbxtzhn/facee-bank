## 一句话
串行收集器只用一个 GC 线程回收垃圾，回收期间暂停所有业务线程；新生代用标记-复制算法，老年代用标记-整理算法。

## 要点
- [kp1|3] 只有一个 GC 线程干活，回收时所有业务线程暂停（STW）
- [kp2|3] 新生代用标记-复制，老年代用标记-整理
- [kp3|2] 实现简单、额外开销小，适合小堆、单核或客户端类程序
- [kp4] 用 `-XX:+UseSerialGC` 开启

## 详解
### 先搞懂：一个人收拾整个房间
串行收集器就像家里只有一个人打扫卫生：打扫时全家人都得先停下手里的事，等他扫完才能继续。人少、房子小的时候，这样最省事，也不用互相协调。

后文用到的术语：
- **新生代**：刚创建的对象先放在这里，大部分很快就会变成垃圾。
- **老年代**：在新生代熬过多次回收的对象搬到这里。
- **标记-复制**：把还活着的对象复制到另一块空区域，原区域整块清空。
- **标记-整理**：把活着的对象往一端挪紧凑，再清掉边界外的空间。

### 串行：单线程，全程 STW
回收时只有一个 GC 线程在工作，业务线程全部暂停，直到回收结束。线程之间不需要协调，实现简单，运行时额外占用的资源也少。

代价是堆越大，单线程回收一次越慢，业务暂停的时间也越长。

### 新生代和老年代用不同算法
- **新生代用标记-复制**：新生代里大部分对象都是垃圾，活下来的很少，复制活对象的成本很低，回收完整块清空，也没有碎片。
- **老年代用标记-整理**：老年代里对象大多存活，复制成本太高；整理则把存活对象挪到一起，避免碎片。

老年代对应的收集器通常叫 Serial Old。

### 什么时候用
适合内存不大、CPU 核数少的环境，比如小型命令行工具或客户端程序。需要低延迟的线上服务通常不会选它，因为停顿会随堆变大而变长。

## 示例
```bash
java -XX:+UseSerialGC -Xmx256m -jar app.jar
```

## 易错点
- 以为"串行"是说新生代、老年代轮流回收；它指的是只有一个 GC 线程
- 以为老年代也用复制算法；老年代用的是标记-整理

## 追问
### [f1] 串行收集器和并行收集器的区别是什么？
回收算法基本一致，区别是并行收集器用多个 GC 线程一起回收，所以在多核机器上暂停时间更短；两者回收期间都会暂停业务线程。
