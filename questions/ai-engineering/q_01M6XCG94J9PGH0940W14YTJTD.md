## 一句话
Agent 是以大模型为大脑，能规划、记忆、调用工具，并不断循环直到把任务做完的软件系统，不是一问一答的聊天机器人。

## 要点
- [kp1|3] Agent 可以概括为 LLM 加规划、记忆和工具
- [kp2|3] 它会感知环境、做决策、执行动作，循环直到任务完成
- [kp3|2] 聊天机器人答完就结束，Agent 会根据结果继续行动
- [kp4] 工具让它能查数据、调接口、执行代码，影响外部世界

## 详解
### 先搞懂：聊天机器人是顾问，Agent 是助理
你问顾问「帮我订明天去上海的票怎么订」，他告诉你步骤，事情还是你自己做。你对助理说「帮我订明天去上海的票」，他会查车次、比价格、下单，遇到没票再换方案，最后告诉你结果。

Agent 就是后者：它不只回答，还会动手做事，并且根据每一步的结果决定下一步。

后文用到的术语：
- **LLM**：大语言模型，负责理解和决策。
- **规划**：把大目标拆成可执行的小步骤。
- **记忆**：保存对话和过程中的信息。
- **工具**：模型可以调用的外部能力，如搜索、数据库查询、代码执行。

### 四个组成部分
- **LLM** 是大脑，负责理解任务、决定下一步。
- **规划**让它能把复杂任务拆开，一步步推进。
- **记忆**让它记得做过什么、用户有什么偏好。
- **工具**让它能真正操作外部系统，而不只是生成文字。

### 它怎么运行：感知、决策、执行的循环
1. 观察当前情况，比如用户需求和已有结果；
2. 模型判断下一步该做什么；
3. 调用工具执行；
4. 把工具结果放回上下文，回到第 1 步。

直到任务完成或触发停止条件才结束。这个循环是 Agent 和普通聊天最大的区别。

### 对比：聊天机器人和 Agent
| 对比点 | 聊天机器人 | Agent |
|---|---|---|
| 交互方式 | 一问一答 | 多步循环 |
| 能否用工具 | 通常不能 | 可以 |
| 谁推进任务 | 用户 | 模型自己推进 |

结论：只需要问答时用聊天；任务需要多步操作、依赖外部系统时才用 Agent。

## 示例
```python
messages = [user_task]
while True:
    reply = llm(messages, tools)
    if reply.is_final:               # 模型认为任务完成
        break
    result = run_tool(reply.tool_call)
    messages.append(result)          # 工具结果放回上下文
```

## 易错点
- 以为接了大模型的聊天窗口就是 Agent；没有工具和循环的只是聊天
- 以为 Agent 一定更好；简单问答用它会更慢、更贵、更难控制
- 以为 Agent 不会出错；它可能选错工具或陷入循环，需要停止条件

## 追问
### [f1] Agent 为什么需要停止条件？
模型可能一直调用工具却无法完成任务，造成无限循环和高额消耗。常见做法是设置最大轮次，或在模型给出最终答案时结束。

### [f2] Agent 和工作流有什么区别？
工作流的步骤由人事先定好，Agent 的步骤由模型运行时自己决定。前者更可控，后者更灵活。
