## 一句话
进程调度是操作系统从就绪的进程里挑出下一个占用 CPU 的进程，决定 CPU 时间怎么分配。

## 要点
- [kp1|3] 调度的对象是就绪状态的进程，也就是等着用 CPU 的进程
- [kp2|3] 调度程序决定下一个谁用 CPU、用多久
- [kp3|2] 常见算法：先来先服务、短作业优先、优先级调度、时间片轮转
- [kp4] 不同算法在公平、响应快慢和等待时间之间取舍

## 详解
### 先搞懂：窗口排队
银行只开一个窗口，大厅里坐满了等着办业务的客户。谁先办，办多久，要有一个规矩，不然就会吵起来。这个排班规矩，就是调度。

CPU 就是那个窗口，就绪的进程就是排队的客户，负责叫号的就是调度程序。

后文要用的术语：

- **就绪进程**：已经准备好，只差 CPU 的进程。
- **调度程序**：操作系统里决定下一个运行谁的部分。
- **调度算法**：挑选规则。

### 调度做什么
单个 CPU 核同一时刻只能运行一个进程，而系统里常常有很多进程想运行。调度程序要做的就是：

1. 从就绪的进程里选出一个；
2. 让它占用 CPU 运行；
3. 运行结束、时间片用完或要等待事件时，再选下一个。

### 常见的调度算法
- **先来先服务**：谁先到谁先用，简单；
- **短作业优先**：优先运行预计时间短的，平均等待时间短；
- **优先级调度**：优先级高的先运行；
- **时间片轮转**：每个进程轮流使用一小段时间，适合交互式系统。

不同算法关注的目标不同：有的追求公平，有的追求响应快，有的追求完成得多。没有一种算法在所有方面都最好。

## 易错点
- 以为调度的对象是所有进程；它只在就绪的进程中选，阻塞的进程在等事件，不在候选之内
- 以为存在最好的调度算法；每种算法都有取舍

## 追问
### [f1] 调度发生在什么时候？
常见时机有：进程运行结束、进程阻塞等待事件、时间片用完、有更高优先级的进程变为就绪。
