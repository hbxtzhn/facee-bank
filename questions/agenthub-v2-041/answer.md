并发问题不一定需要两个 CPU 线程才会出现。两个异步请求可以先后读到同一个旧值，然后分别根据旧值写入；如果写入没有约束，两者都可能认为自己成功。应用层“先查询，再决定，再更新”之间存在可交错的时间。

项目 SQL 抽象的设计建议把条件放进数据库语句，例如 `UPDATE ... WHERE used=0`，再检查实际更改的行数。第一个请求把状态从未使用变为已使用后，第二个请求的条件不再成立，影响行数为零。也可以通过唯一索引让重复插入被数据库拒绝。这些手段把关键条件交给数据库执行，减少检查与写入分离造成的竞态。

这个模式仍需针对真实业务设计。例如重试时要区分“这次请求之前已经成功”和“被另一个请求占用”；条件更新只证明满足了当前语句的条件，不自动生成完整业务幂等协议。
