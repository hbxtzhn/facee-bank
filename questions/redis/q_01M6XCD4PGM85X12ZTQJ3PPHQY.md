## 一句话
缓存雪崩是大量缓存 key 在同一时间失效，或者缓存服务整个宕机，请求一下子全部落到数据库上，把数据库压垮。

## 要点
- [kp1|3] 雪崩指大量请求同时越过缓存，直接访问数据库
- [kp2|3] 两种常见原因：大批 key 同时过期，或 Redis 整体宕机
- [kp3|2] 和击穿的区别：击穿是一个热点 key，雪崩是一大批 key
- [kp4] 常见对策：过期时间加随机值、Redis 集群、限流降级、多级缓存

## 详解
### 先搞懂：缓存是数据库的挡箭牌
做项目时，我们把常用数据放进 Redis，大部分请求读缓存就返回了，数据库只处理少量请求。数据库的能力是有限的，它能扛住的是「少量请求」，扛不住「全部请求」。

打个比方：景区门口有个咨询台（缓存），游客问路都在这里解决，只有少数疑难问题才找经理（数据库）。如果咨询台的人同时下班，所有游客一起涌向经理办公室，经理就被淹没了。

后文用到的术语：

- **回源**：缓存里没有，转去数据库查。
- **TTL**：key 的存活时间，到点过期。
- **宕机**：服务器或进程挂掉，不能响应请求。

### 雪崩的两种成因
1. **大批 key 同时过期**：比如活动前用同一个 TTL 一次性导入了一批数据，到点后这些 key 一起失效，请求一起回源。
2. **缓存服务宕机**：Redis 单点挂了或整个集群不可用，所有读请求都没有缓存可用，全部打到数据库。

数据库被压垮之后，依赖它的服务一起变慢甚至挂掉，故障会一层层扩散，所以叫「雪崩」。

### 三个容易混淆的概念
- **穿透**：查的数据缓存和数据库里都没有，请求每次都落到数据库。
- **击穿**：一个热点 key 过期，同时来了大量请求。
- **雪崩**：一大批 key 同时过期，或缓存整体不可用。

### 怎么预防
- 给不同 key 的 TTL 加随机值，让它们分散过期。
- 用 Redis 主从加哨兵或集群，避免单点故障。
- 在入口做限流、降级，超出能力的请求不放进数据库。
- 加一层本地缓存，形成多级缓存。

各方案的细节在后面的题目里分别展开。

## 易错点
- 把雪崩和击穿混为一谈；击穿是单个热点 key，雪崩是大量 key 或整个缓存
- 以为只有过期会导致雪崩；缓存服务宕机同样会
- 以为只靠缓存就够；数据库自身也要有限流等保护

## 追问
### [f1] 雪崩和击穿怎么区分？
看范围：一个热点 key 过期是击穿，一大批 key 同时过期或缓存整体宕机是雪崩。击穿用互斥锁或逻辑过期，雪崩用随机 TTL、集群和限流降级。
