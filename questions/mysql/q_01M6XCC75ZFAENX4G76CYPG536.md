## 一句话
Server 层负责接收连接、解析 SQL、优化和执行；存储引擎层只负责数据的存取。两层通过统一的接口交互，所以引擎可以更换。

## 要点
- [kp1|3] Server 层包括连接器、解析器、优化器、执行器
- [kp2|3] 存储引擎层负责数据的存储和读取，如 InnoDB、MyISAM
- [kp3|2] 两层通过引擎接口交互，同一个库里不同表可以用不同引擎
- [kp4] 内置函数、存储过程、视图等跨引擎的功能，在 Server 层实现

## 详解
### 先搞懂：前台和仓库
去一家快递站取件：前台负责听你说要什么、核对身份、决定怎么找最快；仓库只管按指令把货找出来或放进去。

MySQL 也是这样分成两层。你发来的 SQL 先到 Server 层，由它决定怎么做；真正读写数据，由存储引擎层完成。

后文用到的术语：

- **连接器**：管理连接、验证账号和权限；
- **解析器**：检查 SQL 写得对不对，理解它的意思；
- **优化器**：决定用哪个索引、按什么顺序查；
- **执行器**：按优化器定好的方案，调用引擎的接口去取数据。

### Server 层：想清楚怎么做
Server 层不直接碰数据文件，它做的是「处理请求」这部分：

- 接收客户端连接，检查权限；
- 解析 SQL，选出执行方案；
- 执行器按方案调用引擎接口，拿到数据后整理结果返回；
- 内置函数、存储过程、视图这类和具体引擎无关的功能，也在这一层。

### 存储引擎层：只管存和取
这一层负责数据在磁盘和内存里怎么放、怎么按条件读出来。InnoDB、MyISAM、Memory 都在这一层。

### 为什么要分两层
引擎和 Server 层之间有统一的接口，所以引擎可以像插件一样替换：建表时用 `ENGINE=` 指定即可，上层的 SQL 写法不变。

## 易错点
- 以为 MySQL 的各个功能都由存储引擎实现；解析、优化、执行这些其实是 Server 层的事
- 以为换了存储引擎，SQL 就要重写；两层之间有统一接口，SQL 写法不变，只是引擎能力不同
- 把 binlog 当成引擎自己的日志；它由 Server 层写，所有引擎都有

## 追问
### [f1] 事务是 Server 层还是引擎层实现的？
是引擎层。InnoDB 支持事务，MyISAM 不支持，说明事务能力由具体引擎提供，不在 Server 层。

### [f2] 优化器做什么？
它在多种可行的执行方案里挑一个认为代价较小的，比如决定用哪个索引、多表连接时先查哪张表。
