# AgentHub 项目快速理解

这份资料帮助你在刷题前先建立项目全貌。文中按已阅读的项目路径解释设计；具体上线配置和个人分工需要你结合自己的经历确认。例子是用于学习的假设，不是宣称发生过的故障。

## 这个项目解决什么问题

群聊里经常出现值得复用的技术问答，但信息散落在大量消息中；读者以后再遇到相同问题，很难找到当时讨论的结论。平台把群问答、可控的智能体工具、知识整理与网页检索连接起来：用户可以在群里或网页提出问题，符合公开条件的内容经过处理后可作为知识来源被再次查找。

最重要的是区分几种不同的“内容”：群聊原始记录、当前会话中供模型参考的记忆、群内私有知识、经过审核的公开问答和整理后的知识条目。它们的读写范围和公开资格不一样，不能统称为一个大家都能访问的数据库。

## 一轮回答怎样运行

可以先记住下面的概念流程，再通过题目了解各入口的差异：

```text
用户提问 → 入口识别身份与会话范围 → 准备上下文和可用工具
        → 模型生成 / 请求工具 → 宿主执行并返回结果 → 生成回答
        → 检查当前轮是否仍有效 → 发送并记录确认状态

符合来源与审核规则的内容 → 整理为知识 → 按访问范围检索与引用
```

这不是所有入口的逐行调用图。网页路径会在回答前主动检索已发布资料；群路径按本群角色、数据范围和可用绑定构造工具。一次聊天也不会自动成为公开知识，还要通过来源资格和审核。

## 四个最值得深入理解的环节

**模型容错。** 模型可能在调用工具后失败。如果工具做过写入或开始发送消息，换一个模型重新执行可能重复操作。系统记录工具副作用与执行状态，只有满足安全重放和预算等条件时才考虑备用。记住：超时不等于远端没有执行，发送后没有 ACK 也不等于消息没有送达。

**网页前置检索。** 模型不一定主动调用检索工具，因此网页宿主先按访问范围搜索已发布条目和问答，再把合适的来源作为数据提供给模型。边缘路径使用 FTS5 trigram 词面检索；短词、同义表达和无命中的局限需要单独解释。检索到了资料，不等于资料一定正确或模型一定引用了它。

**权限与记忆。** 群、用户和入口共同决定当前数据范围。群管理员能操作本群，不代表能操作其他群；模型生成的参数和用户文本也不能自行证明身份。使用本群私有资料后，回答可能携带私有标记，供后续审核和公开链路识别。

**记录与回归。** 排查要分别看输入是否被接收、主备模型是否实际调用、工具是否开始和结束、回答是否获得发送确认。离线回归用模拟模型、发送端和时间推进去构造重复事件、失败、超时与权限边界。测试覆盖了什么、有没有实际运行，以及线上是否开启对应记录，都要分开说。

## 从一次例子串起全链路

假设群友询问一项技术方案。系统先确定群和提问者，给本轮提供允许使用的工具。如果查询命中本群内部笔记，结果会受到私有来源约束。模型生成回答时，如果调用的都是已完成且成功的只读工具，模型故障后仍需要检查时间等条件，才可能尝试备用；如果已经开始写入或发送，则不能简单重跑。回答生成后，交付还要等待平台确认。即便用户看到了答案，也不代表该轮可以自动进入公开知识，需要按来源资格和审核规则判断。

换成网页访客时，系统应先按访客可见范围准备公开来源；不能因为同一个主题存在群内笔记，就把群笔记注入访客对话。搜索没有命中也不等于知识库里一定没有答案，可能是选词、短词限制或权限范围造成。

## 建议怎么刷

先读题 1–6 建立主线，再依次学习工具容错、检索、权限和交付。第二遍不要看答案，自己画出一次提问从接收、模型、工具到发送的过程，标出会产生副作用或涉及权限的节点。第三遍练每题追问，遇到“项目是否已经上线”“是不是自己完成”“有没有提升百分比”，只说自己能证明的事实。
