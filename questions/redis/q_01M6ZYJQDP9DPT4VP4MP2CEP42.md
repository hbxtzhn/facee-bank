## 一句话
Redis 快，主要因为数据放在内存里，命令用单线程执行省去锁和切换，再用 I/O 多路复用让一个线程同时服务大量连接。

## 要点
- [kp1|3] 数据放在内存，读写不用等磁盘，这是快的根本原因
- [kp2|3] 命令执行是单线程，没有线程切换，也不用加锁
- [kp3|2] I/O 多路复用让一个线程监听很多连接，哪个有数据就处理哪个
- [kp4] 高效的数据结构（如哈希表、跳表）让单个操作本身很快
- [kp5] Redis 6.0 起可选用多线程读写网络数据，命令执行仍是单线程

## 详解
### 先搞懂：一个收银员为什么能服务一整条街
想象便利店只有一个收银员，但他很快。东西都摆在手边，不用跑仓库。一次只结一个人的账，不用和同事抢收银机。谁排到了就结谁，不会傻等某个顾客翻钱包。Redis 就是这个收银员。

后文会用到几个词：
- **磁盘 I/O**：读写硬盘，比读写内存慢很多。
- **上下文切换**：CPU 从一个线程换到另一个线程干活，换的时候要保存和恢复现场，有成本。
- **锁竞争**：多个线程抢着改同一份数据，要排队等锁。
- **I/O 多路复用**：一个线程同时盯着很多网络连接，哪个连接有数据来了，操作系统就通知它。

### 纯内存：不用等磁盘
Redis 的数据放在内存里，读写直接访问内存。内存比硬盘快得多，这是 Redis 快的根本原因。

持久化（RDB、AOF）虽然会写磁盘，但那是后台附加的事情，不在每次读写的路径上。

### 单线程执行命令：没有锁，也没有切换
Redis 用一个线程依次执行客户端发来的命令，任意时刻只有一条命令在跑。这样有两个好处：

- 不用在线程之间切换，省掉切换的成本；
- 数据不会被两个线程同时改，所以不需要加锁，也没有锁竞争。

代价是任何一条慢命令都会让后面的命令排队。所以要避免在生产环境用耗时很长的命令，比如对大集合执行全量遍历。

### I/O 多路复用：一个线程管很多连接
如果每个连接都阻塞等数据，单线程早就卡死了。

Redis 用操作系统提供的多路复用机制（Linux 上是 epoll）。线程只问一句“哪些连接有数据了”，然后只处理这些连接。没数据的连接不占用它的时间。网络读写也是非阻塞的，不会因为某个客户端慢而卡住别人。

### 进阶：Redis 真的只有一个线程吗（基础薄弱可先跳过）
- “单线程”指的是执行命令的主线程。Redis 进程里还有后台线程，用来做关闭文件、异步释放内存（惰性删除）等耗时操作。
- Redis 6.0 起，可以通过 `io-threads` 配置开启多线程读写网络数据，默认不开启。命令的执行依然是主线程串行完成。
- 为什么要加网络多线程：命令本身在内存里执行很快，网络读写在高并发下反而成为瓶颈。

## 易错点
- 以为 Redis 整个进程只有一个线程；实际上有后台线程，6.0 起还可以开网络 I/O 线程
- 以为单线程一定比多线程慢；Redis 的瓶颈主要在内存和网络，不在 CPU。单线程反而省去锁的成本
- 以为快只是因为单线程；内存存储和多路复用同样关键

## 追问
### [f1] 单线程怎么利用多核 CPU？
单个 Redis 实例只用一个核来执行命令。想利用多核，可以在一台机器上起多个实例，或者用集群把数据分片到多个节点。

### [f2] 为什么 Redis 6.0 要引入多线程？
单线程执行命令不是瓶颈，网络读写才是，高并发时大量时间花在收发数据上。6.0 把网络读写交给多个 I/O 线程，命令执行仍由主线程完成，所以仍然不需要给数据加锁。
