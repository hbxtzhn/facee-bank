## 一句话
JVM 由三大部分组成：类加载器把 class 文件读入内存，运行时数据区存放程序运行时的数据，执行引擎负责执行字节码。

## 要点
- [kp1|3] 类加载器：从文件系统、网络等来源读取 class 文件，加载进内存
- [kp2|3] 运行时数据区：方法区、堆、栈、程序计数器、本地方法栈
- [kp3|2] 执行引擎：执行字节码，包括解释执行和即时编译（JIT）
- [kp4|2] 堆和方法区由线程共享，栈、程序计数器、本地方法栈是线程私有
- [kp5] 垃圾回收主要作用在堆上

## 详解
### 先搞懂：一家工厂
把 JVM 想成一家工厂：
- 原料仓库入口（类加载器）：把原料（class 文件）运进来；
- 厂房和货架（运行时数据区）：放原料、半成品、工具；
- 流水线工人（执行引擎）：真正按图纸干活，执行字节码。

做项目时，你写的 Java 代码编译成 class 文件，交给 JVM 运行，这三部分就依次工作。

后文术语：
- **字节码**：class 文件里的指令，JVM 能理解。
- **线程私有 / 共享**：每个线程自己一份，还是所有线程共用一份。

### 类加载器：把 class 搬进来
负责从文件、jar 包、网络等来源读取 class 文件的二进制数据，加载到内存，供后面使用。

### 运行时数据区：程序跑起来要用的内存
- **方法区**：存类的结构信息、常量、静态变量等，线程共享；
- **堆**：存放 new 出来的对象，线程共享，垃圾回收主要在这里；
- **虚拟机栈**：每个线程一个，方法调用时存放局部变量等；
- **程序计数器**：每个线程一个，记录当前执行到哪一行；
- **本地方法栈**：给 native（本地）方法使用，线程私有。

### 执行引擎：真正执行字节码
- **解释器**：逐条读字节码并执行，启动快；
- **即时编译器（JIT）**：把经常执行的热点代码编译成机器码，之后运行更快；
- 垃圾回收器也和执行引擎一起被归在这个部分的一些划分里，具体归类各资料略有不同。

### 它们怎么配合
程序启动时，类加载器把需要的类加载进来，存进方法区；运行时在堆里创建对象，每个线程用自己的栈执行方法；执行引擎一条条执行字节码，热点代码交给 JIT 编译优化。

## 易错点
- 以为堆和栈都是线程共享的；栈是线程私有的，堆是共享的
- 以为 JVM 只是解释执行；热点代码会被 JIT 编译成机器码
- 把方法区、元空间当成无关概念；元空间是 HotSpot 里方法区的一种实现

## 追问
### [f1] 哪些区域线程共享，哪些线程私有？
堆和方法区线程共享；虚拟机栈、程序计数器、本地方法栈每个线程各一份。
