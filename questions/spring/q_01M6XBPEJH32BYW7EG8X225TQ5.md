## 一句话
ORM 就是对象关系映射：把数据库里的表和记录对应到 Java 的类和对象上，让你用操作对象的方式操作数据库。

## 要点
- [kp1|3] ORM 解决关系型数据库与 Java 对象之间的映射问题
- [kp2|3] 表对应类，一行记录对应一个对象，列对应属性
- [kp3|2] 靠描述映射关系的元数据，把对象持久化到数据库
- [kp4] 常见实现有 Hibernate、MyBatis

## 详解
### 先搞懂：为什么需要对象和表的对应
做项目时，数据库里有一张用户表，代码里有一个 `User` 类。这像"通讯录"和"联系人卡片"：表是通讯录里的一页，每行是一个联系人；`User` 对象是一张联系人卡片。ORM 就是自动在两者之间抄写信息的人。

后文用到的词：

- **关系型数据库**：用表、行、列存数据的数据库，如 MySQL。
- **持久化**：把内存里的对象保存到数据库，重启后还在。
- **元数据**：描述"类的哪个属性对应表的哪一列"的配置信息。

### 对应关系
| 数据库 | Java |
|---|---|
| 表 | 类 |
| 一行记录 | 一个对象 |
| 一列 | 一个属性 |

### ORM 怎么工作
你用注解或 XML 写好映射元数据。保存对象时，框架按元数据把属性值写进对应的列；查询时，把列的值读出来填进对象。这样业务代码里不用再手动逐列取值。

### 全自动与半自动
不同框架自动化程度不同：Hibernate 连 SQL 都帮你生成，MyBatis 则需要自己写 SQL。

## 示例
```java
public class User {
    private Long id;      // 对应列 id
    private String name;  // 对应列 name
    // getter、setter 省略
}
```

## 易错点
- 以为 ORM 只是一种框架；它是一种思想，具体由框架实现
- 以为用了 ORM 就不用懂 SQL；性能问题仍然要看生成的 SQL

## 追问
### [f1] ORM 有什么缺点？
自动生成的 SQL 不一定最优，复杂查询难以调优，使用不当还会带来性能问题。
