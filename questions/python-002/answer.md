CPython 的内存管理分为**内存分配（PyMalloc）**与**垃圾回收（Garbage Collection）**两大部分。

---

## 1. 垃圾回收机制：三道防线

### ① 主干：引用计数（Reference Counting）
- 每一个 Python 对象内部都有一个 `ob_refcnt` 字段。
- **引用增加**：对象被创建、被赋值、作为参数传递、存入容器中。
- **引用减少**：显式 `del`、变量离开作用域、被重新赋值、容器被销毁。
- **优点**：实时性极高，引用归零时内存立刻被就地释放，没有停顿。
- **致命缺陷**：**无法解决循环引用（Reference Cycle）**（例如 `a.b = b; b.a = a; del a, b`，两者引用计数恒为 1，永远无法归零）。

### ② 补充：标记清除（Mark-Sweep）
- 专门用于处理**容器对象**（如 `list`、`dict`、`tuple`、自定义类实例）之间的循环引用。
- 通过双向链表追踪所有容器对象，将实际引用计数复制到 `gc_refs` 中，先遍历所有对象并将其引用的子对象计数递减。若减完后计数仍 > 0，说明有来自外部的强引用（可达），将其标记为存活；其余被判定为不可达的孤岛群组统一销毁。

### ③ 优化：分代回收（Generational Collection）
- 基于**弱分代假说（Weak Generational Hypothesis）**：存活时间越长的对象越不容易被回收，年轻对象死得快。
- Python 将对象分为 3 代（Gen 0、Gen 1、Gen 2）：
  - **第 0 代**：新分配的对象，回收频率最高（默认分配与释放差额达到 700 次触发）。
  - **第 1 代**：经历过 0 代回收仍存活的对象晋升到 1 代，回收频率中等（第 0 代回收满 10 次触发 1 次）。
  - **第 2 代**：老年代对象，存活时间长，回收频率极低（第 1 代回收满 10 次触发 1 次）。

## 2. 内存池机制：PyMalloc
为了避免频繁向操作系统申请/释放小块内存导致内存碎片，CPython 设计了分层内存管理：
- **大内存（> 512 字节）**：直接回退调用系统级 `malloc()`。
- **小内存（≤ 512 字节）**：由 **PyMalloc** 接管：
  - **Arena**：向系统申请的 256KB 连续内存。
  - **Pool**：Arena 被切分为若干 4KB 大小的 Pool。
  - **Block**：Pool 按 8 字节对齐划分为固定大小的 Block（如 8B, 16B... 512B），相同规格的小对象分配在同一 Pool 内，极大缓解碎片化。
