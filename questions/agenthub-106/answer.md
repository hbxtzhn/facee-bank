### 一句话总结

先做兼容扩展，让新旧代码可共存，再在确认后收缩旧结构。

### 回答要点

1. 新增可兼容字段或表通常先迁移再部署，代码处理缺省值与历史数据；需要回填时控制批次、检查点和重复执行语义。

2. 删除、重命名或改变含义属于更高风险变更，应先让旧依赖退出再收缩，按项目发布流程单独评估。

3. 记录 schema 版本、实际应用结果和回滚边界，不能假定回滚代码会自动撤销数据库迁移或恢复删除数据。

### 常见误区与边界

不要默认所有迁移都能通过执行反向 SQL 无损撤销。

[Cloudflare：D1 Migrations](https://developers.cloudflare.com/d1/reference/migrations/)。官方资料用于核对通用 API 语义，不证明任何项目已启用相应能力。
