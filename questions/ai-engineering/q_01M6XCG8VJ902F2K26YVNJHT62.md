## 一句话
PPO 要先训练奖励模型，再在线采样做强化学习；DPO 直接用偏好对改模型，不要显式的奖励模型和在线采样，流程更简单。

## 要点
- [kp1|3] PPO 流程需要奖励模型，并让模型在线生成回答再打分优化
- [kp2|3] DPO 直接拿好回答和差回答的偏好对，用一个分类式损失训练
- [kp3|2] DPO 用参考模型约束偏离，训练像普通监督学习一样稳定简单
- [kp4|2] PPO 更灵活、可在线探索，但实现复杂、调参难、资源占用大
- [kp5] 两者的目标一致，都是让模型更符合人类偏好

## 详解
### 先搞懂：请评委打分，还是直接看对比结果
想象训练厨师。PPO 的方式是：先培训一位评委学会打分，然后厨师不停做新菜，评委当场打分，厨师根据分数改进。DPO 的方式是：直接给厨师看一批「A 菜比 B 菜好」的对比记录，让他学着多做 A 那样的菜。

前者要多培养一个评委，还要现场反复做菜；后者只需要现成的对比数据。

后文用到的术语：
- **偏好对**：同一个问题的一个好回答和一个差回答。
- **在线采样**：训练过程中让当前模型实时生成回答。
- **参考模型**：训练开始时的模型副本，用来约束新模型别跑太远。

### PPO：奖励模型加在线强化学习
流程分两大段：

1. 用偏好数据训练奖励模型；
2. 让当前模型生成回答，奖励模型打分，PPO 算法据此更新模型，同时用惩罚项限制偏离参考模型。

实际训练时要同时管理好几个模型：正在训练的策略、参考模型、奖励模型，通常还有价值模型。显存占用和工程复杂度都比较高。

### DPO：把偏好直接变成训练目标
DPO 的思路是：不显式训练奖励模型，而是用数学推导把奖励隐含在模型本身的概率里。

训练时，对每个偏好对，提高好回答相对参考模型的概率，降低差回答的概率。整个过程像做一次分类训练，不需要在线生成，也不需要强化学习循环。

### 方案对比：PPO 和 DPO
| 对比点 | PPO | DPO |
|---|---|---|
| 奖励模型 | 需要单独训练 | 不需要显式奖励模型 |
| 数据来源 | 训练中在线采样 | 事先收集好的偏好对 |
| 实现复杂度 | 高，多个模型协同 | 较低，接近监督训练 |
| 灵活性 | 可探索新回答 | 受限于已有偏好数据 |

结论：想要简单稳定、快速起步，先选 DPO；需要在线探索、追求更高上限，且有足够工程资源时，考虑 PPO。哪个效果更好取决于任务和数据，不能一概而论。

### 进阶：DPO 的局限（基础薄弱可先跳过）
- 效果依赖偏好数据质量，数据里没覆盖的情形学不到。
- 数据不是当前模型生成的，分布可能和模型当前行为有差距。
- 有人在此基础上提出了多种变体，比如改进损失或加入在线采样。

## 示例
```python
# DPO 的训练数据：每条是一个偏好对
sample = {
    "prompt": "如何道歉？",
    "chosen": "真诚说明情况并提出补救办法……",
    "rejected": "不用道歉。",
}
```

## 易错点
- 以为 DPO 完全没有奖励；奖励被隐含在模型和参考模型的概率比里
- 以为 DPO 一定比 PPO 好或差；结论取决于任务、数据和调参
- 以为 PPO 只是个算法名；落地时它是一整套多模型协同的训练流程

## 追问
### [f1] DPO 里的参考模型起什么作用？
它是训练前模型的冻结副本。损失里比较新模型和参考模型对同一回答的概率，这样新模型不会为了拉开好坏差距而偏离太远。

### [f2] 为什么说 DPO 更稳定？
它把问题变成了离线的监督式训练，没有采样、奖励打分和价值估计这些相互影响的环节，需要调的东西更少。

### [f3] 两者有什么共同前提？
都需要高质量的人类偏好数据。数据里的偏差，无论经过奖励模型还是直接训练，都会被模型学进去。
