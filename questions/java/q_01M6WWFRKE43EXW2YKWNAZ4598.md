## 一句话
方法重写是子类写一个和父类方法签名相同的方法，提供自己的实现来覆盖父类的版本，这是多态成立的基础。

## 要点
- [kp1|3] 子类方法与父类方法名、参数列表相同，方法体由子类自己写
- [kp2|3] 重写是实现多态的基础，运行时按对象真实类型调用
- [kp3|2] 返回类型要相同或是父类返回类型的子类，访问权限不能比父类更小
- [kp4] private、static、final 方法不能被重写

## 详解
### 先搞懂：子类对家规有自己的做法
父类 `Animal` 定了「叫」这个行为，但每种动物叫法不同。狗子类可以说：这个行为我自己来做，叫「汪汪」。这就是重写：行为的名字不变，具体做法换成自己的。

后文要用的词：
- **方法签名**：方法名加参数列表。
- **@Override**：写在子类方法上的注解，告诉编译器「我在重写」，如果写错了会报错。

### 重写的规则
- 方法名和参数列表必须与父类**完全相同**；
- 返回类型相同，或者是父类返回类型的子类型；
- 访问权限不能比父类更严格，如父类是 `public`，子类不能写成 `protected`；
- 抛出的受检异常不能比父类更宽泛。

### 哪些方法不能重写
- `private` 方法：子类根本看不到；
- `static` 方法：属于类，写同名方法只是隐藏，不是重写；
- `final` 方法：明确禁止重写。

### 为什么要重写
让子类在保持接口不变的前提下，换上自己的行为。结合「父类引用指向子类对象」，同一个调用在运行时会执行子类版本，也就是多态。

### 用 @Override 保护自己
参数写错一个类型就变成了重载，编译器不报错，行为却不是你想要的。加上 `@Override`，写不对编译就会报错。

## 示例
```java
class Animal {
    void speak() { System.out.println("动物叫"); }
}
class Dog extends Animal {
    @Override
    void speak() { System.out.println("汪汪"); }
}
Animal a = new Dog();
a.speak();   // 汪汪
```

## 易错点
- 参数列表不一样，以为在重写，其实变成了重载；用 @Override 可以避免
- 子类重写时把访问权限缩小，编译报错
- 以为 static 方法能重写；它只是被隐藏，不具备多态

## 追问
### [f1] 子类重写后，还能调用父类的版本吗？
可以，在子类方法里用 `super.方法名()` 调用父类版本。

### [f2] 重写和重载的区别？
重写发生在父子类之间，签名相同，运行时决定；重载发生在同一个类，参数不同，编译期决定。
