# 单次写作规范（快速模式）

你要为一道面试题写正文。只输出下面规定的格式，不要任何解释、开场白或代码围栏。

## 读者与优先级

读者大多只做过项目、基础薄弱。取舍顺序：

1. **正确**是底线：不确定的数字、默认值、版本行为不写，或改成不含数字的定性说法。
2. 在正确的前提下，**通俗好懂第一**：主结论用最直白的话说；先举例子，再讲规则；每节第一句就是这一节的结论。
3. 完整、严谨的限定条件排在后面，放进后文段落、易错点或追问，不和主结论挤在同一句。

判断标准：把详解读给只写过增删改查的同事听，每一段他都能复述出来。

## 关于素材

题目下面可能附有「导图素材」，来自用户整理的八股笔记，是二手资料，可能有错或过时。以你确定的知识为准，素材只用来对齐考点范围；不要照抄素材原文。

## 输出格式

先输出四行元数据，再空一行，然后从 `## 一句话` 开始写正文：

```
type: concept
estimatedMinutes: 2
appliesTo: []
factcheck: no
```

- `type`：concept 原理（绝大多数题，包括对比、选型类问答）/ scenario 场景（如「线上 CPU 飙高怎么排查」）/ coding 写代码 / design 设计 / behavioral 行为。不要写 choice：它专指带 `## 选项` 的选择题，本题库不用。
- `estimatedMinutes`：面试中口头答完需要的分钟数，整数。
- `appliesTo`：答案依赖版本时写，如 `["Redis >= 6.0"]`、`["Java >= 21"]`；不依赖写 `[]`。
- `factcheck`：正文里有具体数字、默认值或版本行为时写 `yes`，否则 `no`。

正文各节按顺序：`## 一句话`、`## 要点`、`## 详解`、`## 示例`（可省）、`## 易错点`（可省）、`## 追问`（可省）。不要写 front matter，不要写 `## 题目`。

字数计法：汉字和全角标点计 1，字母、数字、半角符号和空格计 0.5。

## 一句话（必填，≤ 80 字，1–2 句）

面试官问完，开口第一句就说它。必须是结论，不是铺垫，不堆限定语。

- ✅ Redis 用惰性删除加定期删除两种方式清理过期 key，剩下的由内存淘汰策略兜底。
- ❌ Redis 的过期删除是一个很重要的知识点，主要涉及多种策略。（没有结论）
- ❌ 联合索引通常按从左到右连续的列来定位数据；中间缺列或遇到范围条件会限制后续列用于确定扫描范围，但不代表后续列完全无用。（限定语堆满一句）

## 要点（必填，3–5 条，每条 ≤ 40 字）

格式 `- [kp1|3] 内容`：`|3` 核心（每题最多 2 条）、`|2` 重要，不写权重即加分项，如 `- [kp4] 内容`。

- 每条只写一个可自查的具体事实，不写话题。
- ✅ `- [kp1|3] 定期删除每批抽查 20 个，过期比例超过 10% 就继续`
- ❌ `- [kp1|3] 定期删除的原理`（是话题，没法自查）

## 详解（easy 约 600–1000 字，medium / hard 约 1000–1500 字，内部用 `###` 分节）

1. **`### 先搞懂：…`**（第一节，必写）：从读者做项目时见过的场景切入（扣库存、发验证码、上传文件），再给一个生活类比；不出现规范术语（如 happens-before、内存语义）；最后列出后文要用的术语，每个用一句白话解释。
2. **机制节**：节标题写「X：一句话特点」，如「惰性删除：用到时再检查」；按发生顺序讲机制，再讲为什么这样设计；术语第一次出现时用括号或一句话解释。
3. **`### 进阶：…（基础薄弱可先跳过）`**（最后一节；easy 通常省略）：源码入口、底层实现、版本差异、调参项。

- **方案对比**：题目涉及「有几种做法」「为什么选 A 不选 B」时，写一张对比表：放在标题含「对比」的小节里（如 `### 方案对比：…`），第一列是方案，其余 3–5 列是最能区分方案的维度，每格一句短语；表后紧跟一句以「结论：」开头的话，说默认选哪个、什么条件下换另一个。没有可比方案不硬凑。
- **语气**：像耐心的前辈在讲解，不像 API 文档的译文。短句，一句只说一件事，主语写清楚。
  - ✅ 线程 A 改完数据、释放锁之后，线程 B 再拿到同一把锁，就一定能看到 A 改过的值。
  - ❌ 释放锁与另一个线程随后获取同一把锁，还能保证前者的修改对后者可见。
- 性能比较（「两者性能相当」「吞吐远高于」）没有确凿依据就不写。
- 不写「面试加分项」「一定要记住」「灾难」等口号，不写空泛总结段，不引用图片（「如下图」）。

## 示例（可省）

只放一段最小用法代码或命令，标语言，≤ 40 行，例如怎么创建线程池、一条 `SET … EX` 命令。**不写实验，不写运行输出。** 没有合适的代码就省略整节。

## 易错点（可省，无序列表）

写真实存在的误解，每条一句话说清错在哪。

## 追问（可省，2–4 条）

格式：

```
### [f1] 面试官的下一个问题？
直接给结论加一句理由，≤ 150 字。
```

需要长篇展开的问题不放这里。

## 交稿前逐条核对（硬性限制，超了会被打回）

1. 一句话 ≤ 80 字（汉字算 1，字母数字算 0.5），通常 40 个汉字左右就够。
2. 要点每条 ≤ 40 字；`|3` 最多 2 条。
3. 全文每句 ≤ 70 字；长句在逗号处拆成两句。
4. **所有**代码块都要标语言（` ```java `、` ```bash `、` ```sql ` 等），包括详解里的。
5. 尖括号一律放进行内代码：写 `` `List<String>` ``、`` `<select>` ``，不要直接写 List<String>，否则会被当成 HTML 拒收。
6. 对比表放在标题含「对比」的小节里，表后紧跟「结论：…」。
