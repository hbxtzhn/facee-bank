## 1. 紧凑字典的结构

CPython 3.6 引入紧凑字典，3.7 起插入顺序成为语言保证。常见的 combined table 将稀疏的索引数组与较紧凑的 entries 分离，空槽不再保存完整键值结构。索引宽度会随表大小变化，不是所有字典的索引都只占一个字节；实例属性还可能采用共享键的 split table。

插入新键会追加条目；更新已有键的值不改变其顺序；删除后重新插入则排在末尾。更省内存是这种布局的设计目标，具体节约比例依工作负载与版本而异。

## 2. 冲突与扩容

字典使用开放寻址与扰动探测，哈希决定初始位置，相等比较用于确认候选键。可用容量通常按约三分之二的负载控制，但**扩容大小与删除处理是 CPython 的版本实现细节**，不能把早期的“5 万以下扩四倍、以上扩两倍”当成现代规则。

删除通常留下探测标记及 entries 空洞，后续插入、重建或扩容时回收。单次删除不保证缩容；`clear()` 与重建字典可以改变容量，依版本实现而定。

## 3. 相等与哈希的契约

字典键必须可哈希，生命周期内哈希值保持稳定；若 `a == b`，则必须有 `hash(a) == hash(b)`。不等的对象可以同哈希。

自定义类可以使用继承自 `object` 的身份相等与哈希，无需总是重写两者；一旦重写值相等规则，就要提供与其一致的哈希，或保持不可哈希。
