## 一句话
布隆过滤器写入时，用 k 个哈希函数算出 k 个位置并全部置 1；判断时再算一遍，只要有一个位置是 0 就一定不存在，全是 1 才认为可能存在。

## 要点
- [kp1|3] 写入：元素经 k 个哈希函数得到 k 个位置，把这些位置都置 1
- [kp2|3] 判断：重新算出 k 个位置，任一位置为 0 就一定不存在
- [kp3|2] 所有位置都是 1 时无法确定存在，别的元素也会把这些位置 1
- [kp4] 位数组一开始全是 0，只会从 0 变 1，不会变回去

## 详解
### 先搞懂：给每个人打几个钩
想象一块黑板上有 10 个格子，开始全空。来一个人，我们按他的名字算出 3 个格子的编号，在这 3 格上打钩。以后来的人，同样算出 3 个编号：只要有一个格子没钩，他就肯定没登记过；如果 3 个格子都有钩，他很可能登记过。

后文用到的词：
- **位数组**：一排只能是 0 或 1 的格子，布隆过滤器的存储空间。
- **哈希函数**：把元素变成格子编号的计算方法，同一元素每次算出来结果相同。
- **k**：哈希函数的个数，也是每个元素占用的位数。

### 写入过程
1. 位数组初始全部是 0；
2. 元素经过 k 个哈希函数，得到 k 个位置（编号在数组长度范围内）；
3. 把这 k 个位置都置为 1。

比如数组长度为 10，元素 A 算出位置 1、4、7，就把第 1、4、7 位置 1。

### 判断过程
1. 对要查询的元素，用同样的 k 个哈希函数算出 k 个位置；
2. 只要有任何一个位置是 0：这个元素一定没写入过，因为写入时这些位置都会被置 1；
3. 如果 k 个位置全是 1：可能写入过，也可能是别的元素凑巧把这几位置成了 1。

### 为什么“不存在”是可靠的
位只会从 0 变 1，不会变回去。如果某元素真的写入过，它的 k 个位置一定都是 1。所以出现了 0，就能断定它没写入过，没有漏判。

### 为什么“存在”不可靠
别的元素写入时，也可能把本元素的位置置 1。k 个位置恰好都被别人占满，就会误判。这就是下一题讲的误判。

## 示例
```java
// 简化演示：位数组长度 16，两个哈希函数
boolean[] bits = new boolean[16];

void add(String s) {
    bits[Math.floorMod(s.hashCode(), 16)] = true;
    bits[Math.floorMod(s.hashCode() * 31 + 7, 16)] = true;
}

boolean mightContain(String s) {
    return bits[Math.floorMod(s.hashCode(), 16)]
        && bits[Math.floorMod(s.hashCode() * 31 + 7, 16)];
}
```

## 易错点
- 以为判断“存在”要比对原始数据；它只检查位是否为 1，不保存原数据
- 以为 k 越大越好；k 太大会很快把位占满，误判反而上升
- 以为可以把某元素的位清 0 来删除；会影响共用这些位的其他元素

## 追问
### [f1] 为什么要用多个哈希函数，而不是一个？
一个哈希函数只看一个位置，不同元素很容易撞到同一位。多个函数要求多个位置同时命中，误判概率更低；但数量太多也会把位占满，所以要取合适的值。
