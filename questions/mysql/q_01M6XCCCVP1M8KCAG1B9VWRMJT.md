## 一句话
聚簇索引的叶子节点直接存整行数据，一张表只有一个；非聚簇（二级）索引和数据分开存，可以有多个，查整行要多一步回表。

## 要点
- [kp1|3] InnoDB 的主键索引是聚簇索引，叶子节点就是整行数据
- [kp2|3] 聚簇索引每表只能有一个，因为数据只能按一种顺序存放
- [kp3|2] 二级索引的叶子节点存索引列和主键值，一张表可以建多个
- [kp4|2] 通过二级索引取整行，要先拿到主键，再回聚簇索引查，叫回表

## 详解
### 先搞懂：字典正文和目录
想象一本新华字典：正文就是按拼音排好的所有字，这就是聚簇索引，数据本身就是索引。你想按「部首」查字，得翻部首目录，目录只写了字所在的页码，还要翻回正文才能看到完整的解释。这个部首目录就是二级索引。

几个术语：

- **聚簇索引**：叶子节点存整行数据的索引，数据按它排序。
- **二级索引**：也叫辅助索引、非聚簇索引，叶子节点不存整行。
- **回表**：先查二级索引，再回聚簇索引取整行。
- **覆盖索引**：想要的列二级索引里就有，不用回表。

### 聚簇索引：数据就在索引里
在 InnoDB 里，表就是一棵按主键排序的 B+ 树，叶子节点存整行数据。所以：

- 按主键查，一次树查找就拿到整行；
- 因为数据只能按一种顺序排，一张表只能有一个聚簇索引；
- 没有定义主键时，InnoDB 会选一个非空唯一索引，再没有就自动生成隐藏的行 ID。

### 非聚簇索引：数据在别处
二级索引是另一棵 B+ 树，叶子节点存索引列的值和主键值，不存整行。所以：

- 一张表可以建多个二级索引；
- 查整行要先在二级索引里找到主键值，再拿主键值去聚簇索引取整行，这就是回表；
- 如果要查的列二级索引里都有，就不需要回表，这叫覆盖索引。

### 方案对比：聚簇和非聚簇
| 对比点 | 聚簇索引 | 非聚簇（二级）索引 |
|---|---|---|
| 叶子节点存什么 | 整行数据 | 索引列加主键值 |
| 数量 | 每张表一个 | 可以有多个 |
| 数据和索引 | 数据就在索引里 | 索引和数据分开 |
| 取整行 | 一次查找 | 可能要回表 |
| 例子 | InnoDB 的主键 | 普通索引、唯一索引 |

结论：按主键查最快；其他列的查询，尽量用覆盖索引避免回表。

### 进阶：MyISAM 的情况（基础薄弱可先跳过）
MyISAM 的索引和数据文件是分开的，所有索引（包括主键）的叶子节点存的都是行的位置，所以它没有聚簇索引。

## 示例
```sql
CREATE TABLE user (
  id BIGINT PRIMARY KEY,      -- 聚簇索引
  name VARCHAR(50),
  KEY idx_name (name)         -- 二级索引，叶子存 (name, id)
);
-- 走 idx_name 找到 id，再回表取整行
SELECT * FROM user WHERE name = 'Tom';
-- 只查 name 和 id，二级索引里就有，不用回表
SELECT id, name FROM user WHERE name = 'Tom';
```

## 易错点
- 以为聚簇索引是一种需要单独创建的索引；在 InnoDB 里它就是主键对应的那棵树
- 以为二级索引叶子节点存的是行的磁盘地址；InnoDB 里存的是主键值
- 以为用二级索引一定比主键慢很多；覆盖索引时可以不回表

## 追问
### [f1] 为什么一张表只能有一个聚簇索引？
聚簇索引决定数据的存放顺序，数据只有一份，只能按一种顺序排，所以只能有一个。
