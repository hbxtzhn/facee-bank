## 一句话
索引是帮助快速定位数据的一种数据结构，类似书的目录。没有索引要逐行扫描整张表，有了索引可以直接定位，但会多占空间、拖慢增删改。

## 要点
- [kp1|3] 没有索引，查询要逐行扫描整张表，叫全表扫描
- [kp2|3] 有索引，可以像查目录一样直接定位到数据，大幅减少磁盘读取
- [kp3|2] 索引要占额外的磁盘空间
- [kp4|2] 增删改时，索引也要同步维护，会让写入变慢

## 详解
### 先搞懂：翻书找内容的两种办法
想在一本 500 页的书里找「事务」这个词：

- 没有目录：从第一页开始一页一页翻，直到找到为止；
- 有目录：先查目录，看到在第 230 页，直接翻过去。

数据库查数据也是这样。表里数据很多时，一行行看太慢，索引就是这本书的目录。

后文用到的术语：

- **全表扫描**：从头到尾逐行检查；
- **磁盘 IO**：从磁盘读取数据，是数据库里最耗时的操作之一。

### 为什么能加快查询
数据存放在磁盘上，读取磁盘比读内存慢得多。

- **没有索引**：数据库只能逐行读取，检查每一行是否符合条件。数据量越大，要读的磁盘数据就越多。
- **有索引**：索引把列值按顺序组织起来，查询时顺着索引快速找到目标位置，只需要读很少的数据。MySQL 的 InnoDB 默认使用 B+ 树组织索引。

### 索引的代价
索引不是越多越好：

- **占空间**：索引也要存储在磁盘上；
- **写入变慢**：往表里新增、修改、删除数据时，相关的索引也要同步更新，索引越多，这部分开销越大。

所以通常给经常用来查询、过滤、排序的列建索引，而不是每一列都建。

## 示例
```sql
CREATE INDEX idx_user_name ON t_user (name);

SELECT * FROM t_user WHERE name = 'tom';
```

## 易错点
- 以为索引越多越好；索引多了会占空间，也会拖慢增删改
- 以为建了索引就一定会被用上；查询写法不合适时，优化器可能不走索引
- 以为索引只加快查询、没有任何代价

## 追问
### [f1] 哪些列适合建索引？
经常出现在 `WHERE` 条件、`JOIN` 关联条件和 `ORDER BY` 里的列，并且区分度较高，即不同值比较多。

### [f2] 为什么写入会变慢？
因为数据变了，索引里对应的内容也要跟着改，还要保持有序。表上索引越多，每次写入要维护的结构就越多。
