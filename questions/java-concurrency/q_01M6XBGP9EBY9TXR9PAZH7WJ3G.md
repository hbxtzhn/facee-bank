## 一句话
单例模式保证一个类在程序里只有一个实例，并提供一个全局入口获取它。常见写法有饿汉式（类加载时就创建）和懒汉式（第一次用时才创建）。

## 要点
- [kp1|3] 单例模式：一个类只能有一个实例，并提供全局访问点
- [kp2|3] 实现方式是私有构造器加静态方法获取实例
- [kp3|2] 饿汉式：类加载时就创建，简单且线程安全，但不用也占内存
- [kp4|2] 懒汉式：第一次调用时才创建，省资源，但基础写法线程不安全

## 详解
### 先搞懂：为什么需要「只有一个」
项目里的配置读取器、日志管理器、连接池，整个程序里有一份就够了。如果每处代码都 `new` 一个，会浪费资源，还可能出现各自持有不同配置的混乱。

类比公司只有一个前台：所有访客都找同一个人，不会每个访客自己招一个前台。

后文用到的几个词：
- **私有构造器**：构造方法用 `private`，外部不能 `new`。
- **全局访问点**：一个公开的静态方法，所有代码都通过它拿到唯一实例。

### 实现单例的三步
1. 构造器设为 `private`，防止外面随便创建；
2. 类里持有一个静态的实例变量；
3. 提供公开的静态方法返回这个实例。

### 饿汉式：类加载时就建好
实例在类被加载时直接创建。由于类加载过程由 JVM 保证线程安全，所以这种写法天然线程安全，代码也最简单。缺点是即使程序一直没用到它，实例也已经创建出来了。

### 懒汉式：用到时再建
获取实例时先判断是否为空，为空才创建。优点是不用就不占资源。缺点是最基础的写法线程不安全：两个线程同时判断为空，会各自创建一个，单例就破了。线程安全的写法见「怎么实现线程安全的单例模式」。

### 方案对比：饿汉与懒汉
| 写法 | 创建时机 | 线程安全 | 优点 | 缺点 |
|---|---|---|---|---|
| 饿汉式 | 类加载时 | 安全 | 简单 | 可能浪费资源 |
| 懒汉式（基础） | 第一次使用时 | 不安全 | 延迟创建 | 多线程会创建多个 |

结论：实例创建成本不高、一定会用到时用饿汉式最省心；需要延迟创建时用线程安全的懒汉写法。

## 示例
```java
// 饿汉式
public class Singleton {
    private static final Singleton INSTANCE = new Singleton();
    private Singleton() {}
    public static Singleton getInstance() { return INSTANCE; }
}
```

## 易错点
- 忘记把构造器设为 private；外部仍然可以 new 出新实例
- 以为懒汉式天然线程安全；基础写法在多线程下可能创建多个实例
- 以为单例就绝对只有一个；反射、序列化可能创建出额外实例

## 追问
### [f1] Spring 的 Bean 默认是单例吗？
默认是单例作用域，但它是容器管理下「每个容器一个实例」，不是用私有构造器实现的单例模式。
