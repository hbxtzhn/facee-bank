## 一句话
HTTP 的每个请求相互独立，服务器默认不记得上一次是谁，所以要靠 Cookie 或 Session 保存状态。

## 要点
- [kp1|3] 无状态指服务器不会自动记住之前的请求
- [kp2|3] 每个请求必须带齐处理它所需的信息
- [kp3|2] 无状态让服务器实现简单，也方便横向扩展
- [kp4|2] 需要记住用户，就用 Cookie 或 Session 补上状态

## 详解
### 先搞懂：每次都像第一次见面
想象一个柜员，每次你来窗口，他都完全不记得你。你办完第一件事走开，再来办第二件，他又重新问你是谁。

HTTP 就是这样的柜员。你登录了网站，再点另一个页面，服务器本身并不知道这两次请求是同一个人发的。几个词：

- **无状态**：协议不记录前后请求之间的联系。
- **Cookie**：服务器让浏览器保存、以后每次请求带上的一小段数据。
- **Session**：服务器上保存的用户状态，用一个编号去找。

### 什么叫无状态
服务器处理一个请求，只根据这个请求里带来的信息，处理完就不留下对这个客户端的记忆。所以每个请求都是独立的，前面请求做过什么，对后面没有影响。

### 为什么这样设计
- **简单**：服务器不用为每个客户端维护状态，实现和排错都更容易；
- **易扩展**：请求和哪台服务器都没有绑定关系，任何一台服务器都能处理，加机器很方便。

### 无状态带来的问题
网站需要记住登录状态、购物车。如果每次都要重新输入用户名密码，用起来很不方便。所以需要在协议之外，想办法让服务器认出同一个人。

### 常见做法
- **Cookie**：登录后，服务器让浏览器保存一段数据，之后每个请求浏览器自动带上；
- **Session**：服务器保存登录状态，只把一个编号交给浏览器，请求时靠这个编号找回状态。

两者经常一起使用：Session 编号通常放在 Cookie 里传递。

## 易错点
- 以为无状态就是不能记录登录状态；协议本身无状态，状态靠 Cookie 或 Session 补
- 以为 TCP 连接保持就是有状态；连接复用不代表 HTTP 记住了用户
- 以为无状态是缺点；它换来了简单和可扩展

## 追问
### [f1] 无状态对服务器集群有什么好处？
请求不依赖某台机器上的记忆，任何一台都能处理，负载均衡和扩容更容易。若状态放在某台机器的内存里，就要另外想办法共享。
