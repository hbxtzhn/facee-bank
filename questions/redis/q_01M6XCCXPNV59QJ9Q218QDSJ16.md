## 一句话
Redis 的数据放在内存里，读写很快，放在数据库前面能挡掉大量读请求；缓存的本质是用一份数据副本换速度。

## 要点
- [kp1|3] 数据在内存中，读写比磁盘数据库快得多
- [kp2|3] 缓存挡住大量读请求，减轻数据库压力
- [kp3|2] 提高响应速度和系统吞吐量
- [kp4|2] 缓存是数据副本，要处理和数据库不一致的问题
- [kp5] 支持过期时间和多种数据类型，使用方便

## 详解
### 先搞懂：把常用的书放在手边
你去图书馆查资料。热门书放在手边的书桌上，一伸手就拿到；冷门书放在远处书库，要走很远去取。

数据库像书库，容量大但取得慢。Redis 像书桌，容量小但取得快。缓存就是把常被查的数据放在书桌上。

后文会用到的术语：

- **缓存**：常用数据的一份副本，放在更快的地方。
- **命中**：要的数据在缓存里，直接拿到。
- **回源**：缓存里没有，只好去数据库查。

### 为什么快
数据库的数据主要在磁盘上，一次读取要等磁盘。Redis 的数据在内存里，读写不用等磁盘，所以延迟低很多。

### 为什么能保护数据库
很多系统读多写少，大量请求读的是同样的热点数据。把它们放进 Redis，大部分请求在缓存里就返回了，数据库只处理少量未命中的请求。

### 常见用法
读取时的基本流程：

1. 先查 Redis，命中就返回。
2. 没命中，查数据库。
3. 把查到的结果写回 Redis，设置过期时间，再返回。

### 代价：数据副本可能过期
缓存里是副本。数据库里的数据改了，缓存里的旧副本如果没更新，就会读到旧数据。所以要设计更新或删除缓存的策略，常见做法是更新数据库后删除缓存，并设置过期时间兜底。

还要注意缓存穿透、击穿、雪崩这类异常场景。

## 示例
```bash
GET product:1001                     # 先查缓存
SET product:1001 '{"name":"A"}' EX 600   # 未命中时回写，10 分钟过期
```

## 易错点
- 以为缓存能无限放数据；内存有限，需要设置过期和淘汰策略
- 以为加了缓存就一定更快；命中率很低时，反而多了一次查询
- 以为缓存和数据库天然一致；需要自己设计更新策略

## 追问
### [f1] 缓存和数据库的数据不一致怎么办？
常见做法是更新数据库后删除缓存，下次读时重新加载，并给缓存设置过期时间兜底。对一致性要求极高的数据，不要用缓存或要额外保证。
