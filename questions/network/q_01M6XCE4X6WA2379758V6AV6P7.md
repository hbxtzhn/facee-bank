## 一句话
浏览器先查自己的缓存，没有就问本地 DNS，本地 DNS 再依次问根、顶级域、权威域名服务器，逐级得到 IP。

## 要点
- [kp1|3] 先查各级缓存，命中就直接返回，不再往下问
- [kp2|3] 缓存未命中时，本地 DNS 依次问根、顶级域、权威域名服务器
- [kp3|2] 根服务器指向顶级域，顶级域指向权威服务器，权威服务器给出 IP
- [kp4] 本地 DNS 拿到结果后缓存并返回给浏览器

## 详解
### 先搞懂：逐级问路
你到一个陌生城市找一家店。先问自己有没有存过地址（自己的记忆），没有就问路口的便利店（本地 DNS）；便利店也不知道，就去问区里的指路处，一级一级问下去，直到有人给出具体门牌号。

DNS 的查询也是这样，每一级只告诉你「下一步去问谁」，最后一级才给出答案。

后文的术语：

- **本地 DNS 服务器**：你的网络提供的 DNS 服务器，替你去查询。
- **根域名服务器**：整个体系的最顶层，知道每个顶级域由谁管。
- **顶级域名服务器**：管理 `.com`、`.cn` 这类顶级域，知道下面域名由谁负责。
- **权威域名服务器**：负责某个具体域名，直接保存域名和 IP 的对应记录。

### 第一步：先查缓存
浏览器先检查自己的缓存，有就直接用。没有再查操作系统的缓存和本机的 hosts 文件。都没有，才向本地 DNS 服务器发出查询。本地 DNS 自己也有缓存，命中同样直接返回。

### 第二步：本地 DNS 逐级查询
本地 DNS 缓存里也没有时，开始向外查询，以 `www.example.com` 为例：

1. 问**根域名服务器**：根服务器不知道具体 IP，但告诉它「`.com` 由这些顶级域服务器负责」。
2. 问**顶级域名服务器**：它告诉本地 DNS「`example.com` 由这些权威服务器负责」。
3. 问**权威域名服务器**：它保存着记录，直接返回 `www.example.com` 对应的 IP。

### 第三步：返回并缓存
本地 DNS 把 IP 返回给浏览器，同时自己缓存一份。浏览器也缓存，然后向这个 IP 发起连接。

### 两种查询方式
- **递归查询**：浏览器向本地 DNS 提问后，就等着拿最终结果，中间的事交给本地 DNS 负责。
- **迭代查询**：本地 DNS 向根、顶级域、权威服务器提问时，对方只回答下一步该问谁，由本地 DNS 自己继续问。

## 示例
```bash
# 追踪从根服务器开始的逐级解析过程
dig +trace www.example.com
```

## 易错点
- 以为浏览器自己会去问根服务器；通常由本地 DNS 代替它完成逐级查询
- 以为每次访问都要查完全部几级；缓存命中时中间步骤都可省去
- 以为根服务器直接返回 IP；根服务器只告诉你下一步去问哪个顶级域服务器

## 追问
### [f1] 为什么 DNS 要设计成分级？
域名数量巨大，一台服务器存不下，也扛不住所有请求。分级后，每一级只管自己下面的部分，既分散了压力，也便于各个域名的所有者自行管理自己的记录。
