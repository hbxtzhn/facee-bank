## 一句话
记录锁就是锁住索引里的某一条具体记录，比如用唯一索引做等值查询、刚好命中一行时，InnoDB 只锁这一行。

## 要点
- [kp1|3] 记录锁锁的是索引里的一条记录，不包括它周围的间隙
- [kp2|3] 唯一索引等值查询命中一行时，只加记录锁
- [kp3|2] 记录锁分共享和排他两种模式
- [kp4] 没有任何索引时，InnoDB 会用隐藏的聚簇索引加锁
- [kp5] 记录锁只挡住对这一条记录的冲突访问，不挡插入

## 详解
### 先搞懂：只锁这一行，旁边不管
假设用户表里有 id 为 1、5、10 的三行。你执行「查 id = 5 并锁住」，InnoDB 只需要把 5 这一行锁起来。其他事务可以改 1 和 10，也可以往 5 与 10 之间插新行，只有对 5 的修改要等。

类比：电影院里订了 5 号座位，别人不能坐这个座位，但旁边的座位照样可以订。

后文会用到这几个词：

- **记录锁**：锁一条索引记录的锁。
- **唯一索引**：索引列的值不重复，主键索引也是唯一索引。
- **等值查询**：条件是 `=`，比如 `id = 5`。

### 什么时候加记录锁
最典型的情况是：

1. 查询条件用的是**唯一索引**（主键或唯一键）；
2. 是**等值**查询；
3. 并且**刚好命中**一条已存在的记录。

这时只需要锁住这条记录，不需要锁间隙，因为唯一索引保证了不会再出现相同的值，也就不会有幻读。

### 记录锁也分读写
记录锁可以是共享的（S），也可以是排他的（X）：

- `SELECT ... FOR SHARE` 加共享记录锁；
- `SELECT ... FOR UPDATE`、`UPDATE`、`DELETE` 加排他记录锁。

### 没有索引怎么办
表如果没有主键和唯一索引，InnoDB 会创建一个隐藏的聚簇索引。记录锁依然是加在索引记录上，只是加在这个隐藏索引上。

## 示例
```sql
-- id 是主键，且存在 id = 5 的记录
START TRANSACTION;
SELECT * FROM user WHERE id = 5 FOR UPDATE;  -- 对 id=5 加排他记录锁
-- 其他事务更新 id=5 的行会被阻塞，更新 id=1 不受影响
```

## 易错点
- 以为只要等值查询就是记录锁；非唯一索引上还会加间隙相关的锁
- 以为唯一索引上等值查询没命中也是记录锁；没命中时会加间隙锁
- 以为记录锁锁的是整行数据，实际锁的是索引记录

## 追问
### [f1] 唯一索引等值查询没命中记录，会怎样？
记录不存在时，没有记录可锁，会改为对这个值所在的间隙加间隙锁，防止别人往这个位置插入同样的值。
