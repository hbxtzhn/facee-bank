## 一句话
GC Roots 是一组肯定还在使用的引用，是可达性分析的起点：从它们出发能找到的对象是活的，找不到的就是垃圾。

## 要点
- [kp1|3] GC Roots 是可达性分析的起点，从它们出发的引用链上的对象是存活的
- [kp2|3] 虚拟机栈里的局部变量、方法参数引用的对象可作为 GC Roots
- [kp3|2] 类的静态变量引用的对象是 GC Roots
- [kp4|2] 本地方法（JNI）引用的对象是 GC Roots
- [kp5] 严格说，Roots 是引用而不是对象，它们指向的对象才被当作存活

## 详解
### 先搞懂：从哪些地方开始找人
判断一间教室里谁还在，不能随便找，得从肯定有人的地方开始：正在上课的老师、坐在座位上的学生。顺着「谁和谁在一起」往下找，找得到的就是在场的人，剩下没人认识的，就是该清走的。

GC Roots 就是这些「肯定在场」的起点。

后文用到的术语：

- **引用链**：从起点出发，经过一连串引用到达某个对象的路径。
- **虚拟机栈**：每个线程运行方法时用的栈，局部变量就在里面。
- **JNI**：Java 调用本地（C/C++）代码的接口。

### 常见的 GC Roots
- **虚拟机栈里的引用**：正在执行的方法的局部变量、参数。方法执行到一半，这些变量指向的对象当然不能回收。
- **本地方法栈里的引用**：本地方法（JNI）持有的对象引用。
- **类的静态变量**：static 字段引用的对象，只要类还在就一直存在。
- **常量引用**：运行时常量池里的常量引用的对象，如字符串常量。
- **其他**：正在运行的线程对象、被 `synchronized` 持有的锁对象等，也会作为 Roots。

具体包含哪些，不同虚拟机实现略有差别，记住前面几类就能应付常规问题。

### 为什么这样选
这些位置有个共同点：只要程序还在运行，就一定会用到它们。从它们出发还能走到的对象，就有可能被用到，不能回收。反过来，从这些起点走不到的对象，程序已经没有办法再访问，回收是安全的。

## 示例
```java
public class Demo {
    static Object a = new Object();    // 静态变量，GC Roots 指向的对象

    void run() {
        Object b = new Object();       // 栈里的局部变量，方法执行期间是 GC Roots
        // ...
    }
}
```

## 易错点
- 以为 GC Roots 是对象；它们是引用，指向的对象才是被保护的
- 以为堆里的对象都可以作为 GC Roots；普通堆对象不是，只有被 Roots 引用到才存活
- 以为方法执行结束后局部变量引用的对象仍受保护；方法返回后栈帧销毁，引用消失

## 追问
### [f1] 为什么静态变量容易引起内存泄漏？
静态变量是 GC Roots，它引用的集合只要不清理，里面的对象就一直可达，不会被回收。
