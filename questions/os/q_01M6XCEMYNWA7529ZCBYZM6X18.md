## 一句话
信号是操作系统向进程发的事件通知，只告诉进程某件事发生了，不能用来传输大量数据。

## 要点
- [kp1|3] 信号用来通知进程某个事件发生了
- [kp2|3] 信号只表示事件类型，不携带大量数据
- [kp3|2] 进程可以执行默认动作、捕获后自己处理或忽略信号
- [kp4|2] `SIGKILL` 和 `SIGSTOP` 不能被捕获或忽略
- [kp5] 常见：按 Ctrl+C 发出 `SIGINT`，`kill` 默认发出 `SIGTERM`

## 详解
### 先搞懂：敲门铃和打电话
信号像是敲门铃：铃一响，你知道有人来了，但不知道他要说什么。想传复杂的内容，得开门聊天，也就是用别的通信方式。

你在命令行里按 Ctrl+C 终止程序，就是在给这个进程发了一个信号。

后文要用的术语：

- **信号**：一个带编号的事件通知，每个编号代表一种事件。
- **捕获**：进程提前登记一个处理函数，信号来了就执行它。

### 信号怎么工作
1. 某个事件发生：用户按了 Ctrl+C，或另一个进程调用了 `kill`，或程序出错；
2. 操作系统把对应的信号发给目标进程；
3. 目标进程收到后，按设定的方式处理。

### 进程有三种处理方式
- **默认动作**：多数信号的默认动作是终止进程；
- **捕获**：自己写处理函数，比如收到终止信号后先保存数据再退出；
- **忽略**：不理会这个信号。

但 `SIGKILL` 和 `SIGSTOP` 不能被捕获或忽略，这保证了管理员总有办法强行结束或暂停进程。

### 常见信号
| 信号 | 常见触发方式 | 默认效果 |
|---|---|---|
| `SIGINT` | 按 Ctrl+C | 终止进程 |
| `SIGTERM` | `kill` 命令默认发送 | 终止进程，可被捕获 |
| `SIGKILL` | `kill -9` | 强制终止，不能被捕获 |

## 示例
```bash
kill -TERM 1234   # 请求进程 1234 正常退出，进程可以捕获并清理
kill -KILL 1234   # 强制结束，进程来不及清理
```

## 易错点
- 以为信号能传大量数据；它只是事件通知
- 以为 `kill` 命令就是杀死进程；它的本质是发送信号，是否终止取决于信号类型和进程的处理方式

## 追问
### [f1] 优雅停机和强制杀死有什么区别？
优雅停机是发 `SIGTERM`，进程捕获后先完成收尾再退出；强制杀死是发 `SIGKILL`，进程来不及清理，可能丢数据。
