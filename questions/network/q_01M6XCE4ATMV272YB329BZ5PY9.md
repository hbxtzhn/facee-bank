## 一句话
URL 由协议、域名（或 IP）、端口、路径和查询参数等部分组成，合起来说明用什么方式、去哪台服务器、取哪个资源。

## 要点
- [kp1|3] 协议部分说明用什么规则通信，如 http 或 https
- [kp2|3] 域名或 IP 说明访问哪台服务器，端口说明访问服务器上的哪个服务
- [kp3|2] 路径指明服务器上的哪个资源，查询参数用问号后的键值对传参
- [kp4] 端口省略时使用协议的默认端口，http 为 80，https 为 443

## 详解
### 先搞懂：一个完整的收货地址
URL 就像一条完整的收货信息：几号楼（服务器）、几号房（服务）、放在哪个柜子（资源），还要说明用什么方式送货。浏览器拿到 URL，才知道该怎么去取这个资源。

### 以一个例子拆开
```text
https://www.example.com:8080/user/profile?id=123&lang=zh#section2
```

- `https`：**协议**，说明用什么规则通信。https 是加密的 HTTP。
- `www.example.com`：**域名**，指明服务器。也可以直接写 IP 地址，比如 `192.168.1.10`。
- `8080`：**端口**，指明服务器上的哪个服务。
- `/user/profile`：**路径**，指明服务器上的哪个资源。
- `?id=123&lang=zh`：**查询参数**，问号开头，多个参数用 `&` 连接，每个参数是 `名字=值`。
- `#section2`：**锚点（片段）**，指向页面里的某个位置。它只在浏览器里使用，不会随请求发给服务器。

### 各部分的细节
- **协议**：决定浏览器用哪种方式去请求。
- **域名与端口**：浏览器会先把域名解析成 IP，再连接这个端口。端口如果不写，就按协议的默认端口：http 是 80，https 是 443。
- **路径**：服务器根据路径决定返回哪个资源，或交给哪个处理程序。
- **查询参数**：把额外的信息传给服务器，比如搜索关键词、页码。参数里有中文、空格或特殊字符时，需要先做 URL 编码。

## 易错点
- 以为锚点会发送给服务器；锚点只在浏览器本地使用
- 以为 URL 里必须写端口；不写时使用协议的默认端口
- 以为 URL 里能直接放中文和空格；需要编码后才能安全传输

## 追问
### [f1] URL 和 URI 有什么区别？
URI 是统一资源标识符，用来标识一个资源；URL 是其中能说明怎么找到资源的一种，所以 URL 是 URI 的子集。日常说的网址，一般指 URL。
