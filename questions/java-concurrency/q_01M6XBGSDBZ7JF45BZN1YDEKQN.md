## 一句话
原子性是指一个操作要么完整做完、要么不做，中间不会被别的线程插进来；i++ 其实是读取、加一、写回三步，多线程交错执行就会丢更新，所以不是原子操作。

## 要点
- [kp1|3] 原子性：操作不可分割，中途不会被其他线程打断
- [kp2|3] i++ 包含读取、加一、写回三步，不是一个原子操作
- [kp3|2] 两个线程同时 i++，可能都基于旧值计算，结果少加一次
- [kp4] 解决办法：synchronized 加锁，或使用 AtomicInteger 等原子类

## 详解
### 先搞懂：转账为什么要「要么全成要么全败」
银行转账：从 A 账户扣 100，再往 B 账户加 100。如果扣完钱系统出错，B 没收到，钱就凭空消失了。所以这两步必须作为一个整体：要么都完成，要么都不做。这种「不可分割」的性质就是原子性。

后文用到的几个词：
- **原子操作**：一步完成、不会被其他线程看到中间状态的操作。
- **丢失更新**：两个线程都做了修改，其中一个的结果被覆盖，等于没做。

### i++ 拆开看是三步
`i++` 一行代码，执行时要分三步：

1. 读取 i 的当前值；
2. 把值加 1；
3. 把新值写回 i。

单线程下，三步连着做完没问题。多线程下，线程之间可以在任意两步之间切换。

### 一个丢失更新的例子
设 i 是 0，线程 A 和 B 同时执行 `i++`：

1. A 读到 0；
2. B 也读到 0；
3. A 算出 1，写回；
4. B 也算出 1，写回。

执行了两次 `i++`，i 却是 1。第二次的结果覆盖了第一次，一次自增丢了。

### 怎样保证原子性
- `synchronized` 或 `Lock`：同一时刻只让一个线程执行这三步；
- `AtomicInteger` 等原子类：用 CAS 一步完成自增；
- 注意 `volatile` 不能保证原子性，它只管可见和有序。

## 示例
```java
int i = 0;
// 多个线程同时执行
i++;                // 非原子：读取、加一、写回

AtomicInteger n = new AtomicInteger();
n.incrementAndGet(); // 原子自增
```

## 易错点
- 以为一行代码就是原子的；单行代码在字节码层面也可能是多步
- 以为给变量加 volatile 就能让 i++ 安全；它不保证复合操作的原子性
- 以为原子性只和多线程有关；它描述的是操作能否被打断，只是在多线程下才有影响

## 追问
### [f1] 对 long 或 double 的读写是原子的吗？
Java 规范允许 64 位的 long、double 非 volatile 读写拆成两次 32 位操作，理论上不保证原子；主流 64 位虚拟机实现上通常是原子的，要严格保证可以加 volatile。
