## 一句话
脏读是读到了别的事务还没提交的数据；如果对方随后回滚，你读到的数据就是实际不存在的。

## 要点
- [kp1|3] 脏读：读到另一个事务修改了但还没提交的数据
- [kp2|3] 对方回滚后，你读到的数据等于从没存在过
- [kp3|2] 读未提交级别会出现脏读，读已提交及以上避免
- [kp4] 脏读读的是同一行的未提交值，和幻读、不可重复读不同

## 详解
### 先搞懂：别人草稿上的数字
假设财务在改你的工资单，他先把工资写成 20000，还没点保存。你偷看了他的草稿，看到 20000。结果他发现写错了，撤销改回 10000。

你看到的 20000，从来没有真正生效过。这就是脏读：读到了别人还没「保存」的数据。

后文会用到的术语：

- **事务**：一组要么全做、要么全不做的操作。
- **提交**：确认事务的修改，从此对别人可见。
- **回滚**：撤销事务的所有修改。

### 脏读是怎么发生的
两个事务交替执行：

1. 事务 B 把账户余额从 100 改成 200，但还没提交。
2. 事务 A 查询余额，读到了 200。
3. 事务 B 发现出错，回滚，余额变回 100。
4. 事务 A 拿着 200 继续做决定，比如放行一笔支付。

事务 A 用了一个不存在的值。

### 怎么避免
把隔离级别设成读已提交或更高。这样事务只能读到别人已经提交的数据，没提交的修改看不到。

读未提交是唯一会脏读的级别，实际几乎不会用。

## 示例
```sql
-- 会话 B
START TRANSACTION;
UPDATE account SET balance = 200 WHERE id = 1;  -- 未提交

-- 会话 A（读未提交级别）
SET SESSION TRANSACTION ISOLATION LEVEL READ UNCOMMITTED;
SELECT balance FROM account WHERE id = 1;       -- 读到 200（脏读）

-- 会话 B
ROLLBACK;                                       -- 余额回到 100
```

## 易错点
- 把脏读和不可重复读混淆；脏读读到的是未提交的数据，后者是读到别人已提交的修改
- 以为脏读只在极端情况出现；只要用读未提交级别，随时可能出现

## 追问
### [f1] 读已提交是怎么避免脏读的？
InnoDB 用读视图判断每个版本是否可见，已提交事务产生的版本才可见。别人还没提交的修改，在读视图里被判定为不可见。
