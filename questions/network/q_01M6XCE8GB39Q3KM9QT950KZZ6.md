## 一句话
流量控制让发送方按接收方的处理能力发数据，因为接收方缓冲区有限，发得太多会溢出丢数据，白白浪费网络。

## 要点
- [kp1|3] 接收方缓冲区大小有限，来不及处理的数据会被丢弃
- [kp2|3] 接收方通过窗口告诉发送方自己还能接收多少
- [kp3|2] 发送方发出的数据量不能超过这个窗口
- [kp4] 窗口为 0 时发送方暂停，并定时询问接收方是否有空位

## 详解
### 先搞懂：水管接水桶
水龙头开得太大，水桶接不过来，水就溢出去浪费了。你得让接水的人喊一声「桶快满了，开小点」。

TCP 的发送方就是水龙头，接收方的缓冲区就是水桶，流量控制就是那声「开小点」。

后文用到的术语：

- **缓冲区**：接收方暂存还没被应用读走的数据的地方。
- **接收窗口**：缓冲区里还剩多少空位。
- **发送速率**：单位时间内发出去的数据量。

### 为什么发送方不能无限制地发
数据到达后先放进接收方的缓冲区，应用再慢慢读走。如果应用读得慢，而发送方一直猛发，缓冲区很快就满了。

满了之后新来的数据就被丢掉，发送方还得重传。这样既浪费网络，又拖慢速度。

### 流量控制怎么做
1. 接收方每次回确认，都把缓冲区还剩多少空位写进窗口字段。
2. 发送方看到窗口值，就知道最多还能发多少。
3. 发出一些数据后，发送方可用的窗口变小。
4. 应用读走数据后，接收方的空位变大，下次确认里窗口也跟着变大。

### 窗口为 0 怎么办
接收方缓冲区满了，会通知窗口为 0。发送方就暂停发送，并启动一个定时器，每隔一段时间发个小报文询问。等接收方有了空位，发送方就继续发送。

### 它和拥塞控制的区别
| 概念 | 保护谁 | 依据 |
|---|---|---|
| 流量控制 | 接收方 | 接收方告知的窗口 |
| 拥塞控制 | 中间的网络 | 发送方对网络状况的判断 |

结论：流量控制只管对方能不能收得下，网络堵不堵是拥塞控制的事。

## 易错点
- 以为流量控制由发送方自己判断；实际依据接收方告知的窗口
- 以为窗口为 0 后发送方就一直等；它会定时询问
- 把流量控制和拥塞控制混淆；前者保护接收方，后者保护网络

## 追问
### [f1] 窗口为 0 时，如果通知窗口恢复的报文丢了怎么办？
所以发送方要用定时器主动询问。不靠接收方主动通知，就不会因为那个通知丢失而一直卡住。
