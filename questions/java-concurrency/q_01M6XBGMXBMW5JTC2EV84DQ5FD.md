## 一句话
传统的 Java 线程（平台线程）和操作系统线程是一对一的：一个 Java 线程背后就是一个系统线程，由操作系统调度。Java 21 的虚拟线程则是多个虚拟线程共用少量系统线程。

## 要点
- [kp1|3] 平台线程与操作系统线程是 1:1 的关系，调用 start() 后由系统创建线程
- [kp2|3] 线程的调度由操作系统完成，Java 本身不负责
- [kp3|2] 系统线程创建和切换成本较高，所以不能无限制创建
- [kp4|2] Java 21 的虚拟线程由 JVM 调度，多个虚拟线程映射到少量平台线程上
- [kp5] 一个进程至少有一个线程，同一进程内的线程共享进程资源

## 详解
### 先搞懂：Java 线程是系统线程的“代理”
Java 程序本身不能直接让 CPU 干活，真正排队等 CPU 的是操作系统的线程。你 `new Thread()` 并 `start()` 之后，JVM 会请操作系统创建一个对应的系统线程来执行，就像你通过中介（JVM）去雇一个工人（系统线程）。

术语：
- **进程**：操作系统分配资源的基本单位，如一个运行中的应用；
- **线程**：进程内的一条执行路线，同一进程的线程共享内存；
- **平台线程**：传统的 Java 线程，和操作系统线程一一对应。

### 平台线程：一对一
1. 调用 `thread.start()`，JVM 请求操作系统创建一个线程；
2. 之后由操作系统决定它什么时候运行、运行多久；
3. 线程执行完，对应的系统线程也结束。

这种模式的好处是简单，能充分利用多核 CPU。代价是每个线程占用系统资源，创建和切换都有成本，所以数量不能太多。

### 方案对比：平台线程与虚拟线程
| 对比项 | 平台线程 | 虚拟线程（Java 21+） |
|---|---|---|
| 与系统线程关系 | 一对一 | 多个虚拟线程共用少量平台线程 |
| 调度者 | 操作系统 | JVM |
| 创建成本 | 较高 | 很低 |
| 适合场景 | 计算密集型 | 大量阻塞 IO 的任务 |

结论：计算密集型任务继续用平台线程池；大量等待 IO 的任务可以考虑虚拟线程。

## 易错点
- 以为 Java 线程由 JVM 自己调度；平台线程由操作系统调度
- 以为线程越多越快；线程多了切换开销增加，整体可能变慢
- 以为虚拟线程取代了所有线程；它适合阻塞 IO，计算密集型仍受 CPU 核数限制

## 追问
### [f1] 线程和进程有什么区别？
进程是资源分配的基本单位，拥有独立的内存空间；线程是进程内的执行单位，同一进程的线程共享内存，所以线程切换开销更小，但也要处理共享数据的并发安全问题。
