## 一句话
MSS 是一个 TCP 报文段最多能带的数据长度，建立连接时双方互相告知，之后发送和重传都按这个大小切块。

## 要点
- [kp1|3] MSS 只算数据部分，不含 TCP 首部和 IP 首部
- [kp2|3] 在三次握手的 SYN 报文里，双方通过选项告知各自能接收的 MSS
- [kp3|2] 数据按 MSS 切成多个报文段发送，重传也以这个单位
- [kp4] MSS 受链路最大传输单元限制，目的是避免 IP 层再分片

## 详解
### 先搞懂：寄快递的箱子有大小上限
你要寄一大堆东西，快递员说每个箱子最多装多少。你就把东西分装成若干箱寄出，哪个箱子丢了，只补寄那一箱。

TCP 发送大块数据也是这样，每个报文段是一个「箱子」，MSS 就是箱子里最多能装的数据量。

后文用到的术语：

- **报文段**：TCP 发送的一块数据，包含首部和数据。
- **MSS**：一个报文段里数据部分的最大长度。
- **MTU**：链路一次最多能传的包的大小，是网络层的限制。

### MSS 怎么约定
三次握手时，双方在 SYN 报文的选项里写上自己的 MSS，告诉对方「你发给我的报文段，数据部分别超过这个长度」。

发送时通常取两边的较小值，保证对方能接收，数据也不会超出链路的承载能力。

### 为什么要有 MSS
MSS 一般根据链路的 MTU 来定。如果 TCP 一次塞进太多数据，包超过链路的 MTU，IP 层就要把它拆成几片再发。拆片之后只要丢了一片，整个包都要重传。

所以 TCP 自己先把数据切成合适大小，让每个包到了 IP 层都不用再拆，也让重传的代价小一些。

### 发送和重传
应用交给 TCP 的数据不管多大，TCP 都会按 MSS 切成一个个报文段，每段带自己的序列号。某个报文段没被确认，就只重传那一段。

### MSS 和 MTU 的区别
| 概念 | 属于哪层 | 限制的是什么 |
|---|---|---|
| MSS | 传输层 TCP | 一个报文段的数据部分 |
| MTU | 链路层 | 一个 IP 包的总长度 |

结论：MSS 是 TCP 为了配合 MTU 而设的数据上限，所以它要比 MTU 小，留出首部的空间。

## 易错点
- 以为 MSS 包含首部；实际只算数据部分
- 以为 MSS 双方必须相同；两边各自告知，发送时取适合的值
- 把 MSS 和 MTU 混淆；MTU 是链路层的包长上限

## 追问
### [f1] 数据超过 MSS 会怎样？
应用交下来的数据会被 TCP 切分成多个报文段发送，每段不超过 MSS，接收方再按序列号拼回完整数据。
