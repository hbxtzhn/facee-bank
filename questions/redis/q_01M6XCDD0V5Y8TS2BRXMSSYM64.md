## 一句话
缓存预热是在系统上线或启动前，先把预先定好的热点数据加载进缓存，避免上线初期缓存是空的，大量请求直接打到数据库。

## 要点
- [kp1|3] 缓存预热：在对外服务之前，提前把数据写进缓存
- [kp2|3] 目的是避免刚上线时大量缓存未命中，请求全压到数据库
- [kp3|2] 适用于系统重启、新上线、大促活动开始前
- [kp4] 预热的数据通常是已知的热点，比如热门商品、首页配置

## 详解
### 先搞懂：冷启动的问题
你的网站平时靠 Redis 缓存商品信息，数据库只处理少量请求。某天 Redis 重启，里面的数据全没了。

这时用户来了，每个请求都读不到缓存，只能去查数据库。这种“读缓存没找到”叫**缓存未命中**。大量请求同时未命中，数据库可能直接被打垮。

可以类比饭店开业：如果开门前厨房什么都没备，第一批客人点菜要现杀现切，后厨会乱成一团。提前备好常用食材，开门就能顺畅出菜。这就是预热。

后文用到几个词：

- **缓存命中**：要找的数据在缓存里，直接返回。
- **缓存未命中**：缓存里没有，只能去数据库查。
- **冷启动**：缓存是空的，系统刚开始运行的状态。

### 什么时候需要预热
- 系统刚上线，缓存里还没有数据。
- Redis 重启或故障恢复后，数据丢失。
- 大促、秒杀等活动开始前，已知会有大量访问。

### 怎么做预热
- **启动时加载**：应用启动阶段，从数据库把热点数据查出来写入缓存，加载完再对外提供服务。
- **定时任务**：在活动开始前，用脚本或定时任务批量写入。
- **按访问记录**：根据历史访问数据，找出最常被访问的数据优先加载。

### 要注意什么
- 预热的数据量要可控，一次性读太多数据库也会有压力。
- 预热的数据也要设置合理的过期时间，避免同一时间全部过期。

## 示例
```java
// 应用启动完成后，把热门商品写入缓存
@PostConstruct
public void warmUp() {
    List<Product> hot = productDao.listHot(100);
    for (Product p : hot) {
        redis.opsForValue().set("product:" + p.getId(), toJson(p), Duration.ofHours(1));
    }
}
```

## 易错点
- 以为预热就是把整个数据库搬进缓存；只需要加载热点数据
- 预热的 key 过期时间都设成一样；到期时同时失效，可能引发缓存雪崩
- 预热还没完成就开放流量；起不到保护数据库的作用

## 追问
### [f1] 预热的数据怎么选？
优先选历史访问量高、变化少的数据，比如热门商品和首页配置。可以根据访问日志统计，也可以由运营提前指定活动商品。
