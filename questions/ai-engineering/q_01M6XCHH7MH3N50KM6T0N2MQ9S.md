## 一句话
工作记忆是当前任务的推理上下文，任务结束就失效；长期记忆跨会话保存个人经验；RAG 查的是外部知识库里的通用知识。

## 要点
- [kp1|3] 工作记忆装当前任务的上下文和进展，任务结束后失效
- [kp2|3] 长期记忆要持久化，跨会话保存，需要时再检索回来
- [kp3|2] RAG 的知识库是通用的外部资料，不属于某个用户的个人经历
- [kp4|2] 长期记忆沉淀的是个人化经验，如偏好和历史决策
- [kp5] 实现上都可能用检索，区别在于存什么、为谁服务

## 详解
### 先搞懂：办公桌、个人笔记本和图书馆
你在办公桌上摊开的文件是当前正在做的事，做完就收走，这是工作记忆。你随身的笔记本记着自己的习惯和做过的事，每次上班都带着，这是长期记忆。公司图书馆里放着各种参考书，谁都能查，这是 RAG 用的外部知识库。

后文用到的术语：
- **工作记忆**：当前任务的上下文和中间结果。
- **长期记忆**：跨会话保留下来的信息。
- **RAG**：先从知识库检索资料，再让模型据此回答。

### 工作记忆：当前任务的草稿纸
它包含用户这一轮的问题、已调用工具的结果、当前的推理进展。主要放在上下文里，随任务结束而丢弃。它的容量受上下文长度限制，所以需要及时精简。

### 长期记忆：跨会话的个人积累
它需要写到外部存储，才能在下次会话还在。内容和具体的用户或 Agent 有关，比如这个用户的偏好、以前解决过的类似问题。使用时按当前任务检索相关条目，放进工作记忆。

### RAG：通用知识的外部来源
RAG 的知识库通常是文档、手册、网页这类通用资料，不是 Agent 自己经历出来的。它回答的是「某件事是什么」，而长期记忆回答的是「这个用户是什么样、以前怎么做的」。

### 方案对比：三者的区别
| 对比点 | 工作记忆 | 长期记忆 | RAG 知识库 |
|---|---|---|---|
| 存什么 | 当前任务上下文 | 个人偏好、历史经验 | 通用文档资料 |
| 生命周期 | 任务结束即失效 | 跨会话保留 | 随资料更新而维护 |
| 是否个人化 | 是，但只在当下 | 是 | 通常不是 |
| 谁来写入 | 运行时自动产生 | Agent 提炼后写入 | 人工导入资料 |

结论：当前任务用工作记忆；要让 Agent 越用越懂你用长期记忆；需要权威的通用资料用 RAG。

### 进阶：三者怎么配合（基础薄弱可先跳过）
- 开始任务时，从长期记忆和 RAG 各检索一批内容，放进工作记忆。
- 任务结束时，挑出值得保留的结论写入长期记忆，其余随工作记忆丢弃。
- 检索技术可以相同，如向量检索，但写入和更新规则不同。

## 示例
```python
working = [user_message]                                  # 工作记忆
working += long_term.search(user_id, user_message)        # 取回个人经验
working += knowledge_base.search(user_message)            # RAG 取回通用知识
answer = llm(working)
long_term.save_if_useful(user_id, working, answer)        # 提炼后写回长期记忆
```

## 易错点
- 以为长期记忆就是 RAG；前者是个人经验，后者是通用知识库
- 以为工作记忆可以无限增长；它受上下文长度限制
- 以为用了向量检索就是 RAG；长期记忆也可能用向量检索，区别在内容的性质

## 追问
### [f1] 任务结束后，工作记忆里哪些内容该存入长期记忆？
有长期价值的：用户明确表达的偏好、关键决策及理由、有效的解决办法。中间过程和临时数据一般不存。

### [f2] 长期记忆和 RAG 能用同一个向量库吗？
技术上可以，但建议分开命名空间管理，因为它们的更新方式和权限不同，混在一起容易污染。
