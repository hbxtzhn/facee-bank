## 一句话
核心线程数是线程池长期保留的线程数量，空闲也默认不回收；最大线程数是线程总数的上限，队列满了才会扩展到这个数。

## 要点
- [kp1|3] 核心线程数 corePoolSize：长期保留的线程数，空闲时默认也不回收
- [kp2|3] 最大线程数 maximumPoolSize：核心线程加非核心线程的总数上限
- [kp3|2] 线程池先建核心线程，队列满了才创建非核心线程
- [kp4] 最大线程数必须大于等于核心线程数，否则构造时报错

## 详解
### 先搞懂：正式工和临时工
店里平时固定雇几个正式员工，忙季再招一些临时工，但店面只能容纳一定人数，总人数不能超过上限。

线程池的核心线程就是正式员工，最大线程数就是总人数上限，两者之差就是最多能临时招的人数。后文术语：

- **核心线程**：池里常驻的线程。
- **非核心线程**：核心线程不够用时临时加的线程，闲下来会被回收。

### 核心线程数：常驻的人手
`corePoolSize` 定义了池中保持的线程数量。线程数没到这个数时，每来一个任务就新建一个核心线程。这些线程即使空闲也不会被回收，随时等着接任务。

如果想让它们空闲时也被回收，可以调用 `allowCoreThreadTimeOut(true)`，前提是设置了大于 0 的存活时间。

### 最大线程数：临时扩容的天花板
`maximumPoolSize` 规定池里线程总数的上限，包括核心和非核心线程。核心线程忙着、队列也满了，新任务才会促使线程池创建非核心线程，最多到这个数。

所以最大线程数起作用的前提是队列有上限。用了无界队列，队列永远不会满，最大线程数就形同虚设。

### 两者怎么搭配
- 核心数等于最大数：线程数固定，不会扩缩。
- 核心数小于最大数：平时少用线程，高峰扩容，闲时回收。

具体取值没有统一公式，要按任务是计算型还是等待型，并通过压测确定。

## 示例
```java
ThreadPoolExecutor pool = new ThreadPoolExecutor(
        2,   // corePoolSize：常驻 2 个线程
        5,   // maximumPoolSize：最多 5 个线程
        30, TimeUnit.SECONDS,
        new ArrayBlockingQueue<>(10));
```

## 易错点
- 以为线程数先涨到最大再排队；实际先建核心线程、再排队，队列满了才扩
- 以为核心线程永远不会被回收；设置 `allowCoreThreadTimeOut(true)` 后会
- 把最大线程数设得小于核心数；构造器会抛出 `IllegalArgumentException`

## 追问
### [f1] 核心线程是不是一开始就创建好？
默认不是，任务到来时才创建。想提前创建，可以调用 `prestartAllCoreThreads()`。

### [f2] 最大线程数设得很大有什么问题？
线程太多会占用大量内存，CPU 切换也更频繁，反而变慢。所以要设定合理上限，并配合有界队列。
