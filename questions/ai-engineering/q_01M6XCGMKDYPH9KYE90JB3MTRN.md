## 一句话
MRR 对每个查询取第一个相关结果排名的倒数，再对所有查询求平均。第一个相关结果排得越靠前，MRR 越高，最大是 1。

## 要点
- [kp1|3] 单个查询得分 = 1 / 第一个相关结果的排名，排第 1 得 1 分
- [kp2|3] MRR 是所有查询得分的平均值，只看第一个相关结果
- [kp3|2] 前 K 条里没有相关结果时，这个查询记 0 分
- [kp4] MRR 不看第二个及以后的相关结果，也不衡量找回了多少

## 详解
### 先搞懂：用户通常只看最上面那几条
你用过搜索引擎：答案排在第 1 条，一眼就能看到；排在第 10 条，很多人就不看了。检索系统也一样，大模型的上下文有限，排在前面的文档更重要。

可以把它想成找人问路：第一个问到的人就知道路，最省事；问到第五个才知道，就折腾多了。MRR 要衡量的，就是「第几次才问对人」。

后文用到几个术语：
- **排名（rank）**：检索结果从高分到低分排列后的名次，第 1 条名次为 1。
- **倒数排名**：名次取倒数，名次 1 得 1，名次 2 得二分之一，名次 4 得四分之一。
- **MRR**：Mean Reciprocal Rank，平均倒数排名。

### 怎么算：先给每个查询打分，再求平均
计算分三步：

1. 对每个查询，找出结果列表里第一个相关文档的名次。
2. 取这个名次的倒数，作为这个查询的得分。
3. 把所有查询的得分加起来，除以查询总数。

比如有 3 个查询：第一个查询的相关文档排第 1，得 1；第二个排第 2，得 0.5；第三个排第 4，得 0.25。三个得分相加是 1.75，除以 3，MRR 约为 0.58。

如果某个查询的结果里一个相关文档也没有，通常记 0 分。

### 为什么用倒数：越靠前，差距越大
倒数让名次越靠前，价值掉得越快：

- 从第 1 名掉到第 2 名，得分从 1 降到 0.5，掉了一半。
- 从第 4 名掉到第 5 名，得分只从 0.25 降到 0.2。

这符合直觉：用户最在意答案是不是在最前面，靠后之后差几名，感受差别很小。

### 它看什么、不看什么
MRR 只关心第一个相关结果的位置，所以有两点要注意：

- 第二个、第三个相关文档排在哪，MRR 完全不管。
- 它不关心找回了多少相关文档，这是召回率的任务。

所以 MRR 适合「只要一个好答案」的场景，比如问答、单条事实查询。如果答案需要综合多篇文档，就要配合召回率，或者用考虑所有相关结果位置的指标，比如 NDCG。

### 方案对比：命中率、召回率和 MRR
| 指标 | 看什么 | 看不看排名 | 适合回答的问题 |
|---|---|---|---|
| 命中率 | 前 K 条里有没有相关文档 | 不看 | 用户至少能不能拿到一条有用的 |
| 召回率 | 相关文档找回了多大比例 | 不看 | 该找的资料有没有找全 |
| MRR | 第一个相关文档排多靠前 | 看，只看第一个 | 最好的那条是不是排在最前面 |

结论：评估检索时，命中率和召回率看「找没找到」，MRR 看「排得好不好」，实际常放在一起用。

## 示例
```python
def mrr(results, relevant):
    # results: 每个查询的检索结果 id 列表；relevant: 每个查询的相关文档 id 集合
    total = 0.0
    for docs, rel in zip(results, relevant):
        for rank, d in enumerate(docs, start=1):
            if d in rel:
                total += 1 / rank
                break
    return total / len(results)
```

## 易错点
- 以为 MRR 衡量找回了多少相关文档；它只看第一个相关结果的位置
- 以为第二个相关结果排得好也能抬高 MRR；它对第一个之后的结果不起作用
- 忘了没命中的查询要记 0 分；漏掉它们会让 MRR 偏高

## 追问
### [f1] MRR 高，召回率一定高吗？
不一定。MRR 高只说明第一个相关文档排得靠前，但相关文档可能一共有很多篇，只找回了一两篇，召回率仍然很低。

### [f2] 为什么不直接用第一个相关结果的名次求平均？
名次平均会被个别排得很靠后的查询拉得很大，而且名次越大越好，不直观。取倒数后得分落在 0 到 1 之间，越大越好，也更突出靠前名次的差别。
