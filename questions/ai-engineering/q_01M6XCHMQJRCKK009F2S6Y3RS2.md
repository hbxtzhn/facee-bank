## 一句话
RAG 分离线和在线两段：离线把文档清洗、切分、向量化后存入向量库；在线把问题改写、检索、重排、拼上下文，最后交给 LLM 生成答案。

## 要点
- [kp1|3] 离线阶段：清洗、切分、向量化，再存入向量数据库
- [kp2|3] 在线阶段：查询改写、相似度检索、重排序、构建上下文、生成
- [kp3|2] 切分是把长文档拆成适合检索的小片段
- [kp4] 重排序是对检索出的候选片段再精排

## 详解
### 先搞懂：像图书馆的编目和借阅
图书馆先要给每本书整理、分类、编目，放上书架，这是准备工作。读者来了提出需求，管理员在目录里找出相关书，挑出最合适的几本，交给读者阅读后回答。

RAG 也分这两段。下面是后文要用的术语：

- **切分（Chunking）**：把长文档拆成较小的片段。
- **向量化（Embedding）**：把文字变成一串数字，用来表示含义。
- **向量数据库**：存放向量，并能按相似度查找的数据库。
- **重排序（Rerank）**：对初步检索的结果重新打分排序。

### 离线阶段：建索引
1. **清洗文档**：去掉乱码、页眉页脚等无用内容。
2. **切分**：拆成大小合适的片段，太长检索不准，太短缺上下文。
3. **向量化**：用嵌入模型把每个片段变成向量。
4. **入库**：存进向量数据库，建立可检索的结构。

这个阶段在用户提问之前就做好，知识更新时再补充。

### 在线阶段：回答问题
1. **查询改写**：把用户的问题改写得更适合检索，如补全指代、拆成子问题。
2. **相似度检索**：把问题也向量化，找出最相似的若干片段。
3. **重排序与过滤**：对候选片段精细打分，去掉不相关的，留下最好的几个。
4. **构建上下文**：把问题和选中的片段拼成给模型的输入。
5. **生成答案**：模型依据上下文回答。

### 为什么要分两段
文档处理耗时，提前做完，用户提问时就只需要做快速的检索，响应更快。

## 示例
```text
离线：文档 -> 清洗 -> 切分 -> 向量化 -> 向量库
在线：问题 -> 改写 -> 检索 -> 重排序 -> 拼上下文 -> 模型生成
```

## 易错点
- 以为每次提问都要重新处理文档；文档处理在离线阶段已经完成
- 忽略切分大小；片段太长或太短都会让检索效果变差
- 认为检索出来的片段就一定相关；所以需要重排序和过滤

## 追问
### [f1] 为什么检索之后还要重排序？
向量检索速度快，但排序不够精细。重排序用更精确的方法对少量候选重新打分，把真正相关的排到前面，成本也可控。
