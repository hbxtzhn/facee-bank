## 一句话
HTTPS 就是在 HTTP 下面加了一层 TLS 加密，让通信内容加密、能确认服务器身份，并且不被中途篡改。

## 要点
- [kp1|3] HTTPS 是 HTTP 加上 TLS/SSL 加密层，不是新的应用协议
- [kp2|3] 它提供三种保护：内容加密、身份验证、完整性校验
- [kp3|2] 服务器用数字证书证明自己的身份
- [kp4] 内容用对称加密传输，对称密钥在握手中协商

## 详解
### 先搞懂：明信片和密封挂号信
HTTP 像明信片：邮递员、中转站的人都能看到你写了什么，甚至改几个字再送出去。HTTPS 像密封的挂号信：内容别人看不到，还要核对收件人身份，信被拆过会被发现。

几个词：

- **TLS/SSL**：给通信加密的协议，HTTPS 里的“S”指它。
- **证书**：权威机构发的凭证，证明服务器的身份。
- **会话密钥**：这次通信用来加密内容的密钥。

### HTTP 的问题
HTTP 是明文传输，会带来三个风险：

- **窃听**：别人能看到密码、手机号等内容；
- **冒充**：别人可以伪装成目标网站；
- **篡改**：内容在路上被修改，双方都不知道。

### HTTPS 怎么解决
HTTPS 在 HTTP 和 TCP 之间插入 TLS 层，HTTP 内容先加密再交给 TCP：

1. **加密**：内容用会话密钥加密，中途截获的人看到的只是乱码；
2. **身份验证**：服务器出示证书，客户端验证它，确认连的是真网站；
3. **完整性**：数据带校验，被改动就能发现。

### 它的工作大致流程
客户端先和服务器握手：服务器发来证书，客户端验证通过后，双方协商出会话密钥。之后所有 HTTP 内容都用这个密钥加密传输。握手的细节见 HTTPS 握手流程那道题。

### 它不能做什么
HTTPS 保护的是传输过程。网站本身有漏洞，或者服务器上的数据被泄漏，HTTPS 管不了。它也不能证明网站是“好”的，只能证明你连到的是证书里写的那个域名。

## 易错点
- 以为 HTTPS 是和 HTTP 完全不同的协议；它是 HTTP 加 TLS
- 以为用了 HTTPS 网站就安全；它只保护传输过程
- 以为 HTTPS 全程使用非对称加密；内容用的是对称加密

## 追问
### [f1] HTTPS 为什么不全程用非对称加密？
非对称加密计算较慢，不适合加密大量数据。HTTPS 用它协商密钥，之后用更快的对称加密传内容。
