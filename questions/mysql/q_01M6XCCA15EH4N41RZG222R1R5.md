## 一句话
按功能分，MySQL 常见索引有主键索引、唯一索引、普通索引和全文索引；主键索引要求非空且唯一，唯一索引保证值不重复，普通索引只加速查询。

## 要点
- [kp1|3] 主键索引：唯一标识一行，列值必须唯一且不能为空，一张表只能有一个
- [kp2|3] 唯一索引：保证列值不重复，允许有 NULL，一张表可以有多个
- [kp3|2] 普通索引：最基本的索引，没有唯一性要求，只用来加速查询
- [kp4] 全文索引：用于文本内容的关键词搜索

## 详解
### 先搞懂：身份证号、手机号和姓名
想想一个用户表里的几个字段：

- 用户 ID：每人一个，不能为空，不能重复，用来唯一确定一个人；
- 手机号：一般不能重复，但有人可能没填；
- 姓名：可以重名，但经常按姓名查询；
- 个人简介：一大段文字，想按里面的词搜索。

四种场景，对应四种索引。

后文用到的术语：

- **唯一**：同一列里不会出现两个相同的值；
- **非空**：这一列必须有值。

### 主键索引
给主键列建立的索引。主键要求列值唯一且非空，一张表只能有一个主键。InnoDB 里，数据就是按主键组织存放的。

### 唯一索引
保证列值不重复。和主键的区别是：它允许值为 `NULL`，一张表可以建多个唯一索引。适合手机号、邮箱这类需要不重复的字段。

### 普通索引
最基本的索引，没有唯一或非空的约束，只是为了让查询更快。适合姓名这样可能重复、又经常用来查询的字段。

### 全文索引
用在文本类型的列上，用来做关键词搜索，比 `LIKE '%词%'` 更合适。比如在文章内容里搜索某个词。

## 示例
```sql
CREATE TABLE t_user (
    id BIGINT PRIMARY KEY,
    phone VARCHAR(20),
    name VARCHAR(50),
    intro TEXT,
    UNIQUE KEY uk_phone (phone),
    KEY idx_name (name),
    FULLTEXT KEY ft_intro (intro)
);
```

## 易错点
- 把唯一索引和主键索引混为一谈；主键不能为空，唯一索引的列可以有 `NULL`
- 以为一张表可以有多个主键；主键只能有一个
- 以为唯一索引不能加速查询；它同样是索引，既能保证唯一又能加速查询

## 追问
### [f1] 主键索引和唯一索引能不能同时存在？
可以。一张表有一个主键索引，同时还可以有多个唯一索引，各自约束不同的列。

### [f2] 还有按列数分的索引吗？
有。只包含一列的叫单列索引，包含多列的叫联合索引，也叫复合索引。
