## 一句话
多级缓存是把本地缓存、Redis 等多层缓存串起来，一层失效时下一层还能接住请求，从而降低大面积失效时数据库的压力。

## 要点
- [kp1|3] 多级缓存：请求依次查本地缓存、Redis，最后才查数据库
- [kp2|3] 某一层大面积失效或宕机，其他层仍能承接请求
- [kp3|2] 本地缓存在应用进程内，速度最快，但容量小、各实例独立
- [kp4|2] 多层缓存会带来一致性问题，更新时要同步处理各层
- [kp5] 本地缓存的 TTL 通常设得比 Redis 短

## 详解
### 先搞懂：家里的冰箱、小区超市和大仓库
想吃零食，先翻自家桌上，没有再去小区便利店，再没有才去远处的大仓库。离得越近越快，但存得越少。层层兜底，大仓库就不用天天被敲门。

多级缓存就是这个思路：第一层是应用进程里的本地缓存，第二层是 Redis，最后才是数据库。

后文用到的术语：

- **本地缓存**：数据放在应用自己的内存里，如 Caffeine，不走网络。
- **分布式缓存**：Redis 这类独立服务，多个应用实例共享。
- **回源**：上层没有，转去下一层或数据库查。

### 请求怎么走
读请求依次经过：

1. 查本地缓存，命中直接返回。
2. 未命中查 Redis，命中就返回，并可以顺手回填本地缓存。
3. 仍未命中才查数据库，再依次写回 Redis 和本地缓存。

大部分请求在前两层就被消化了，数据库只处理极少数。

### 为什么能缓解雪崩
雪崩的核心是缓存层突然失效，请求涌向数据库。有了多级缓存：

- Redis 大批 key 过期或短暂宕机时，本地缓存里还有一部分数据，能挡掉一部分请求。
- 本地缓存和 Redis 的过期时间可以不一样，失效时间错开，不容易同时失效。
- 本地缓存是每个应用实例独立持有的，一个实例的缓存失效，不影响其他实例。

### 代价：多一层就多一份一致性麻烦
- 数据被修改时，要同时处理本地缓存和 Redis，否则会读到旧值。
- 本地缓存存在每个实例里，一个实例修改后，其他实例的本地缓存不会自动更新。常见做法是用较短的过期时间，或通过消息通知各实例清理。
- 本地缓存占用应用内存，容量要控制。

所以多级缓存适合读多写少、对短暂不一致不敏感的数据。

## 易错点
- 以为本地缓存能无限存；它占用应用堆内存，要限制容量
- 更新时只改 Redis；其他实例的本地缓存仍是旧值
- 以为多级缓存能完全防雪崩；它只是降低概率，仍要配合限流等手段

## 追问
### [f1] 本地缓存在多实例下怎么保持一致？
最简单的做法是给本地缓存设较短的过期时间，容忍短暂不一致。要求更高时，数据变更后通过消息队列或 Redis 发布订阅通知各实例清除本地缓存。
