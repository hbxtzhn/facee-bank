## 一句话
深拷贝不仅复制对象本身，还把它引用的内部对象也逐层复制一份，所以修改副本不会影响原对象。

## 要点
- [kp1|3] 深拷贝连引用成员指向的对象也复制一份
- [kp2|3] 副本和原对象完全独立，各改各的互不影响
- [kp3|2] 引用成员本身还有引用成员时，要一层层复制下去
- [kp4] 实现方式有重写 clone()、拷贝构造器、序列化再反序列化
- [kp5] 代价是代码更繁琐，复制的对象多、更占内存

## 详解
### 先搞懂：不只复印订单，连仓库资料也复印
还是订单和地址的场景：订单里的“地址”栏只写着一个门牌号，真正的地址资料在仓库里。

- 浅拷贝：复印订单，门牌号照抄，两张订单指向同一份地址资料；
- 深拷贝：复印订单，同时到仓库把地址资料也复印一份，新订单写新门牌号。

这样，谁改自己的地址资料，另一个都不受影响。

后文用到的词：

- **引用成员**：对象里指向别的对象的字段，保存的是地址。
- **逐层复制**：引用成员里还有引用成员时，一层层都复制，直到全是基本类型或不可变对象。

### 深拷贝：每一层都复制
深拷贝的做法是：

1. 新建副本对象；
2. 基本类型成员，直接复制值；
3. 引用类型成员，不照抄地址，而是新建一个对象，再把里面的内容复制进去；如果这个成员内部还有引用成员，同样处理。

结果是副本和原对象在内存里没有任何共用的可变对象。

### 效果与代价
效果：修改副本里的任何东西，原对象都不会变，反过来也一样。需要“拿一份快照来随便改”的场景，就用深拷贝。

代价有两点：

- 写起来麻烦，每个引用成员都要处理，类的结构改了，拷贝代码也要跟着改；
- 对象层次深、数量多时，复制耗时更久、占用的内存也更多。

不可变对象（如 String）不需要真的复制，共用同一个也不会出问题，所以深拷贝时通常直接复用。

## 示例
```java
class Address {
    String city;
    Address(Address other) { this.city = other.city; }
}
class Order {
    int amount;
    Address address;
    Order(Order other) {            // 拷贝构造器，写成深拷贝
        this.amount = other.amount;
        this.address = new Address(other.address);
    }
}
```

## 易错点
- 只复制了外层对象，以为就是深拷贝；引用成员没有新建，那仍然是浅拷贝
- 对集合只调用 `new ArrayList<>(list)`，以为元素也被复制了；这只复制了列表本身，元素仍是同一批对象
- 对每层都要复制，漏掉其中一层，那一层仍然被共享

## 追问
### [f1] 深拷贝一定比浅拷贝好吗？
不是。深拷贝更独立、更安全，但写起来麻烦，也更占内存。对象只含基本类型或不可变成员时，浅拷贝足够，没必要深拷贝。
