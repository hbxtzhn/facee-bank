## 一句话
缓存穿透是请求的数据在缓存和数据库里都不存在，缓存永远命不中，每次请求都穿过缓存直接打到数据库。

## 要点
- [kp1|3] 穿透针对的是不存在的数据，缓存和数据库里都没有
- [kp2|3] 缓存永远命不中，每次请求都落到数据库上
- [kp3|2] 常见原因：恶意攻击、乱填的参数、数据被误删
- [kp4] 常用对策：缓存空值、布隆过滤器、接口参数校验

## 详解
### 先搞懂：查一个根本不存在的商品
商品页的请求先查缓存，缓存没有再查数据库，然后把结果放进缓存。正常商品第二次起就能命中缓存。但如果有人一直查一个不存在的商品编号，数据库查不到，缓存里也就没东西可放，下次还是查数据库。请求量一大，数据库就被这些“无效请求”压垮了。

后文用到的词：
- **缓存命中**：想要的数据正好在缓存里。
- **穿透**：请求绕过缓存直接到达数据库。

### 为什么会穿透
典型的缓存逻辑是：

1. 先查缓存，命中就直接返回；
2. 没命中，查数据库；
3. 数据库查到了，写入缓存。

问题出在第 3 步：数据库里没有，就没有东西可以写入缓存，所以下一次请求还会重复第 2 步。

### 可能的来源
- 攻击者故意用大量不存在的 ID 请求；
- 前端或调用方传了错误的参数；
- 数据被删除后，仍然有人在访问。

### 怎么防
- **参数校验**：非法 ID（比如负数、格式不对）在接口层直接拒绝；
- **缓存空值**：数据库查不到，也在缓存里存一个空结果，设置较短过期时间；
- **布隆过滤器**：把所有存在的 ID 放进布隆过滤器，不存在的请求在过滤器处直接拦截；
- **限流**：对异常高频的来源限速。

具体的做法在后续题目里展开。

## 易错点
- 把穿透和击穿混为一谈；穿透是数据根本不存在，击穿是热点数据恰好过期
- 以为缓存里没有就会被写入缓存；数据库也没有时，默认没有东西可写
- 以为只有攻击才会穿透；业务里的错误参数也会引起

## 追问
### [f1] 穿透、击穿、雪崩有什么区别？
穿透：查的数据不存在。击穿：一个热点 key 过期，大量请求同时打到数据库。雪崩：大量 key 同时过期，或缓存整体不可用。
