## 一句话
死锁是多个线程各自拿着对方需要的锁，又都在等对方先放手，结果谁也无法继续往下执行。

## 要点
- [kp1|3] 死锁时，几个线程互相等待对方持有的锁，永远不会自己结束
- [kp2|3] 典型情形：线程 A 持锁 1 等锁 2，线程 B 持锁 2 等锁 1
- [kp3|2] 产生死锁要同时满足互斥、持有并等待、不可剥夺、循环等待四个条件
- [kp4] 死锁不会抛异常，表现为程序卡住，线程一直处于阻塞状态

## 详解
### 先搞懂：两个人在窄路上互不相让
想象转账：把钱从账户 A 转到账户 B，需要先锁住 A，再锁住 B。如果同时还有一笔从 B 转到 A 的操作，它会先锁 B，再锁 A。

- 第一个线程锁住了 A，正在等 B；
- 第二个线程锁住了 B，正在等 A。

就像两个人在独木桥中间碰面，各自都不肯后退，谁也过不去。这就是死锁。

后文用到的词：
- **锁**：保证同一时刻只有一个线程能执行某段代码的机制。
- **阻塞**：线程拿不到锁，停下来等。
- **死锁**：一组线程互相等待，永远等不到。

### 死锁是怎么发生的
按时间顺序看：

1. 线程 A 拿到锁 1；
2. 线程 B 拿到锁 2；
3. 线程 A 想拿锁 2，被占用，只能等；
4. 线程 B 想拿锁 1，被占用，只能等。

这时 A 等 B 释放，B 也等 A 释放，没人能先放手。因为线程在等锁的时候不会主动释放已经拿到的锁，也没人能强行把锁抢走，程序就卡住了。

### 产生死锁的四个条件
四个条件必须同时满足才会死锁，破坏任意一个就不会死锁：

1. **互斥**：一把锁同一时刻只能被一个线程持有。
2. **持有并等待**：线程拿着一把锁，同时去申请另一把。
3. **不可剥夺**：线程拿到的锁只能自己释放，别人不能强行抢走。
4. **循环等待**：线程之间形成一个环，A 等 B，B 等 A（也可以是更多线程围成一圈）。

### 死锁有什么表现
程序没有报错，但某些请求一直不返回，线程数不下降，CPU 也不高。可以用 `jstack` 查看线程栈，它会直接提示发现 Java 级别的死锁，并列出相互等待的线程和锁。

## 示例
```java
Object lock1 = new Object();
Object lock2 = new Object();

new Thread(() -> {
    synchronized (lock1) {
        sleep(100);                 // 给另一个线程留出时间拿 lock2
        synchronized (lock2) { System.out.println("A"); }
    }
}).start();

new Thread(() -> {
    synchronized (lock2) {
        sleep(100);
        synchronized (lock1) { System.out.println("B"); }
    }
}).start();
// 两个线程各持一把锁，互相等待，程序卡住（sleep 为自定义的休眠辅助方法）
```

## 易错点
- 以为死锁一定要两把锁；多个线程围成一圈互相等待也是死锁
- 以为死锁会抛异常；它只会让程序一直卡住，需要靠线程栈排查
- 把「线程等得很久」当成死锁；死锁是永远等不到，等待时间长只是慢

## 追问
### [f1] 怎么发现线程死锁？
用 `jstack <pid>` 导出线程栈，末尾会报告 Found one Java-level deadlock 并列出相关线程；也可以用 jconsole、VisualVM 等工具的线程面板检测。

### [f2] 数据库也会死锁吗？
会。两个事务各自锁住一些行，又去申请对方持有的行锁，就形成死锁。数据库通常能检测到并回滚其中一个事务，应用要准备好重试。
