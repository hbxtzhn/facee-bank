## 一句话
哈希槽是 Redis 集群把数据分成的 16384 个固定格子，key 经 CRC16 计算后对 16384 取余得到槽号，每个节点负责其中一部分槽。

## 要点
- [kp1|3] Redis 集群固定有 16384 个槽，编号 0 到 16383
- [kp2|3] 槽号等于 key 的 CRC16 值对 16384 取余
- [kp3|2] 每个主节点负责一段槽，槽归谁，数据就在谁那里
- [kp4|2] 槽可以整体从一个节点迁移到另一个节点，用于扩缩容
- [kp5] 哈希标签 `{}` 让不同的 key 落进同一个槽

## 详解
### 先搞懂：邮局的分拣格
想象一个邮局有 16384 个分拣格，每封信按地址算出该进哪个格子，格子有固定编号。邮局里有几位分拣员，每人管一段编号的格子。信进哪个格子由地址决定，不会变；格子归哪个分拣员，可以调整。

这样信和分拣员之间隔着一层“格子”，换人只需要换格子的归属，不必重新分拣所有信。哈希槽就是这层格子。

后文用到的词：

- **CRC16**：一种把任意字符串变成数字的计算方法。
- **取余**：用这个数字除以 16384，余数就是槽号。

### 槽号是怎么来的
`槽号 = CRC16(key) % 16384`

同一个 key 每次算出来的槽号都一样，所以读写总能找到同一个地方。

### 节点怎么分槽
假设 3 个主节点，可以均分：

- 节点 A：0 到 5460
- 节点 B：5461 到 10922
- 节点 C：10923 到 16383

每个节点只保存自己槽里的数据。创建集群时，槽会被分配给各节点；之后也可以手动调整。

### 为什么要多这一层
数据直接对应节点，节点一变（扩容、缩容），映射就全乱了。数据先对应槽，槽再对应节点：槽的数量永远不变，增减节点时只需要把某些槽搬到别的节点上。

### 哈希标签
`user:{1001}:cart` 和 `user:{1001}:order` 这样的 key，只用大括号里的 `1001` 计算槽号，所以两个 key 一定在同一个槽里，可以一起用多 key 命令。

## 示例
```bash
# 查看某个 key 属于哪个槽
redis-cli -c CLUSTER KEYSLOT user:1001
# 查看槽在节点间的分布
redis-cli -c CLUSTER SLOTS
```

## 易错点
- 以为槽数量会随节点数变化；槽固定是 16384，变的是槽的归属
- 以为每个 key 单独记录归属；集群只记录槽归属，key 靠计算定位
- 以为槽是物理存储单元；它只是逻辑上的分区编号

## 追问
### [f1] 如何让两个 key 落在同一个槽？
用哈希标签：把共同的部分放进 `{}`，比如 `{order:1}:info` 和 `{order:1}:items`，只对大括号内的内容算槽，所以两个 key 落在同一个槽。
