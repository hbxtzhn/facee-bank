## 一句话
事务是一组要么全部成功、要么全部失败的操作，有原子性、一致性、隔离性、持久性四个特性，简称 ACID。

## 要点
- [kp1|3] 事务：一组操作，要么全部提交，要么全部回滚
- [kp2|3] 原子性：事务不会只执行一半
- [kp3|2] 一致性：事务前后，数据都满足业务规则
- [kp4|2] 隔离性：并发的事务互不干扰；持久性：提交后修改不丢
- [kp5] InnoDB 用 undo log、redo log、锁和 MVCC 来实现

## 详解
### 先搞懂：转账为什么需要事务
A 给 B 转 100 元，需要两步：A 的账户减 100，B 的账户加 100。

如果第一步成功、第二步失败（比如服务器崩了），A 的钱没了，B 也没收到。这是不能接受的。我们希望这两步要么都成功，要么都不发生，这就是事务。

类比：银行柜台办业务，要么整笔办完盖章，要么整笔作废，不能办到一半把单子留在桌上。

后文会用到这几个词：

- **提交（commit）**：事务成功结束，修改正式生效。
- **回滚（rollback）**：事务撤销，所有修改恢复到事务开始前。
- **ACID**：四个特性英文首字母的组合。

### 原子性（Atomicity）：全做或全不做
事务里的所有操作是一个整体，不会只执行一部分。转账中任何一步出错，已经做过的修改都要撤销。InnoDB 靠 **undo log** 保存修改前的旧值，回滚时按它恢复。

### 一致性（Consistency）：从合法状态到合法状态
事务执行前后，数据都要满足业务规则。转账前后，A 和 B 的总金额不变。

一致性和业务规则有关，数据库提供约束（主键、唯一、外键等）帮忙，但最终要靠原子性、隔离性、持久性，加上业务代码一起保证。

### 隔离性（Isolation）：并发的事务别互相干扰
多个事务同时操作同样的数据时，每个事务看起来像是在独立执行。InnoDB 靠**锁**和 **MVCC**（多版本并发控制）实现，并通过隔离级别决定隔离到什么程度。

### 持久性（Durability）：提交了就不会丢
事务一旦提交，修改就永久保存，即使随后数据库崩溃，重启后数据也还在。InnoDB 靠 **redo log**：提交时先保证日志写到磁盘，崩溃后可以按日志把修改重放回来。

## 示例
```sql
START TRANSACTION;
UPDATE account SET balance = balance - 100 WHERE id = 1;
UPDATE account SET balance = balance + 100 WHERE id = 2;
COMMIT;      -- 出错时执行 ROLLBACK;
```

## 易错点
- 以为一致性完全由数据库保证；它还依赖业务规则和代码
- 以为隔离性等于完全串行；实际有多个隔离级别，可以按需要选择
- 以为只要写了多条 SQL 就是事务；自动提交模式下，每条语句各自是一个事务
- 把原子性理解成「速度快」，其实是「不可拆分」

## 追问
### [f1] 四个特性分别靠什么实现？
原子性靠 undo log，持久性靠 redo log，隔离性靠锁和 MVCC。一致性是前面几项加上约束和业务逻辑共同的结果。

### [f2] 自动提交是什么意思？
默认每条语句执行完自动提交，相当于每条语句各是一个事务。想把多条语句放进同一个事务，要显式 `START TRANSACTION`，并用 `COMMIT` 或 `ROLLBACK` 结束。
