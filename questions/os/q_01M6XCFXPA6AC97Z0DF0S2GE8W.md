## 一句话
文件描述符是进程打开文件或 socket 后拿到的一个整数编号，内核靠这个编号找到对应的资源。

## 要点
- [kp1|3] 文件描述符是一个非负整数，代表进程已打开的文件或 socket
- [kp2|3] 进程用它来调用 read、write、close 等，不直接接触内核对象
- [kp3|2] 每个进程有自己的描述符表，同一个数字在不同进程里指向不同资源
- [kp4|2] Linux 里一切皆文件，普通文件、socket、管道都用 fd 表示
- [kp5] 默认 0、1、2 分别是标准输入、标准输出、标准错误

## 详解
### 先搞懂：餐厅的取餐号
你在餐厅点餐，拿到一个号码。之后取餐只要报号码，不用说点了什么、厨房在哪。文件描述符就是这个号码：进程拿到号码，就能让内核做事。

后文会用到几个词：

- **文件描述符（fd）**：内核给进程的一个整数句柄。
- **描述符表**：每个进程里，记录 fd 对应哪个资源的表。
- **一切皆文件**：Linux 把很多资源都用文件的方式来操作。

### 怎么工作
进程调用 `open` 打开文件，或用 `socket`、`accept` 建立网络连接，内核会创建对应的内部对象，并在进程的描述符表里加一条记录，把最小的可用编号返回给进程。

以后进程调用 `read(fd, ...)` 或 `write(fd, ...)`，内核按这个编号在表里找到真正的文件或连接。用完调用 `close(fd)`，编号被释放。

### 为什么用整数句柄
进程不能直接访问内核里的对象，通过一个整数句柄，内核既可以控制访问，又隐藏了内部细节。这也让文件、socket、管道可以用同样的接口操作。

### 和多路复用的关系
select、poll、epoll 监视的就是一组文件描述符。服务器每个连接占用一个 fd，所以能打开的 fd 数量会限制连接数量。

## 示例
```bash
ulimit -n            # 查看当前进程最多能打开的文件描述符数
ls -l /proc/self/fd  # 查看当前进程已打开的文件描述符
```

## 易错点
- 打开后忘了关闭，描述符会一直占用，最终出现 too many open files
- 以为 fd 全局唯一；它只在进程内有意义
- 以为 fd 只和普通文件有关；socket 和管道也用它

## 追问
### [f1] 出现 too many open files 怎么办？
先检查是否有 fd 泄漏，用 `lsof` 看打开了什么；确实需要时再调大 `ulimit -n` 的限制。
