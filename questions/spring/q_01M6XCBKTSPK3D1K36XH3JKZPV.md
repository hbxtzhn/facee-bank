## 一句话
`#{}` 会被换成 JDBC 的 `?` 占位符，参数值再通过预编译方式设进去，自动转义，能防 SQL 注入，是最常用的参数写法。

## 要点
- [kp1|3] 解析 SQL 时，`#{}` 被替换成 `?` 占位符
- [kp2|3] 执行时把参数值设到对应的 `?` 位置，值只当数据
- [kp3|2] 字符串参数会被正确转义，所以能有效防止 SQL 注入
- [kp4] 条件值、插入值、更新值都应该用 `#{}`

## 详解
### 先搞懂：先写好问句，再填答案
想象你去前台办业务，表格上有一行“姓名：____”。表格已经印好，你只是在空格里写名字。无论你写什么，它都只是名字，不会变成表格上的新规定。

`#{}` 就是这个空格。SQL 的结构先定好，参数值后来才填进去。

术语说明：

- **占位符**：SQL 里的 `?`，表示这里将来有个值；
- **预编译**：数据库先接收并分析 SQL 结构，参数后传；
- **转义**：把值里的特殊字符处理好，防止被当作 SQL 语法。

### #{}：两步走
1. **解析时**：MyBatis 看到 `where id = #{id}`，把它变成 `where id = ?`，交给 JDBC 做预编译；
2. **执行时**：MyBatis 把参数值设到第一个问号的位置，再发给数据库执行。

对于字符串，值会被当作字符串数据处理，里面的引号等字符不会改变 SQL 的结构，所以恶意输入没法篡改语句。

### 为什么是首选
- **安全**：值与 SQL 结构分开，防止注入；
- **省心**：不用自己加引号或处理类型，MyBatis 按参数类型选合适的方式设值；
- **可复用**：预编译语句在数据库侧可以复用，同一类 SQL 不必每次重新分析。

但要注意，`#{}` 只能代表“值”。表名、列名、`order by` 后的列这些位置，不能用占位符。

## 示例
```xml
<select id="selectById" resultType="User">
  select * from user where id = #{id} and status = #{status}
</select>
```

```sql
-- MyBatis 实际发出的预编译 SQL，id、status 通过参数设置
select * from user where id = ? and status = ?
```

## 易错点
- 在 `#{}` 外面再加单引号，如 `'#{name}'`，会变成 `'?'`，值无法设置
- 想用 `#{}` 传表名或列名，不会生效，因为占位符只能代表值
- 以为 `#{}` 会在日志里显示完整 SQL，实际日志里常是问号加参数列表

## 追问
### [f1] 为什么 `'%#{name}%'` 会报错？
引号里的 `?` 被数据库当成普通字符，不是占位符，参数就没处可设。模糊查询应该用 `concat('%', #{name}, '%')`。
