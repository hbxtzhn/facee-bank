## 一句话
硬链接是给同一个 inode 起的另一个文件名；软链接是一个独立的小文件，里面存的是目标文件的路径。

## 要点
- [kp1|3] 硬链接：新的目录项，指向和原文件同一个 inode
- [kp2|3] 软链接：有自己独立的 inode，内容是目标文件的路径
- [kp3|2] 删除原文件后，硬链接仍可访问，软链接会失效
- [kp4|2] 硬链接不能跨文件系统，一般也不能链接目录；软链接可以
- [kp5] 硬链接的删除受引用计数控制，计数为 0 才真正删除

## 详解
### 先搞懂：别名和快捷方式
同一个人可以有两个名字，两个名字指向的是同一个人，这是硬链接。快捷方式只是写着「去哪里找」，目标搬走或删除，它就找不到了，这是软链接。

后文会用到几个词：

- **inode**：保存文件元数据和数据位置的结构。
- **目录项**：目录里的「文件名到 inode 编号」的记录。
- **引用计数**：有多少个目录项指向这个 inode。

### 硬链接：同一个 inode，多一个名字
创建硬链接，只是在目录里多加一条记录，指向原文件的 inode。两个名字完全平等，没有主次之分。

删除任何一个名字，只是把引用计数减一。计数为 0 时，文件才真正被删除。所以删掉原名，通过硬链接仍可访问内容。

限制是：硬链接不能跨文件系统，因为 inode 编号只在一个文件系统内有意义；一般也不允许对目录创建硬链接。

### 软链接：存着路径的独立文件
软链接是一个新文件，有自己的 inode，内容是目标路径。访问它时，系统读出路径，再去访问目标。

所以它可以指向别的文件系统，也可以指向目录。目标被删除或移动后，路径找不到，软链接就成了悬空链接。

### 方案对比：硬链接和软链接
| 维度 | 硬链接 | 软链接 |
|---|---|---|
| 本质 | 指向同一 inode 的目录项 | 存路径的独立文件 |
| 删除原文件后 | 仍可访问 | 失效 |
| 跨文件系统 | 不可以 | 可以 |
| 链接目录 | 一般不可以 | 可以 |

结论：想给文件多取个名字、防止误删用硬链接；需要跨文件系统、指向目录或做快捷方式，用软链接。

## 示例
```bash
ln file.txt hard.txt        # 硬链接
ln -s file.txt soft.txt     # 软链接
ls -li                      # 对比 inode 编号：硬链接相同，软链接不同
```

## 易错点
- 以为硬链接是复制了一份；它们共用同一份数据，改一个另一个也变
- 以为软链接和原文件无关；原文件删除后，软链接会失效
- 以为硬链接可以跨磁盘分区；不同文件系统间 inode 无法共用

## 追问
### [f1] 怎么判断一个文件有几个硬链接？
`ls -l` 输出里的第二列就是链接数，也就是 inode 的引用计数。
