## 一句话
观察就是工具执行后返回的结果，它被放回上下文，成为模型下一步推理的依据，这样 Agent 才形成感知、决策、执行的闭环。

## 要点
- [kp1|3] 观察是工具执行的结果，比如查询返回的数据或报错信息
- [kp2|3] 观察被追加进上下文，模型据此决定下一步
- [kp3|2] 没有观察，模型就是在盲目行动，不知道动作是否成功
- [kp4] 观察可以是成功结果，也可以是错误信息，两者都有用

## 详解
### 先搞懂：做完一步要看看结果
你煮面，放下去之后要看一眼：熟了没有，水开没开。如果闭着眼只管按菜谱走，面糊了你也不知道。

Agent 也一样。它调用工具之后，必须读到工具的结果，才知道刚才那一步成功了没有、该继续还是换办法。这个结果就是观察。

后文用到的术语：
- **上下文**：模型每次推理时能看到的全部内容。
- **闭环**：动作的结果会反过来影响下一个动作。

### 观察是怎么回到模型的
流程很简单：

1. 模型决定调用某个工具，比如查天气；
2. 程序执行工具，得到结果，比如「晴，25 度」；
3. 程序把结果作为一条消息追加到上下文；
4. 模型下一轮推理时就能读到它。

模型本身不会执行工具，真正干活的是外部程序，观察是程序把结果交还给模型的桥梁。

### 观察的内容可好可坏
- 成功的结果：数据、文件内容、网页文字，模型据此继续推进；
- 失败的信息：报错、超时、查无结果，模型据此换参数重试或改用别的工具。

有了这个反馈，Agent 才能自我修正。

### 为什么要注意观察的质量
观察会占用上下文，太长或噪声太多会影响后续判断。所以要截取关键信息，错误提示尽量清楚。

## 示例
```python
call = reply.tool_call                  # 模型要求调用工具
result = run_tool(call)                 # 外部程序执行
messages.append({"role": "tool", "content": result})   # 观察回到上下文
```

## 易错点
- 以为模型自己执行工具；实际由外部程序执行后，把结果交回给模型
- 以为只有成功结果才算观察；报错信息同样是重要的观察
- 以为观察会自动保留；上下文有长度限制，过长内容需要压缩

## 追问
### [f1] 工具返回错误时模型会怎么做？
模型读到错误观察后，可能修正参数重试、换一个工具，或告诉用户无法完成。这依赖错误信息是否清晰。

### [f2] 观察和用户输入有什么区别？
用户输入是人发来的指令，观察是工具执行产生的反馈。两者都进入上下文，但来源不同，处理时也要注意观察内容不一定可信。
