## 一句话
Redis 最常见的用途是缓存，也常用来做计数器、排行榜、分布式锁和会话共享。

## 要点
- [kp1|3] 缓存：数据放内存，读写快，减轻数据库压力
- [kp2|3] 计数器：原子递增命令，适合点赞数、访问量
- [kp3|2] 排行榜：有序集合按分数排序，适合榜单
- [kp4|2] 分布式锁：多个服务竞争同一个资源时互斥
- [kp5] 会话共享：多台服务器共用一份登录状态

## 详解
### 先搞懂：Redis 是一块放在内存里的「公共小黑板」
你做过的网站，数据存在 MySQL 里，每次读都要查磁盘。Redis 像贴在墙上的公共小黑板：常用的东西抄一份上去，大家抬头就能看到，比翻档案柜快得多。

后文会用到的术语：

- **缓存**：把常用数据的副本放在更快的地方，下次直接读。
- **分布式锁**：多个服务进程之间的互斥锁。
- **会话（Session）**：记录用户登录状态的数据。

### 缓存
把热点数据放进 Redis，读取时先查 Redis，没有再查数据库。内存读写很快，能提高响应速度，也让数据库少承受请求。

### 计数器
Redis 的 `INCR` 命令对数字原子加一。点赞数、文章访问量、接口调用次数，都可以用它。

### 排行榜
有序集合（ZSet）给每个成员一个分数，自动按分数排序。取前十名只要一条命令。

### 分布式锁
多个服务实例要抢同一个资源时，可以用 `SET key value NX EX 秒数`，谁设置成功谁拿到锁。要注意锁的过期、误删等问题，生产中常用成熟的客户端库。

### 会话共享
用户登录状态放进 Redis，多台应用服务器读同一份，用户被转发到哪台都能识别。

### 还能做什么
- 消息队列的简单场景（List、Stream）。
- 限流：记录一段时间内的请求次数。
- 去重和集合运算：Set 的交集、并集。

## 示例
```bash
SET user:1:token abc123 EX 1800    # 会话，30 分钟过期
INCR article:100:views             # 计数器加一
ZADD rank:game 95 alice            # 排行榜写入分数
```

## 易错点
- 以为 Redis 可以完全代替数据库；它主要靠内存，容量有限，持久化能力弱于数据库
- 以为缓存数据永远和数据库一致；需要处理更新和过期，否则会读到旧数据

## 追问
### [f1] 为什么这些用途都选 Redis？
它基于内存，读写快；提供多种数据类型，计数、排行、集合运算都有现成命令；单个命令是原子的，不用自己加锁。
