## 一句话
Agent 的记忆分两类：短期记忆是当前会话的上下文，保持对话连贯；长期记忆跨会话保存用户偏好、历史决策等信息。

## 要点
- [kp1|3] 短期记忆就是当前会话放进上下文的内容，会话结束就没了
- [kp2|3] 长期记忆存在外部存储里，跨会话保留，需要时再取回
- [kp3|2] 模型本身不会记事，所谓记住是把信息重新放进上下文
- [kp4] 上下文长度有限，历史太长时要截断或做摘要

## 详解
### 先搞懂：便签和笔记本
你和同事开会，当场说的话记在脑子和便签上，会开完便签就扔了，这是短期记忆。而同事的饮食习惯、你们上次的决定，你记在笔记本里，下次见面翻出来用，这是长期记忆。

Agent 也是这样。大模型本身每次调用都不会记得上一次，它所谓的记忆，其实是系统把需要的信息再喂给它。

后文用到的术语：
- **上下文**：这一次调用中，发给模型的全部内容。
- **持久化**：把信息存到数据库或文件里，程序重启也在。

### 短期记忆：靠上下文保持连续
每一轮对话，系统都会把之前的对话记录一起发给模型，所以它能接上话，知道「它」指的是什么。

但上下文长度有限。对话太长时，常见处理是保留最近的内容，把更早的内容压缩成摘要。

### 长期记忆：存下来，下次再用
长期记忆把信息写到外部存储，如数据库或向量库。下次会话开始时，按当前问题检索相关内容，放进上下文。

适合存的内容有：用户偏好（喜欢简洁回答）、历史决策（上次选了某个方案）、重要事实。

### 对比：短期和长期记忆
| 对比点 | 短期记忆 | 长期记忆 |
|---|---|---|
| 存放位置 | 当前上下文 | 外部存储 |
| 生命周期 | 当前会话 | 跨会话保留 |
| 作用 | 保持对话连贯 | 沉淀个性化经验 |

结论：对话连贯靠短期记忆；要让 Agent 越用越懂用户，就要加长期记忆。

## 示例
```python
# 会话开始时：取回长期记忆，放进上下文
prefs = memory_store.search(user_id, query=user_message)
messages = [{"role": "system", "content": "用户偏好：" + prefs}] + history
```

## 易错点
- 以为模型自己记得上次聊了什么；它每次调用都从头读上下文
- 以为上下文越长越好；太长会增加成本，也可能干扰模型关注重点
- 以为长期记忆什么都该存；无用或过期的信息会污染检索

## 追问
### [f1] 对话太长超出上下文怎么办？
常见做法是保留最近几轮原文，把更早的对话压缩成摘要，或者把重要信息存到长期记忆，需要时再检索回来。

### [f2] 长期记忆通常存在哪里？
常见是数据库、文件，或向量库。向量库适合按语义检索，数据库适合存结构化的偏好。
