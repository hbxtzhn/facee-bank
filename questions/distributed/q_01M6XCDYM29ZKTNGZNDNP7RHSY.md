## 一句话
JMS 是 Java 的消息服务接口规范，定义了 Text、Map、Object、Bytes、Stream 五种消息体，以及点对点和发布订阅两种模型，ActiveMQ 是典型实现。

## 要点
- [kp1|3] JMS 是 Java 的 API 规范，不是线路协议，也不是具体产品
- [kp2|3] 五种消息体：Text、Map、Object、Bytes、Stream
- [kp3|2] 点对点模型用队列，一条消息只被一个消费者处理
- [kp4|2] 发布订阅模型用主题，一条消息发给所有订阅者
- [kp5] ActiveMQ 是常见的 JMS 实现

## 详解
### 先搞懂：规范是插座标准，产品是电器
JMS 就像插座标准：规定了插头的形状，但不管电器是谁做的。写代码时按 JMS 接口来，换一家实现，业务代码改动较少。

后文用到的几个词：
- **规范**：只规定接口怎么写，不提供具体实现。
- **消息体**：消息里装的内容，有不同的数据格式。
- **队列、主题**：消息传递时用的两种载体。

### 五种消息体：装内容的不同容器
| 消息体 | 装什么 |
|---|---|
| `TextMessage` | 一段文本，比如 JSON 字符串 |
| `MapMessage` | 一组键值对 |
| `ObjectMessage` | 一个可序列化的 Java 对象 |
| `BytesMessage` | 原始字节数据 |
| `StreamMessage` | 一串按顺序读写的基本类型值 |

实际项目里，文本加 JSON 最常见，因为跨语言、好调试。

### 两种消息模型
- **点对点（P2P）**：使用队列。生产者发消息，一条消息只能被一个消费者处理。没被消费的消息留在队列里，直到被消费或过期。
- **发布订阅（Pub/Sub）**：使用主题。发布者发一条消息，所有订阅者都能收到，类似广播。

### 方案对比：两种模型
| 维度 | 点对点 | 发布订阅 |
|---|---|---|
| 载体 | 队列 | 主题 |
| 一条消息被谁收到 | 一个消费者 | 所有订阅者 |
| 典型场景 | 任务分发、订单处理 | 通知广播、事件推送 |

结论：一件事只需要一个消费者处理，用点对点；多个系统都要知道这件事，用发布订阅。

## 易错点
- 以为 JMS 是一个具体的消息队列产品；它只是接口规范
- 以为 JMS 能跨语言；它是 Java 平台的 API，跨语言通常靠 AMQP 这类协议
- 以为点对点只能有一个消费者在线；可以有多个消费者竞争，但每条消息只被一个拿走

## 追问
### [f1] JMS 和 AMQP 有什么区别？
JMS 定义的是 Java API，不管网络上怎么传；AMQP 是线路层协议，规定了字节怎么传，所以能跨语言。

### [f2] 发布订阅里订阅者不在线怎么办？
普通订阅在离线期间会错过消息；持久订阅则会让 Broker 保存这段时间的消息，等订阅者上线后再投递。
