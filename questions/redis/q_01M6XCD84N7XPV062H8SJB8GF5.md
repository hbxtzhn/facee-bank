## 一句话
主从复制是把一个主节点的数据单向复制到多个从节点，作用是数据冗余备份、读写分离，以及分担主节点的读压力。

## 要点
- [kp1|3] 复制是单向的：数据只能从主节点同步到从节点
- [kp2|3] 作用一：数据冗余，从节点是热备份，主节点故障可顶替
- [kp3|2] 作用二：读写分离，主节点写，从节点读，分担读压力
- [kp4|2] 从节点也可以再挂从节点，减轻主节点的同步负担
- [kp5] 复制是异步的，从节点数据可能略落后于主节点

## 详解
### 先搞懂：老师的板书和学生的笔记
老师在黑板上写课，学生在各自的笔记本上抄。老师写什么，学生抄什么，学生不会反过来改黑板。如果老师突然离开，任何一个学生的笔记都能当作备份继续讲。

主从复制也是这样：主节点（master）是黑板，从节点（slave，也常叫 replica）是笔记，数据只能从主流向从。

后文用到的术语：

- **主节点**：接受写入的 Redis 节点。
- **从节点**：从主节点复制数据的节点，默认只读。
- **读写分离**：写请求发给主节点，读请求分散给从节点。
- **热备份**：备份节点一直在线并保持同步，随时能接替。

### 主从复制有什么作用
1. **数据冗余**：从节点保存了一份主节点数据的副本。这是持久化之外的另一种数据备份方式。
2. **故障恢复**：主节点出问题，可以把从节点提升为新主节点，服务继续。
3. **读写分离**：写操作只走主节点，读操作分给多个从节点，读多写少时能提升整体处理能力。
4. **高可用的基础**：哨兵和 Cluster 的自动故障转移，都建立在主从复制之上。

### 同步的两种结构
- **主从同步**：从节点直接从主节点复制。
- **从从同步**：从节点再作为别的从节点的数据来源，形成链式结构，让主节点不用为每个从节点都发一份数据，减轻同步负担。

### 需要明白的限制
- 复制是异步的，主节点写完就返回，不等从节点确认。主节点突然宕机时，没来得及复制的数据可能丢失。
- 读从节点可能读到稍旧的数据。
- 复制不能自动切换主节点，要配合哨兵或 Cluster。

## 示例
```bash
# 在从节点上执行，指定主节点的地址和端口
REPLICAOF 192.168.1.10 6379

# 查看复制状态
INFO replication
```

## 易错点
- 以为主从是双向同步；只有主到从一个方向
- 以为从节点和主节点永远一致；复制是异步的，可能落后
- 以为有主从就有自动故障转移；还需要哨兵或 Cluster

## 追问
### [f1] 从节点可以写入吗？
默认从节点是只读的，写入会报错。即使强行允许写入，也不会同步回主节点，还会造成数据不一致，一般不这样做。
