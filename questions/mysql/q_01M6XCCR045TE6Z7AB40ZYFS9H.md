## 一句话
间隙锁锁住两条索引记录之间的空隙，不锁记录本身，作用是阻止别的事务往这个空隙里插入新数据，从而防止幻读。

## 要点
- [kp1|3] 间隙锁锁的是两条记录之间的空隙，不包含记录本身
- [kp2|3] 它的作用是阻止别人往间隙里插入，用来防幻读
- [kp3|2] 查询范围里没命中记录时，会加间隙锁
- [kp4] 间隙锁之间互相兼容，只和插入操作冲突
- [kp5] 主要出现在可重复读隔离级别下

## 详解
### 先搞懂：围住「还没有人坐的空位」
假设表里 id 有 1、5、10 三条记录。你查「id = 7 的记录并锁住」，没有这条记录。

如果不做任何处理，另一个事务可以插入 id = 7 的新行。你再查一次，就多出一行，这就是**幻读**。

所以 InnoDB 会把 5 到 10 之间的空隙围起来，别人想往里插入 6、7、8、9 都要等。

类比：电影院里有一排空座位，你想保证「这一段没人坐进去」，就在这段前后拉一条警戒线。

后文会用到这几个词：

- **间隙**：两条相邻索引记录之间、没有数据的那一段，用开区间表示，如 (5,10)。
- **幻读**：同一个事务里两次范围查询，第二次多出了新插入的行。

### 什么时候加间隙锁
在可重复读隔离级别下，等值或范围查询需要加锁、并且没有命中记录时，会对对应的间隙加锁。

例如上面的例子：`WHERE id = 7 FOR UPDATE`，没有 id = 7，就锁住 (5,10)。

### 间隙锁的特点
- **只挡插入**：它阻止的是往间隙里插入数据，对已有记录的读写没有影响。
- **互相兼容**：两个事务可以同时在同一个间隙上持有间隙锁，因为它们的目的都是「别人别插入」，并不互相冲突。
- **范围是开区间**：间隙不包含两端的记录。

### 副作用
间隙锁会让一些看起来无关的插入被阻塞，并发度下降，有时也会引发死锁。如果业务能接受幻读，可以把隔离级别改成读已提交，间隙锁在大多数情况下就不会再加。

## 示例
```sql
-- 假设 id 有 1、5、10，可重复读级别
-- 事务 A
START TRANSACTION;
SELECT * FROM orders WHERE id = 7 FOR UPDATE;  -- 没命中，锁 (5,10)

-- 事务 B：会被阻塞，直到 A 提交或回滚
INSERT INTO orders(id) VALUES (8);
```

## 易错点
- 以为间隙锁会锁住记录本身；它只锁空隙
- 以为两个间隙锁会互相阻塞；它们是兼容的
- 以为所有隔离级别下都会有间隙锁；读已提交下大多数情况不加

## 追问
### [f1] 间隙锁为什么能防幻读？
幻读是因为别人往范围里插入了新行。间隙锁把这个范围里的空隙锁住，插入会被阻塞，范围里就不会冒出新行。

### [f2] 怎么减少间隙锁带来的阻塞？
尽量用唯一索引做精确查询，缩小锁定范围；缩短事务；或在业务允许时使用读已提交。
