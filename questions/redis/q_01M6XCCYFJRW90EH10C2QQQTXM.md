## 一句话
Redis 有五种基本类型：String 存单个值，Hash 存对象，List 存有序列表，Set 存去重集合，ZSet 存带分数的有序集合。

## 要点
- [kp1|3] String：字符串、数字、序列化数据，用于缓存、计数、会话
- [kp2|3] Hash：字段到值的映射，适合存对象，可单独改某个字段
- [kp3|2] List：按插入顺序排列的列表，可从两端存取，适合简单队列
- [kp4|2] Set：元素唯一且无序，适合去重、共同好友
- [kp5] ZSet：每个元素带分数并排序，适合排行榜、延时任务

## 详解
### 先搞懂：Redis 的 value 有不同的「容器」
Redis 的 key 都是字符串，但 value 可以是不同的容器。就像你家里的收纳：杂物放盒子，衣服放衣柜，书放书架。用对容器，找东西才方便。

后文会用到的术语：

- **key**：数据的名字。
- **value**：数据的内容，可以是不同类型。
- **类型**：决定可以对数据做哪些操作。

### 五种类型对比
| 类型 | 存什么 | 典型场景 | 常用命令 |
|---|---|---|---|
| String | 字符串、数字、二进制 | 缓存、计数器、会话、分布式锁 | `GET`、`SET`、`INCR` |
| Hash | 字段和值的集合 | 用户信息等对象 | `HSET`、`HGET`、`HGETALL` |
| List | 有序的元素列表 | 简单消息队列、最新动态 | `LPUSH`、`RPOP`、`LRANGE` |
| Set | 不重复的元素集合 | 去重、共同好友、抽奖 | `SADD`、`SISMEMBER`、`SINTER` |
| ZSet | 带分数、按分数排序的集合 | 排行榜、延时队列 | `ZADD`、`ZRANGE`、`ZREVRANGE` |

结论：存单个值或序列化后的对象用 String；对象字段要单独读写用 Hash；需要顺序用 List；需要去重用 Set；需要按分数排序用 ZSet。

### String：最常用
String 能存文本、数字，也能存序列化后的 JSON，甚至图片等二进制数据。单个 value 有大小上限，所以不适合存特别大的内容。

### Hash：像一个小对象
一个用户有姓名、年龄、城市等字段，用 Hash 存在一个 key 下，想改年龄只改这一个字段，不用把整个对象读出来再写回去。

### List：能当简单队列
从一端放入、另一端取出，就是队列。要注意它不保证消息一定被处理，复杂场景应考虑 Stream 或专业消息队列。

### Set：自动去重
重复添加同一个元素不会重复存。还支持交集、并集、差集，用来算共同好友很方便。

### ZSet：带分数的排序
每个元素有一个分数，按分数排序，范围查询和取前几名很高效。

### 进阶：除了五种还有什么（基础薄弱可先跳过）
Redis 还有 Bitmap、HyperLogLog、Geo、Stream 等类型，用于位统计、基数估算、地理位置、消息流。它们大多是在基本类型基础上的扩展。

## 易错点
- 把整个大对象序列化成一个大 String，每次只改一个字段也要整个写回；这种场景用 Hash 更合适
- 用 List 当可靠消息队列；消息被取出后，如果消费者崩溃，消息就丢了
- 以为 Set 保持插入顺序；它是无序的

## 追问
### [f1] 存用户信息，用 String 还是 Hash？
整体读写用 String 存序列化的对象简单；需要经常单独读写某个字段，用 Hash 更省事。注意 Hash 中字段很多时，也要避免成为大 key。
