## 一句话
ReAct 走一步想一步，灵活但容易跑偏；计划与执行先定好整体步骤再逐步完成，适合依赖明确的长任务，但计划变了就要重新规划。

## 要点
- [kp1|3] ReAct 每步现场决策，计划与执行先出全局计划再按步执行
- [kp2|3] 计划与执行适合步骤多、依赖关系明确的长任务
- [kp3|2] ReAct 更灵活，但步骤多时容易偏离目标、重复绕路
- [kp4|2] 环境变化让计划失效时，计划与执行要重新规划
- [kp5] 计划与执行通常分规划器和执行器两个角色

## 详解
### 先搞懂：出发前画路线，还是边走边问路
去一个陌生城市旅游，有两种方式。一种是出发前先列好行程：第一天去哪、第二天去哪，然后照着走。另一种是到了路口再看情况，边走边决定。

前者就是计划与执行，后者就是 ReAct。

后文用到的术语：
- **规划器**：负责把任务拆成分步计划的部分。
- **执行器**：负责按计划逐步完成每一步的部分。
- **重规划**：执行中发现计划不合适，重新制定计划。

### ReAct：每步现场决定
每一轮都根据最新观察决定下一步。优点是灵活，遇到意外能马上调整。缺点是没有全局视野：步骤一多，模型可能忘了最初目标，反复尝试相似的动作，或者中途跑偏。

### 计划与执行：先规划后落实
流程分两段：

1. 规划器读任务，输出一份分步计划，比如「第一步查数据、第二步清洗、第三步出报表」；
2. 执行器按顺序完成每一步，执行器可以是简单的程序，也可以是小的 ReAct 循环；
3. 全部步骤完成后汇总结果。

好处是整体目标清晰，不容易走偏；步骤相互独立时还可以并行。风险是：计划在执行前就定了，中途情况变了，原计划可能已不合适，这时要回到规划器重新规划。

### 方案对比：ReAct 和计划与执行
| 对比点 | ReAct | 计划与执行 |
|---|---|---|
| 决策时机 | 每一步现场决定 | 先全局规划，再执行 |
| 灵活性 | 高，随时调整 | 较低，需重规划 |
| 长任务表现 | 容易偏离目标 | 目标稳定，结构清晰 |
| 调用成本 | 每步都要推理 | 规划一次，执行可简化 |

结论：任务短、不确定性高时用 ReAct；步骤多、依赖清楚时用计划与执行；两者也可以结合，在计划的每一步里使用 ReAct。

## 示例
```python
plan = planner(task)              # 先产出分步计划
for step in plan:
    result = executor(step)       # 按步骤执行
    if result.failed:
        plan = replanner(task, plan, result)   # 失败时重新规划
        break
```

## 易错点
- 以为计划一旦制定就不能改；遇到变化应重规划
- 以为计划与执行一定比 ReAct 好；环境多变时它会显得僵硬
- 以为两种模式只能二选一；常见做法是把它们组合使用

## 追问
### [f1] 什么情况下需要重规划？
某一步失败、返回了意料之外的结果，或者用户修改了目标。此时把已完成的内容和新情况交给规划器，生成新的剩余步骤。

### [f2] 计划与执行怎么和 ReAct 结合？
规划器负责拆出大步骤，每个大步骤交给一个 ReAct 子循环去完成细节。这样既有全局结构，又有局部灵活性。
