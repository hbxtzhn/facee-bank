## 一句话
不可重复读是同一个事务里两次读同一行，中间有别的事务修改并提交，导致两次结果不一样。

## 要点
- [kp1|3] 同一事务内两次读同一行，结果不同
- [kp2|3] 原因是另一个事务在两次读之间修改了这一行并已提交
- [kp3|2] 读已提交会出现，可重复读及以上避免
- [kp4] 它读到的都是已提交数据，所以不同于脏读

## 详解
### 先搞懂：你查两遍账单，数字变了
你在生成月度报表，先查了一次某客户余额是 100。这时客户又充值了，余额变成 200 并提交。你再查一次，余额是 200。

同一份报表里，同一个客户出现了两个余额，对不上账。这就是不可重复读。

后文会用到的术语：

- **同一个事务**：从开始到提交之间的所有操作，被当成一个整体。
- **提交**：确认事务的修改，从此对别人可见。

### 它是怎么发生的
1. 事务 A 查询某行，读到余额 100。
2. 事务 B 把这行改成 200，并提交。
3. 事务 A 再查同一行，读到 200。

A 两次读到的值不同。这里读到的 200 是已提交的，没有错，但一个事务里前后不一致，会让计算结果出问题。

### 和脏读、幻读的区别
- 脏读：读到别人还没提交的数据。
- 不可重复读：同一行被别人修改并提交，前后读到的值不同。
- 幻读：符合条件的行数变了，别人插入或删除了行。

### 怎么避免
把隔离级别设成可重复读或串行化。MySQL 默认是可重复读，事务第一次查询后复用同一份读视图，所以反复读同一行结果一致。读已提交每次查询都换新视图，所以会出现不可重复读。

## 示例
```sql
-- 会话 A（读已提交级别）
SET SESSION TRANSACTION ISOLATION LEVEL READ COMMITTED;
START TRANSACTION;
SELECT balance FROM account WHERE id = 1;  -- 100

-- 会话 B
UPDATE account SET balance = 200 WHERE id = 1;  -- 自动提交

-- 会话 A
SELECT balance FROM account WHERE id = 1;  -- 200，同一事务两次结果不同
COMMIT;
```

## 易错点
- 以为不可重复读一定是错误；读到的是已提交数据，是否能接受取决于业务
- 把不可重复读和幻读混淆；前者是同一行的值变了，后者是行数变了

## 追问
### [f1] 可重复读为什么能避免不可重复读？
可重复读只在事务第一次查询时生成读视图，之后一直复用。别人后来提交的修改，对这份读视图来说是不可见的，所以读到的值不变。
