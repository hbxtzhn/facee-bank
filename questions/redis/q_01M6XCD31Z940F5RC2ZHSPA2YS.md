## 一句话
对数据库查不到的 key 也缓存一个空值，做法简单有效；问题是空值会占内存，数据之后新增时缓存里的空值可能让用户短暂读不到。

## 要点
- [kp1|3] 数据库查不到时，也把空结果写进缓存，下次直接命中空值
- [kp2|3] 缺点一：大量不同的无效 key 会占用很多内存
- [kp3|2] 缺点二：数据后来新增了，缓存里的空值还没过期，会短暂不一致
- [kp4] 空值要设置较短的过期时间，缓解上面两个问题

## 详解
### 先搞懂：门口贴“查无此人”
快递员问了一圈，这个住户不存在，于是在门口贴一张“查无此人”的告示。之后再有人来找，直接看告示就知道，不用再去物业查。缓存空值就是这张告示。

后文用到的词：
- **空值**：表示“数据库里没有”的占位值，比如空字符串或特殊标记。
- **过期时间（TTL）**：缓存数据保留多久，到期自动删除。

### 做法
1. 先查缓存，命中就返回（空值也算命中，返回“不存在”）；
2. 没命中，查数据库；
3. 数据库里有，写缓存；
4. 数据库里没有，写入一个空值，并设置较短的过期时间。

### 优点
实现简单，不需要额外组件，能立刻挡住对同一批不存在 key 的重复请求。

### 缺点
- **占内存**：攻击者每次都换一个不存在的 ID，每个 ID 都会占一条缓存，空值越来越多。过期时间短一些，可以让它们尽快清走。
- **短暂不一致**：假如 ID 为 100 的数据一开始不存在，缓存了空值。随后业务新增了 ID 100，而缓存中的空值还没过期，用户在这段时间里查到的仍然是“不存在”。

### 怎么缓解不一致
- 过期时间设短一些（几十秒到几分钟，视业务而定）；
- 新增数据时，主动删除对应 key 的空值缓存；
- 无效 key 数量太大时，改用布隆过滤器，把不存在的请求挡在缓存之前。

### 方案对比：缓存空值和布隆过滤器
| 方案 | 实现 | 内存 | 一致性 | 适合 |
|---|---|---|---|---|
| 缓存空值 | 简单 | 随无效 key 增加 | 新增数据时可能短暂不一致 | 无效 key 数量有限 |
| 布隆过滤器 | 需要预热数据 | 固定且较小 | 新增数据要同步加入 | 无效 key 很多、来源随机 |

结论：无效请求不多时先用缓存空值；随机 key 很多时，用布隆过滤器拦在前面。

## 示例
```bash
# 数据库没有 user:100，缓存一个空值，30 秒后过期
SET user:100 "" EX 30
```

## 易错点
- 给空值设置很长的过期时间，数据新增后很久读不到
- 以为缓存空值能解决所有穿透；无效 key 每次都不同时，它占内存而且挡不住
- 忘记新增数据时清理空值缓存

## 追问
### [f1] 缓存空值的过期时间怎么定？
要在两个风险之间平衡：太长，新增数据迟迟可见不到；太短，起不到挡请求的效果。一般取较短时间，并在新增数据时主动删除空值。
