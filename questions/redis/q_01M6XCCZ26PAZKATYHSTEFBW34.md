## 一句话
跳表是在有序链表上叠加多层稀疏索引，每个节点层高随机，查找从最高层开始，往前跳到头就下降一层，逐层逼近目标。

## 要点
- [kp1|3] 底层是完整的有序链表，上层是稀疏的索引
- [kp2|3] 查找从最高层出发，不能再往前就下降一层，直到底层
- [kp3|2] 节点层高随机决定，高层节点少，低层节点多
- [kp4|2] Redis 里 zskiplist 保存表头、表尾、长度和最高层数
- [kp5] zskiplistNode 保存成员、分数、后退指针和各层的前进指针

## 详解
### 先搞懂：查字典先翻目录
你在厚字典里找一个字，不会一页页翻，而是先看部首目录，跳到大致位置，再翻具体页。目录就是一层索引。

如果目录太长，可以再给目录做一个更简略的目录。多层索引叠起来，就是跳表。

后文会用到的术语：

- **有序链表**：节点按大小串成一条线，每个节点指向下一个。
- **层**：节点上的一排指针，层越高，一次跳得越远。
- **前进指针**：指向本层下一个节点。

### 结构：一条完整链加几层稀疏链
- 第 1 层（最底层）：包含所有节点，是完整的有序链表。
- 往上的每一层：只包含部分节点，层越高，节点越少，相邻节点的距离越远。

一个节点出现在几层，就叫它的层高。一个层高为 3 的节点，同时处在第 1、2、3 层。

### 查找：从高到低，逐层逼近
例如要找分数 50 的节点：

1. 从最高层的头节点出发，沿着前进指针往前走。
2. 如果下一个节点的分数大于 50，说明走过头，就下降一层。
3. 如果下一个节点的分数小于 50，继续在本层往前走。
4. 一直走到底层，就能精确定位到目标。

高层一步跳很远，低层精细调整，所以不需要从头一个个走。

### 层高怎么定
节点插入时才随机决定它的层高：先有一层，再按固定概率反复判断是否多长一层。结果是层越高，节点越少，各层之间自然形成稀疏的索引。

不用刻意维护平衡，靠随机让整体大致均匀。

### Redis 里的结构
Redis 用两个结构表示跳表：

- `zskiplist`：记录整个跳表的信息，包括表头、表尾、节点数量、当前最高层数。
- `zskiplistNode`：每个节点，保存成员、分数、一个后退指针，以及一组层，每层有指向本层下一个节点的前进指针。

后退指针指向底层的前一个节点，方便从后往前遍历，比如倒序取前几名。

### 进阶：跨度（基础薄弱可先跳过）
每一层的前进指针还会记录一个「跨度」，表示它跳过了底层多少个节点。查找过程中把跨度累加，就能得到目标的名次，所以 ZSet 能很快回答「第几名」。

## 易错点
- 以为跳表每层节点数是严格对半的；层高是随机的，只是大致均匀
- 以为跳表只有一层链表；它是一层完整链表加多层稀疏索引
- 以为查找每次都要走到最底层才开始；是从最高层开始

## 追问
### [f1] 跳表插入一个节点要做什么？
先查找出每一层该插入的位置，再随机决定新节点的层高，最后在每个涉及的层里改前后节点的指针，并更新跨度。不需要像平衡树那样旋转。

### [f2] 跳表的查找复杂度是多少？
平均是对数级。因为层越高节点越少，每下降一层，要走的节点数大致是常数个。极端情况下层高分布很差，会退化，但概率很低。
