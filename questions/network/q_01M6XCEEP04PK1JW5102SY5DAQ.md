## 一句话
GET 用来从服务器获取资源，POST 用来向服务器提交数据，让服务器处理。

## 要点
- [kp1|3] GET 用于查询，目的是拿到数据，不应改变服务器上的数据
- [kp2|3] POST 用于提交，例如新增数据、提交表单，通常会改变服务器状态
- [kp3|2] GET 的参数一般跟在 URL 后面，POST 的数据放在请求体里
- [kp4] 两者是约定的用法，按用途选择，而不是随意互换

## 详解
### 先搞懂：看菜单和下订单
在餐厅，翻菜单只是看，不会改变任何东西；下订单则会让后厨开始做菜，产生新的订单。

GET 就像看菜单，POST 就像下订单。几个词：

- **请求方法**：HTTP 请求里声明“我要做什么”的字段，如 GET、POST。
- **请求体**：请求里附带的数据部分。
- **URL**：资源地址，GET 的参数可以写在它后面。

### GET：取资源
你打开一个网页、查一篇文章、搜索一个关键词，用的都是 GET。它的含义是“把某个资源给我”。服务器只负责返回，不应该因此修改数据。参数通常放在 URL 的问号后面，例如 `/search?q=java`。

### POST：交数据
你注册账号、提交订单、上传文件，用的都是 POST。它的含义是“把这些数据交给你，请处理”。服务器收到后，可能新建记录、修改状态。数据通常放在请求体里，不显示在 URL 上。

### 怎么选
- 只是读取，不改变数据：用 GET；
- 要新增、修改，或者要提交较多、较复杂的数据：用 POST。

这是 HTTP 的约定，浏览器、缓存和各种工具都按这个约定理解请求，所以用法对了，整个链路才配合得好。

## 示例
```bash
# GET：参数写在 URL 上，用来查询
curl "https://example.com/search?q=java"

# POST：数据放在请求体里，用来提交
curl -X POST https://example.com/orders -d "item=book&count=1"
```

## 易错点
- 以为 GET 不能带数据；它能通过 URL 带参数，只是约定用来查询
- 以为 POST 一定更安全；数据不在 URL 上不等于加密，仍需 HTTPS
- 用 GET 去执行删除、下单这类操作；会破坏约定，容易被缓存或预取误触发

## 追问
### [f1] 搜索框的内容为什么常用 GET？
搜索只是查询，不改变数据，用 GET 可以让结果页有固定 URL，能收藏、能分享，也方便缓存。
