## 一句话
Token 是大模型处理文本的基本单位，通常是用 BPE 等算法切出的子词片段，所以 Token 数和字数不是一回事。

## 要点
- [kp1|3] Token 是模型读写文本的最小单位，不一定是一个字或一个词
- [kp2|3] 常见切法是子词：常见词整个一块，生僻词拆成几块
- [kp3|2] 同样一段话，不同模型的分词器切出的 Token 数可能不同
- [kp4] 计费、上下文长度、输出长度限制，都按 Token 计算

## 详解
### 先搞懂：像拼乐高，模型只认固定的几种积木
你给模型发一句话，它并不是一个字一个字读，而是先把句子拆成它认识的“积木块”，再逐块处理。这些积木块就是 token。

积木的种类是固定的，叫词表。常见的词有现成的整块积木，生僻的词就用几块小积木拼出来。

后文用到的词：
- **分词器**：负责把文本切成 token 的程序。
- **词表**：模型认识的全部 token 的集合。
- **子词**：比词小、比字符大的片段。

### 为什么不直接按字或按词切
- 按词切：词太多，词表会极大，而且遇到新词就不认识。
- 按字符切：词表很小，但一句话会变成很长的序列，处理很慢。
- 子词折中：常见的整块保留，罕见的拆开，既能控制词表大小，又不会有完全不认识的词。

### Token 数和字数怎么对不上
英文里，一个常见单词可能就是一个 token，长单词可能拆成多块。中文里，常用字或词可能是一个 token，也可能一个字被拆成多块，这取决于分词器。

所以不能拿字数直接当 Token 数。要准确知道，就用对应模型提供的分词工具实际数一遍。

### 为什么要关心 Token 数
- **计费**：很多接口按输入和输出的 Token 数计价。
- **上下文窗口**：一次能处理的内容上限用 Token 衡量。
- **输出长度**：最大输出也用 Token 限制。

## 易错点
- 把 Token 当成字或词；它们经常对不上
- 以为不同模型切出的 Token 数一样；分词器不同，结果会不同
- 以为中文一个字固定一个 Token；并不固定

## 追问
### [f1] 为什么要用子词而不是整词？
整词的词表会很大，还会遇到不认识的新词。子词能用有限的积木拼出任何词。

### [f2] 怎么知道一段文本有多少个 Token？
使用该模型对应的分词器或官方提供的计数工具来数，不要靠字数估算。
