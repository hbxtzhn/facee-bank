## 一句话
面向对象编程就是把程序拆成一个个对象，每个对象把自己的数据和操作数据的方法放在一起，再通过封装、继承、多态来组织和复用代码。

## 要点
- [kp1|3] 对象把数据（属性）和操作数据的方法捆在一起，程序靠对象之间调用方法协作
- [kp2|3] 三大特性：封装隐藏内部细节，继承复用父类代码，多态让同一调用有不同表现
- [kp3|2] 类是模板，对象是按模板创建出来的具体实例
- [kp4] 面向过程以步骤为中心，面向对象以对象为中心，各有适用场景

## 详解
### 先搞懂：用「点外卖」想一想两种写法
做一个订单系统，面向过程的思路是：写一堆函数，`计算价格(订单数据)`、`发送通知(订单数据)`，数据在一边，函数在另一边，谁都能改数据。

面向对象的思路是：先有一个「订单」，订单自己带着价格、状态，也自己会「计算价格」「取消」。别人想改订单，只能通过订单提供的方法。

类比一下：面向过程像一份菜谱，一步步照着做；面向对象像一家餐厅，有厨师、服务员、收银员，每个角色管好自己的事，互相配合。

后文要用的词：
- **类**：对象的模板，描述这一类东西有什么属性、会做什么。
- **对象**：按类创建出来的具体实例，如一个具体的订单。
- **方法**：对象能做的事，写在类里的函数。

### 对象：数据和方法放一起
订单的金额、状态是数据，`pay()`、`cancel()` 是操作数据的方法。放在一起后，规则都集中在订单类里，出了问题只用看这一个地方。

### 三大特性：怎么组织代码
- **封装**：把属性藏起来，只留出方法给外部用，防止被随意乱改。
- **继承**：子类直接拥有父类的属性和方法，不用重复写，还可以按需改写。
- **多态**：同样是「调用 `pay()`」，微信支付对象和支付宝对象各自做各自的事，调用方不用关心具体是谁。

### 为什么要这样组织
业务一复杂，代码量会变大。把代码按「对象」划分后，每块职责清楚，改一处不容易牵动别处，也便于复用和扩展。

## 示例
```java
class Order {
    private int amount;                 // 数据
    Order(int amount) { this.amount = amount; }
    int pay() { return amount; }        // 操作数据的方法
}

Order order = new Order(100);           // 对象是类的实例
order.pay();
```

## 易错点
- 把「类」和「对象」混为一谈；类是模板，对象是实例
- 以为面向对象一定比面向过程好；简单脚本用函数式写法反而更直接
- 以为用了 class 就是面向对象；如果数据和方法仍然散着用，只是换了个写法

## 追问
### [f1] 面向对象和面向过程有什么区别？
面向过程按步骤组织代码，关注「先做什么、再做什么」；面向对象按对象组织代码，关注「谁负责什么」。后者更适合规模大、需求常变的业务。

### [f2] 三大特性分别解决什么问题？
封装防止数据被乱改，继承减少重复代码，多态让调用方不依赖具体实现，新增类型时调用处不用改。
