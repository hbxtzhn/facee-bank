## 一句话
Spring 默认的单例 Bean 被所有请求线程共用；只要它有会变化的成员变量，又没有做同步，多个线程同时读写就会互相覆盖，造成数据错乱。

## 要点
- [kp1|3] 单例 Bean 只有一个实例，会被多个线程同时使用
- [kp2|3] 无状态（没有可变成员变量）的单例是线程安全的
- [kp3|2] 有可变成员变量且没有同步，并发读写会出现数据错乱
- [kp4|2] 解决办法：用局部变量、保持无状态、必要时加锁或用 ThreadLocal
- [kp5] 局部变量在每个线程自己的栈里，天然线程安全

## 详解
### 先搞懂：全公司共用一块白板
单例 Bean 就像全公司共用的一块白板，所有请求线程都往上写字、看字。

- 如果大家只是看白板上固定的内容（只读），没问题；
- 如果每个人都往白板上写自己的东西，又不排队，就会出现你写到一半被别人擦掉、写出来的字混在一起的情况。

后文用到的词：
- **成员变量**：写在类里、方法外的字段，一个对象只有一份，所有线程共用。
- **局部变量**：写在方法里的变量，每次调用都有自己的一份，只属于当前线程。
- **无状态**：对象里没有会随请求变化的数据。

### 问题是怎么出现的
设想一个 Service 里写了成员变量保存当前用户：

1. 请求 A 的线程把 `currentUser` 设为 Tom；
2. 请求 B 的线程几乎同时把它设为 Jerry；
3. A 线程继续往下执行，读到的 `currentUser` 已经变成 Jerry。

A 的业务就用错了数据。这不是 Spring 的问题，而是多个线程共享了一个可变的成员变量，这一点和普通 Java 多线程问题完全一样。

### 为什么平时项目里没出事
Controller、Service、Dao 这些类通常只保存依赖（别的单例 Bean），自己没有会变化的数据，所有数据都在方法的局部变量或参数里。这种无状态的单例，多个线程同时调用方法也不会互相干扰。

### 怎么避免
1. **用局部变量**：把数据放在方法内部，每个线程各有一份；
2. **保持无状态**：不在 Bean 里保存请求相关的可变数据；
3. **必须有状态时加同步**：用 `synchronized` 或 `Lock` 保护，或者用原子类；
4. **用 ThreadLocal**：把状态存在线程自己的空间里；
5. **改作用域**：确有必要时改成 prototype，每次获取新对象（要考虑创建成本）。

## 示例
```java
@Service
public class CounterService {
    private int count = 0;            // 可变成员变量：多线程共享，有风险

    public void add() {
        count++;                      // 不是原子操作，并发时会丢失更新
    }

    public int calc(int a, int b) {
        int result = a + b;           // 局部变量：线程安全
        return result;
    }
}
```

## 易错点
- 以为单例一定线程安全；只有无状态的单例才安全
- 以为 Spring 会自动给单例加锁；Spring 不会，线程安全需要自己保证
- 把用户信息、请求参数存进单例的成员变量里
- 以为注入的依赖本身也有问题；依赖如果是无状态单例，就没有问题

## 追问
### [f1] 单例 Bean 里的 Mapper 或 Service 依赖为什么是安全的？
它们是只读的引用，注入后不再变化，并且被引用的对象自己也是无状态的，所以多线程共用是安全的。

### [f2] 为什么不干脆把所有 Bean 都改成 prototype？
prototype 每次都创建新对象，创建和垃圾回收的开销更大，也会让依赖关系变复杂。无状态的单例既安全又省资源，是更好的选择。
