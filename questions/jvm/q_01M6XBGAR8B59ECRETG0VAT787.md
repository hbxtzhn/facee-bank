## 一句话
new 一个对象，JVM 依次做：检查类是否已加载（没有就先加载）、分配内存、内存清零、设置对象头、执行构造方法。

## 要点
- [kp1|3] 先检查类是否已加载、解析、初始化，没有就先走类加载
- [kp2|3] 在堆上为对象分配内存，大小在类加载后就已确定
- [kp3|2] 把分配到的内存清零，成员变量因此有默认值
- [kp4|2] 设置对象头，记录所属类、哈希码、锁状态等信息
- [kp5] 最后执行构造方法，按代码给成员变量赋值

## 详解
### 先搞懂：盖房子的流程
`new Order()` 就像盖一栋房子：先看有没有图纸（类）；有图纸了，划一块地（分配内存）；把地面清理干净（清零）；挂上门牌，写明这是哪种房子（对象头）；最后按你的要求装修（构造方法）。

后文用到的术语：

- **类加载**：把 `.class` 文件读进内存，变成 JVM 里可用的类信息。
- **对象头**：对象内存开头的一小块，放类型指针、锁状态等元信息。
- **零值**：数值是 0、布尔是 false、引用是 null。

### 第一步：检查类有没有加载
`new` 指令的参数指向常量池里一个类的符号引用。JVM 先检查这个类是否已经被加载、解析和初始化。没有的话，先执行类加载过程；已经加载过，则直接进入下一步。

### 第二步：分配内存
类加载完成后，一个对象需要多大内存就已经确定了。JVM 在堆里划出这么大的一块。常见的分配方式有两种：

- **指针碰撞**：堆里已用和空闲的内存各在一边，中间放一个分界指针，分配时指针向空闲方向挪动对象大小的距离。适合内存规整的情况。
- **空闲列表**：已用和空闲内存交错，虚拟机维护一张表，记录哪些块可用，分配时从表里找一块够大的。

多线程同时 `new` 时，要保证不会分到同一块内存。常见做法是给每个线程先预分配一小块私有区域（TLAB），线程在自己的区域里分配，不用加锁；区域用完再去申请新的。

### 第三步：内存清零
分配到的内存先全部置为零值，这就是为什么成员变量不赋值也有默认值：数值类型是 0，布尔类型是 false，对象类型是 null。

### 第四步：设置对象头
JVM 在对象头里写入这个对象属于哪个类、哈希码、GC 年龄、锁状态等信息。

### 第五步：执行构造方法
到这里，从 JVM 角度看一个对象已经创建出来了，但还没有按程序员的意图初始化。最后执行 `<init>` 方法，也就是构造方法，按代码给成员变量赋值，对象才真正可用。

## 示例
```java
class Order {
    int count;          // 清零后默认是 0
    String name;        // 默认是 null
    Order() { count = 5; }
}
Order o = new Order();  // 经过：检查类 → 分配内存 → 清零 → 设对象头 → 构造方法
```

## 易错点
- 以为 new 就是执行构造方法；构造方法只是最后一步
- 以为成员变量必须赋值才有值；清零这一步已经给了默认值，局部变量才没有
- 以为所有对象都分配在堆上；通过优化，有些对象可能被分配到栈上或直接消除

## 追问
### [f1] 构造方法执行前，对象能被其他线程看到吗？
如果在构造方法里把 this 提前泄露出去，别的线程可能看到还没初始化完的对象，所以不要在构造方法中泄露 this。
