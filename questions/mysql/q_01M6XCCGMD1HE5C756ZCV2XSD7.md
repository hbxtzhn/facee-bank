## 一句话
Hash 路由是对分片键做哈希再对表数取模，余数就是目标表。数据分得均匀，缺点是范围查询要跨多张表，扩容要迁移数据。

## 要点
- [kp1|3] Hash 路由先对分片键算哈希，再对表数取模得到目标表
- [kp2|3] 优点是数据和写入通常分布均匀，不容易倾斜
- [kp3|2] 缺点是范围查询要访问多张表，因为相邻的值被打散了
- [kp4|2] 表数变化后取模结果变了，扩容要迁移大量数据

## 详解
### 先搞懂：像发牌一样把数据分出去
几个人打牌，发牌时一人一张轮流发，每个人手里的牌数就差不多。Hash 路由就像这样发牌：每行数据算出一个数，再按规则分给某张表，结果通常很均匀。

后文用到的术语：

- **哈希**：把一个值通过固定算法变成另一个数，相同的输入总是得到相同的结果。
- **取模**：用一个数除以表数取余数，比如 10 除以 4，余数是 2。
- **分片键**：决定数据落到哪张表的字段。

### 机制：先哈希，再取模
以 4 张分表、分片键是 `user_id` 为例：

1. 对 `user_id` 计算哈希值；
2. 用哈希值对 4 取模，得到 0 到 3 之间的数；
3. 这个数就是目标表的编号。

如果分片键本身是均匀的整数，也可以不哈希，直接取模。同一个分片键每次算出的结果都一样，所以读写总会去同一张表。

### 优点：数据均匀
哈希把相邻的值打散到不同的表里，单表不会特别大，写入压力也平摊到各张表。不像范围路由，新数据总是堆在最新那张表。

### 缺点：范围查询和扩容都不方便
- **范围查询要跨表**：比如查 `user_id` 从 100 到 200 的用户，这些值被打散在所有分表里，只能每张表都查一遍，再合并结果。
- **扩容要迁移**：表从 4 张变 8 张后，取模的底数变了，大部分数据的落点都变了，要把数据搬到新的位置。
- **热点分片键仍有问题**：如果某个用户的数据特别多，他的数据全在同一张表里，哈希也救不了。

### 怎么减轻扩容的麻烦
常见做法是一开始就多分一些表，比如分 32 张，先放在少数几台机器上。以后加机器时，只是把整张表搬到新机器，取模的底数不变，路由结果也不变。

## 示例
```sql
-- 4 张分表，user_id 取模路由
SELECT 10 % 4;   -- 结果 2，写入 order_2
SELECT 11 % 4;   -- 结果 3，写入 order_3

-- 带分片键的查询，只访问一张表
SELECT * FROM order_2 WHERE user_id = 10;
```

## 易错点
- 以为 Hash 路由适合所有查询；区间查询会访问所有分表，性能较差
- 以为随时可以加表；表数一变，原有数据的落点就变，要做迁移
- 以为哈希后一定绝对均匀；分片键值本身严重集中时，仍然会倾斜

## 追问
### [f1] 为什么扩容后数据要迁移？
因为路由结果依赖表数。表数变了，同一个分片键取模的余数就变了，数据原来的位置不再是正确位置，必须搬到新的表里，否则查不到。
