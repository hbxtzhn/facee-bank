## 一句话
选值分布均匀、查询条件里经常带、写入也能摊开的字段做分片键，避免数据倾斜和大量跨表查询。

## 要点
- [kp1|3] 分片键值要分布均匀，区分度高，避免某张表数据特别多
- [kp2|3] 选查询里最常用的条件字段，这样一次查询只落到一张表
- [kp3|2] 写入也要被分散，避免所有写入压到同一张表
- [kp4] 分片键定了就很难改，不要选会被修改的字段

## 详解
### 先搞懂：按什么给快递分拣
快递站分拣包裹，要决定按什么分到各个格口。如果按「收件人所在城市」分，北京的包裹特别多，北京那个格口就爆了，别的格口空着，这叫数据倾斜。如果按「运单号尾数」分，各个格口差不多满。另外，取件人通常报的是什么信息，也要考虑：他报手机号，你却按运单号分，就得每个格口都找一遍。

几个术语：

- **分片键**：决定一行数据放到哪个库或表的字段。
- **数据倾斜**：有的分片数据特别多，有的很少。
- **热点**：访问集中在少数分片上。
- **跨表查询**：一次查询要访问多个分表。

### 选分片键的三个条件
1. **区分度高、分布均匀**：值要足够分散，每个分片拿到差不多的数据量。用性别、状态这类取值少的字段当分片键，数据只能分到寥寥几张表。
2. **查询中经常使用**：最常用的查询条件，最好就是分片键，这样查询带上它就能直接定位到一张表，不用到所有表里找。
3. **写入分布均衡**：新写入的数据也要均匀分散。如果按时间范围分，所有新写入都落在最新一张表，会形成写入热点。

### 常见做法
- 用户相关的业务，常用用户 ID 做分片键，因为大多数查询都是「查某个用户的东西」；
- 订单表按用户 ID 分，用户查自己的订单很快；但商家想查自己的订单，就要跨表，常见处理是再冗余一份按商家 ID 分的数据。

### 方案对比：几种字段做分片键
| 字段 | 分布 | 查询匹配度 | 问题 |
|---|---|---|---|
| 用户 ID | 比较均匀 | 用户维度的查询很多 | 其他维度要冗余或跨表 |
| 订单号 | 均匀 | 只有按订单号查才匹配 | 按用户查要跨表 |
| 创建时间 | 新数据集中 | 按时间范围查匹配 | 写入热点，数据倾斜 |
| 性别、状态 | 取值少 | 不均匀 | 分片太少，倾斜严重 |

结论：优先选区分度高、查询里最常带的字段，大多数业务选用户 ID；仅为适应时间范围查询，再考虑时间维度。

### 进阶：选错了怎么办（基础薄弱可先跳过）
分片键一旦确定，改起来要迁移全部数据，代价极大。所以上线前要根据主要查询场景想清楚；其他维度的查询，可以通过冗余数据或同步到搜索引擎来解决。

## 易错点
- 以为随便选一个唯一字段就行；还要看查询是否常带它
- 以为按时间分最自然；会产生写入热点和数据倾斜
- 以为分片键以后可以随时换；换分片键要迁移全部数据

## 追问
### [f1] 查询条件里没有分片键怎么办？
只能广播到所有分片再合并结果，代价高。可以冗余一份按另一维度分片的数据，或者同步到搜索引擎里查询。
