## 一句话
Java 内存模型把内存抽象成两层：共享变量放在主内存，每个线程有自己的本地内存保存副本，线程读写都先在本地内存里进行，再同步回主内存。

## 要点
- [kp1|3] 主内存：存放所有线程共享的变量
- [kp2|3] 本地内存：每个线程私有，保存共享变量的副本
- [kp3|2] 线程读写变量只操作自己的本地内存，不直接改主内存
- [kp4|2] 线程间的值要经过主内存同步，同步不及时就会出现可见性问题
- [kp5] 这是一个抽象模型，不是真实的内存区域划分

## 详解
### 先搞懂：每个人都有自己的草稿纸
想象大家合作算一道题：黑板上写着公共数据（主内存）。每个人为了算得快，会先抄一份到自己的草稿纸上（本地内存）。在草稿纸上算，算完再把结果誊回黑板。

问题来了：你改完草稿纸，还没誊回黑板，别人看黑板，看到的就是旧数据。这就是多线程可见性问题的来源。

后文用到的几个词：
- **主内存**：所有线程共享的变量存放的地方。
- **本地内存**：每个线程私有的工作区，里面是共享变量的副本。
- **副本**：从主内存复制过来的一份值。

### 读写变量的过程
线程使用共享变量时：

1. 先从主内存把变量读到自己的本地内存，得到副本；
2. 之后的读写都在副本上进行；
3. 修改完再把新值写回主内存。

两个线程之间传值，必须经过主内存：A 写回主内存，B 再从主内存读取。

### 它是抽象，不是真实硬件
所谓「本地内存」是 JMM 的抽象概念，并不是 JVM 里真的划出来的一块区域。它涵盖了 CPU 缓存、寄存器、编译器优化等等。它的作用是帮我们理解：为什么一个线程改的值，别的线程不一定马上看到。Java 语言规范自己用的是「共享内存（堆内存）」的说法，主内存、本地内存是常用的讲解模型。

### 为什么这样设计
CPU 直接读写主内存比读写自己的缓存慢得多，让线程先在本地操作能提高效率。代价就是需要同步手段（`volatile`、`synchronized`）来保证该看到的时候能看到。

## 示例
```java
// 没有同步手段时，worker 线程可能一直读到本地副本中的旧值
static boolean stop = false;  // 共享变量，在主内存

// worker 线程：while (!stop) { ... }
// main 线程：stop = true;  // 修改可能没及时同步给 worker
```

## 易错点
- 以为本地内存是 JVM 里实际存在的一块内存区域；它是 JMM 的抽象
- 以为主内存就是堆；两者不是一一对应的概念，主内存是对共享变量存放位置的抽象
- 以为线程改完值，别的线程立刻就能看到；没有同步手段不保证

## 追问
### [f1] JMM 要解决什么问题？
解决多线程下的三个问题：原子性（操作不可分割）、可见性（修改能被别人看到）、有序性（指令不被重排得出错），并给出 volatile、synchronized 等工具来保证。
