## 一句话
抽象类是用 abstract 修饰、不能直接 new 的类，可以包含抽象方法，作用是给一组相关的类提供共同的父类模板，让子类去补全未实现的部分。

## 要点
- [kp1|3] 用 abstract 修饰的类就是抽象类，不能直接用 new 创建对象
- [kp2|3] 抽象类可以有抽象方法（只有声明、没有方法体），子类必须实现
- [kp3|2] 抽象类也可以有普通方法、成员变量和构造方法
- [kp4] 子类如果不实现全部抽象方法，自己也必须声明为抽象类

## 详解
### 先搞懂：半成品的模板
假设你做报表导出：导出前要「查数据」，然后「生成文件」，最后「记日志」。其中查数据、记日志每种报表都一样，而生成文件，Excel 和 PDF 做法不同。

抽象类就像一份「半成品模板」：把通用部分写好，不确定的部分留成空白（抽象方法），让各个子类来填。模板本身不能直接交付使用，所以不能 new。

后文要用的词：
- **抽象方法**：用 `abstract` 修饰、只有声明没有方法体的方法。
- **具体类**：普通的、可以 new 的类。

### 怎么写
```java
abstract class Report {
    void export() {            // 通用流程，写好
        loadData();
        generateFile();
        System.out.println("记日志");
    }
    void loadData() { /* 通用 */ }
    abstract void generateFile();   // 留给子类
}
```

### 抽象类的特点
- 不能被实例化：`new Report()` 编译报错。
- 可以有抽象方法，也可以一个都没有；有抽象方法的类必须是抽象类。
- 可以有构造方法、成员变量和普通方法，构造方法在子类创建对象时被调用。
- 子类继承后必须实现所有抽象方法，否则子类也得是抽象类。
- `abstract` 不能和 `final`、`private`、`static` 搭配用在抽象方法上，因为这些都和「留给子类实现」矛盾。

### 什么时候用
多个类有共同的属性和逻辑，又有部分行为各不相同时，适合用抽象类，这时它们之间是 is-a 关系。

## 易错点
- 以为抽象类里必须有抽象方法；没有也可以
- 以为抽象类没有构造方法；有，只是不能直接 new
- 认为抽象类不能有普通方法；可以有，而且常用来放通用逻辑

## 追问
### [f1] 抽象类和普通类的区别？
抽象类不能实例化，可以带抽象方法；普通类可以实例化，且所有方法都必须有实现。

### [f2] 抽象类和接口有什么区别？
抽象类单继承，表示 is-a，可以带状态；接口可以多实现，更像一种能力的约定。详见专门的对比题。
