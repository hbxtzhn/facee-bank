## 一句话
寄存器是 CPU 内部最快的小型存储，存放正在处理的数据和下一条指令的位置；切换进程时要把它们存下来，再恢复。

## 要点
- [kp1|3] 寄存器是 CPU 内部的存储单元，速度比内存快得多
- [kp2|3] 程序计数器保存下一条要执行的指令的位置
- [kp3|2] 其他寄存器保存正在计算的数据和栈的位置
- [kp4|2] 切换进程时，要保存当前寄存器，并恢复另一个进程的

## 详解
### 先搞懂：厨师手边的案板
厨师炒菜时，不会每次都跑去仓库拿食材，而是把当前要用的放在手边的案板上。CPU 也一样：内存相当于仓库，寄存器就是 CPU 手边的案板，容量很小，但取用最快。

后文要用的术语：

- **寄存器**：CPU 内部的小型存储单元，数量有限。
- **指令**：CPU 能执行的一条基本操作。
- **进程上下文**：进程运行到某一刻的状态，核心部分就是寄存器里的内容。

### 寄存器里存什么
常见的有三类：

- **程序计数器**：记录下一条要执行的指令在哪里。CPU 就是靠它知道程序执行到了哪一步；
- **通用寄存器**：存放正在计算的数据和中间结果；
- **栈指针**：记录当前函数调用栈的位置。

### 为什么切换进程要处理寄存器
单核 CPU 上有进程 A 和 B 轮流运行。A 的时间片用完时，寄存器里还留着 A 的计算数据和执行位置。如果直接让 B 运行，B 会把这些内容覆盖掉，A 再回来时就无法接着往下执行了。

所以切换时操作系统做两件事：

1. 把 A 的寄存器内容保存起来；
2. 把 B 上次保存的寄存器内容装回 CPU，B 就能从上次停下的地方继续。

这就是上下文切换里保存和恢复上下文的核心内容。

## 易错点
- 把寄存器当作内存的一种；寄存器在 CPU 内部，不是内存
- 以为切换进程只需要换一个进程名；必须保存和恢复寄存器等状态，否则进程无法继续

## 追问
### [f1] 程序计数器丢了会怎样？
CPU 就不知道该执行哪条指令了，进程没法接着运行。所以切换进程时，一定要保存它。
