## 一句话
InnoDB 的行锁加在索引记录上，按范围分成记录锁、间隙锁、临键锁和插入意向锁；没有走索引时，会锁住扫描到的所有行。

## 要点
- [kp1|3] InnoDB 的行锁加在索引记录上，不是加在数据行本身
- [kp2|3] 记录锁锁一条索引记录，间隙锁锁记录之间的空隙
- [kp3|2] 临键锁等于记录锁加它前面的间隙，是默认的范围加锁方式
- [kp4|2] 插入意向锁是 INSERT 在间隙里先加的一种间隙锁
- [kp5] 间隙锁和临键锁在可重复读下常见，用来防止幻读

## 详解
### 先搞懂：锁的是「编号」，不只是「那几行」
假设订单表的主键有 1、5、10 这三条记录。你查「id = 5 的订单并锁住」，只锁 5 这一条，很好理解。

但如果你查「id 在 3 到 8 之间的订单」，只锁 5 这一条还不够。别人可以趁机插入一条 id = 4 或 id = 7 的新订单，你再查一遍，会多出行来。这叫**幻读**。所以 InnoDB 还要把「5 前后的空隙」也一起锁住。

类比：停车场里，你不仅占了 5 号车位，还要把车位之间的空地也围起来，防止别人把新车停进去。

后文会用到这几个词：

- **索引记录**：索引里的一个条目，InnoDB 的锁就挂在它上面。
- **间隙**：两条相邻索引记录之间、还没有数据的那一段。
- **幻读**：同一个事务里两次范围查询，第二次多出了别人新插入的行。

### 为什么必须依赖索引
InnoDB 的数据就是存在主键索引里的，每次访问数据都是通过某个索引。所以锁住的是「索引上的记录」。

- 条件走了索引：只锁匹配的那部分索引记录，以及相关的间隙。
- 条件没走索引：要全表扫描，扫描到的所有记录都会被锁，并发会很差。

### 四种锁的分工
**记录锁**：锁住一条具体的索引记录。唯一索引上等值查询，命中一行时用它。

**间隙锁**：锁住两条记录之间的空隙，不锁记录本身。等值或范围查询没有命中记录时用它，阻止别的事务往里插入。

**临键锁**：记录锁加间隙锁，锁住一条记录和它前面的间隙，区间左开右闭。范围查询命中记录时常用。

**插入意向锁**：INSERT 在真正插入前，在目标间隙上加的一种特殊间隙锁。位置不同的插入互不阻塞，但会被已有的间隙锁、临键锁挡住。

### 什么时候不会加间隙相关的锁
间隙锁、临键锁主要用来防幻读，默认的可重复读隔离级别下才常出现。读已提交级别下，大多数情况只锁记录，不锁间隙。

## 示例
```sql
-- 假设 id 有 1、5、10，且 id 有索引，可重复读级别
START TRANSACTION;
SELECT * FROM orders WHERE id = 5 FOR UPDATE;   -- 记录锁
SELECT * FROM orders WHERE id = 7 FOR UPDATE;   -- 没命中，锁住 (5,10) 的间隙
SELECT * FROM orders WHERE id > 5 FOR UPDATE;   -- 范围，临键锁
```

## 易错点
- 以为行锁锁的是数据行本身；实际挂在索引记录上
- 以为查询没命中就不加锁；可重复读下会加间隙锁，阻塞别人的插入
- 以为间隙锁之间也互相冲突；间隙锁和间隙锁是兼容的，它们只阻止插入
- 以为任何隔离级别下都有间隙锁

## 追问
### [f1] 条件没有索引时会怎样？
InnoDB 要全表扫描，扫描到的每条记录都会被加锁，其他事务对这张表的修改几乎都会被挡住，效果接近表锁。

### [f2] 为什么需要间隙锁？
为了防止幻读。事务范围查询后，如果别人能往范围里插入新行，同一个事务再查一次就会多出行。锁住间隙后，这样的插入会被挡住。
