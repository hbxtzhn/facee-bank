这三个名字不能简单背成“都是云数据库”。项目设计把需要结构化查询的数据放在 D1，把适合对象方式读取的文件放在 R2；Durable Object 用于特定对象范围内的运行和协调，例如群 Agent 循环或连接相关能力。项目文档中的具体存储位置还会受到迁移阶段和配置开关影响。

一个直观例子：账号、公开条目的结构化字段适合通过 SQL 按条件查询；图片、附件或某些分段日志适合按对象读取；按群组织的运行逻辑则需要围绕当前群维护请求处理与协调。并不是每条路径都已经完全上云，文档中的表格包含历史状态和分阶段迁移决定，讲项目时应说明代码基线和核验时间。

把这几个角色分清后，再看一次请求：Worker 承接入口逻辑，必要时访问 D1 或 R2，群相关执行可能由对应的群对象处理。资源之间的通信和存储不是自动原子的，跨边界失败、权限和重复执行仍需单独处理。
