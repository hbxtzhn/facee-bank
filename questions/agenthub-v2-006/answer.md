这里的“核心”是一次回答中相对通用的思考部分，如模型调用、预算、工具包装和输出处理；“宿主”是跟入口和运行环境密切相关的能力，如 QQ 收发、网页账号、群身份、数据存储和消息投递。同一个业务可能在不同环境运行，如果核心直接依赖某台机器的文件路径、QQ API 或进程环境，就很难迁移和测试。

项目文档提出把本轮上下文、存储、凭据、模型目录和宿主能力作为边界。宿主负责提供身份、数据访问和发送能力，核心通过接口使用。网页宿主的公开知识预检索、访客额度及流式输出属于网页自己的流程；群 Worker 则需要处理群角色和群工具。该文档也明确这些接口分步实施，因此应区分已存在的代码与设计目标，不能简单说“全部入口已经完全统一”。

例如，想测试模型超时时，测试可以提供一个模拟模型和模拟工具，而不是启动真实 QQ 进程；将一部分功能放到 Worker 时，也不应假设本机文件系统一定存在。边界划分的价值是减少耦合，但增加接口并不自动证明各实现的行为完全一致，仍需逐路径验证。
