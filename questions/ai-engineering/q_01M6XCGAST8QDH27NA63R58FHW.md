## 一句话
ReAct 让模型每走一步都先推理、再行动、拿到结果后再修正判断，这样少靠猜测，适合需要和环境交互的动态任务。

## 要点
- [kp1|3] ReAct 是推理（Reasoning）和行动（Acting）交替进行的模式
- [kp2|3] 每一步行动的结果会回到上下文，用来修正下一步判断
- [kp3|2] 它减少凭空推断，让答案建立在真实的工具返回上
- [kp4|2] 适合环境会变化、结果无法提前预知的任务
- [kp5] 代价是步骤多、调用多，成本和延迟更高

## 详解
### 先搞懂：走一步看一步地找路
你在陌生的商场找一家店。如果只在门口想一遍，凭感觉走到底，很可能走错。更靠谱的做法是：想一想往哪边走，走几步，看看指示牌，再想下一步。

ReAct 就是让模型这样做：不是一口气想完所有步骤，而是想一步、做一步、看一步。

后文用到的术语：
- **推理**：模型写出当前的分析和打算。
- **行动**：调用工具去查或做。
- **观察**：工具返回的真实结果。

### 一次 ReAct 的样子
以回答「某公司现在的股价比去年涨了多少」为例：

1. 想：我需要先知道现在的股价；
2. 做：调用股价查询工具；
3. 看：得到一个数字；
4. 想：还需要去年的股价；
5. 做：再调用工具查历史数据……

最后把两个真实数字相比较，得出答案。

### 为什么要交替进行
如果只推理不行动，模型只能靠训练时记住的内容，容易编造或过时。如果只行动不推理，就像没有头脑的机器，不知道该调什么。

交替进行有两个好处：

- 推理指导行动，行动选得有目的；
- 观察校正推理，及时发现之前想错了。

所以它能减少幻觉，也适合任务中途会出现意外的场景。

### 局限
每一步都要让模型推理一次，调用次数多，成本高、速度慢。而且每步只看眼前，容易偏离整体目标，需要加停止条件。

## 示例
```text
思考：要比较涨幅，先查当前股价。
行动：get_price(symbol="ABC", date="today")
观察：当前价格 120
思考：还需要去年同期价格。
行动：get_price(symbol="ABC", date="last_year")
观察：去年价格 100
思考：涨幅 = (120 - 100) / 100 = 20%。
最终答案：涨了 20%。
```

## 易错点
- 以为 ReAct 只是多写几句思考；关键是行动结果会反过来修正推理
- 以为有了 ReAct 就不会出错；模型仍可能选错工具或误读观察
- 以为所有任务都适合；步骤固定的任务用预先设计的流程更省成本

## 追问
### [f1] ReAct 为什么能减少幻觉？
模型的判断建立在工具返回的真实数据上，而不是凭记忆猜测，所以编造的空间更小。但工具返回错误时，它仍可能被带偏。

### [f2] ReAct 和单纯的思维链有什么不同？
思维链只在模型内部推理，不接触外部信息；ReAct 在推理之间加入了工具调用，能获取新信息。
