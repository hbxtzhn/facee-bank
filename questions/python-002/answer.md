## 1. 引用计数与循环垃圾回收

CPython 主要通过引用计数管理对象生命周期。绑定或容器持有会增加引用，解绑、移出容器等会减少引用；`del x` 删除的是绑定，不是强制销毁对象。普通对象的最后一个引用释放时通常立即析构，但不能概括成所有版本、所有对象都没有延迟或停顿：永生对象、自由线程构建及用户析构逻辑均有特殊情况。

引用计数本身不能回收不可达的引用环。循环 GC 会追踪**可能形成引用环的对象**，在候选集合内扣除相互引用，找出仍由集合外部可达的对象及其后继，回收不可达部分。不是所有对象或所有容器都始终受 GC 追踪。

## 2. 分代是实现策略，不能跨版本背诵固定参数

以 CPython 3.12/3.13 的传统实现为例，年轻对象从第 0 代开始，幸存对象逐步晋升至第 1、2 代，降低反复扫描长寿命对象的成本。阈值和算法在后续版本、补丁版本及自由线程构建中会变化。

排查时用目标解释器的 `gc.get_threshold()`、`gc.get_stats()` 与对应版本文档确认，不把 `700/10/10` 当成所有 Python 环境的固定配置。GC 能处理不可达环，仍被全局变量引用的对象属于存活对象，不能靠 `gc.collect()` 强制释放。

## 3. 对象分配与操作系统内存不同

启用 pymalloc 的 CPython 使用 arena、pool、block 分层管理小对象，常见的小请求上限为 512 字节；更大分配走底层分配器。官方文档中的 arena 大小为 32 位平台 256 KiB、64 位平台 1 MiB，不应统一写成 256 KiB。

自由线程构建采用 mimalloc，不能套用全部 pymalloc 细节。对象释放后内存可能由分配器保留复用，因此 RSS 不立即下降不等于对象仍然可达或已经泄漏。

参考：[内存分配器](https://docs.python.org/3.14/c-api/memory.html)、[gc](https://docs.python.org/3.14/library/gc.html)、[3.13 gc](https://docs.python.org/3.13/library/gc.html)。
