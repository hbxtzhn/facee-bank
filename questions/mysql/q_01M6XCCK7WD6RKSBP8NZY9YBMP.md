## 一句话
前缀索引是只对字符串列的前 N 个字符建索引，写法是 `INDEX(col(N))`。它用更小的索引空间换取查询，适合很长的字符串列。

## 要点
- [kp1|3] 前缀索引只取字符串列开头的 N 个字符放进索引
- [kp2|3] 创建写法：`CREATE INDEX idx ON t (col(N))`
- [kp3|2] 索引更小，占用空间少，读取和更新的代价也更低
- [kp4] 适用于 `VARCHAR`、`TEXT` 等较长的字符串列
- [kp5] 前缀索引不能用作覆盖索引

## 详解
### 先搞懂：查字典只看前几个字
翻字典找一个词，你不必看完整的词，看前两三个字就能定位到大致位置。前缀索引就是这样：只把每个值的开头一小段放进索引，而不是整个值。

后文用到的术语：

- **前缀**：字符串开头的那几个字符。
- **索引空间**：索引占用的磁盘和内存。
- **覆盖索引**：查询所需的列都在索引里，不用回表。

### 为什么需要它
有些列很长，比如邮箱、URL、文章标题。给整列建索引，每个索引项都要存完整的值，索引会变得很大，占磁盘，也会占用更多缓存空间。

而这些值往往开头的几个字符就已经能区分大部分行。只存前面一小段，索引小很多，效果却接近。

### 怎么创建
在列名后面用括号写上要取的字符个数：

```sql
-- 建表时
CREATE TABLE user (
  id BIGINT PRIMARY KEY,
  email VARCHAR(255),
  INDEX idx_email (email(10))
);

-- 给已有表加索引
ALTER TABLE user ADD INDEX idx_email (email(10));
```

意思是只对 `email` 的前 10 个字符建索引。

### 查询时怎么工作
用前缀索引查询时，MySQL 先用前缀在索引里找到可能的行，再回到表里取完整的值，核对是否真的匹配。因为前缀相同的行可能有多条，所以需要回表确认。

### 它的限制
- 前缀不能完整表示整个值，所以不能作为覆盖索引：即使只查这一列，也还要回表；
- 前缀不一定能支持 `ORDER BY` 和 `GROUP BY` 完全利用索引排序；
- 前缀取多长合适，要看数据分布，题库里有专门的题讲怎么选。

## 示例
```sql
-- 对 url 的前 20 个字符建前缀索引
ALTER TABLE page ADD INDEX idx_url (url(20));

-- 这条查询可以先用索引缩小范围，再回表核对完整 url
SELECT id FROM page WHERE url = 'https://example.com/a/b/c';
```

## 易错点
- 把前缀长度写成字节数；对字符串列通常是字符数，但对二进制列是字节数
- 以为前缀索引和普通索引没区别；它不能用于覆盖索引，也可能区分度较低
- 前缀取得太短；很多行前缀相同，索引起不到筛选作用

## 追问
### [f1] 哪些列适合建前缀索引？
长度较长、开头几个字符就能区分大部分行的字符串列，比如邮箱、URL。如果开头几乎都一样，比如统一以 `http://` 开头，前缀索引区分度很差。
