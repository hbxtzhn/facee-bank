## 一句话
fork 是操作系统提供的调用，它会复制出一个和当前进程内存内容相同的子进程，子进程可以独立执行，不影响父进程继续干活。

## 要点
- [kp1|3] fork 创建子进程，子进程的内存内容和父进程一模一样
- [kp2|3] 父子进程各自独立运行，互不阻塞，改数据也互不影响
- [kp3|2] fork 一次调用返回两次：父进程拿到子进程 ID，子进程拿到 0
- [kp4] Redis 用 fork 在后台生成 RDB 快照和重写 AOF

## 详解
### 先搞懂：给文档“另存一份”再各改各的
你写了一份文档，点“另存为”得到一个内容完全一样的副本。之后你改原件，同事改副本，两边互不干扰。fork 对进程做的就是这件事：进程是正在运行的程序，fork 之后就有了两个内容相同的进程。

后文用到的词：
- **进程**：一个正在运行的程序，有自己独立的内存空间。
- **父进程 / 子进程**：调用 fork 的是父进程，被创建出来的是子进程。

### fork 做了什么
1. 父进程调用 fork。
2. 操作系统创建一个新进程，它的内存内容、打开的文件和执行到的位置，都和父进程一样。
3. fork 调用在两个进程里各返回一次：父进程得到子进程的 ID，子进程得到 0。程序靠这个返回值区分“我是父还是子”。
4. 从这一刻起，两个进程各自独立往下执行。

### 为什么 Redis 要用它
Redis 要把某一时刻的全部数据写到磁盘。如果由主线程来写，写的几秒里就没法处理请求。

用 fork 的话，子进程拿到的是 fork 那一刻的数据，它慢慢写磁盘，父进程继续处理客户端请求。子进程看到的数据不会被父进程后续的修改影响，所以写出来的快照是一致的。

### 复制整个内存会不会很慢
不会真的立刻复制。操作系统让父子进程先共用同一份物理内存，只有某一方修改了某块内存，才把那一块复制出来。这个机制叫写时复制，在另一道题里详细讲。

## 示例
```c
pid_t pid = fork();
if (pid == 0) {
    // 子进程：在这里做后台工作，比如写快照文件
} else if (pid > 0) {
    // 父进程：pid 是子进程 ID，继续处理请求
} else {
    // pid < 0：fork 失败
}
```

## 易错点
- 以为子进程和父进程共用同一份数据、改了会互相影响；实际是各改各的
- 以为 fork 是创建一个新线程；fork 创建的是进程，有独立的内存空间

## 追问
### [f1] fork 出的子进程会占双倍内存吗？
一般不会。父子进程先共用物理内存，只有被修改的那部分才会复制。写入越频繁，额外占用的内存越多。
